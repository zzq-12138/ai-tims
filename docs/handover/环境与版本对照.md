# 环境与版本对照（交接用）

> 用途：本地 VM 与公司交付集群是**两套不同代际**的 Kubernetes。所有交付物（manifests、镜像、脚本）必须按**低版本（公司 kubeadm v1.23.17）**写，本地 k3s 只当“跑得通”的验证环境。
> 数据来源：公司侧以 `docs/ops/公司环境操作记录.md` 的只读实测与操作回读为准（6.1 / 8.1 / 10.29 / 10.30，2026-11-14 ~ 11-19）；2026-11-23 又做了一轮集群只读实测（节点 / Ingress / PVC / ConfigMap / Harbor）；本地 VM 为 2026-11-04 实测 + 2026-11-23 复核。**未实测项标「待确认」**。
> 上一版把公司集群写成「v1.24.17 / 6 节点 / containerd 1.6.24 / Ubuntu 24.04」，那是**备选环境 C（11.191）**的口径，已作废；实际交付环境是 **19.64、v1.23.17、7 节点、Docker 20.10.24**。

## 二、硬约束（写在最前面）

1. **所有 K8s manifests 必须兼容 v1.23**，禁止使用 1.25+ 才有的 API、字段、注解；能不用 1.24 新增能力就不用，避免以后换集群再改。
2. **禁止写死本地环境地址**：`localhost:5000`、`192.168.40.10`、`127.0.0.1` 只能出现在本地 overlay / kustomize patch 中；交付基线用公司仓库地址与 `imagePullPolicy: IfNotPresent`。
3. **禁止依赖 Traefik / nginx 私有 CRD 与注解**（`IngressRoute`/`Middleware`、`nginx.ingress.kubernetes.io/*`）；同时**不要假设 Ingress 可用**——`ai-tims` 虽有一个 Ingress 对象，但集群 `IngressClass` 为空、没有 controller 认领，ADDRESS 为空；两个 kubesphere-router 只服务 `flink-operator`、`yms-test`。交付基线对外只写 **NodePort Service**（现有 30204/31579 已占用，新服务另选端口）。
4. **禁止依赖 `k3s` 专属能力**（`k3s crictl`、`/var/lib/rancher`、`local-path` StorageClass 名）写在交付基线里；`local-path` 仅本地验证用，公司侧实测 StorageClass 为 **`nfs-storage`**。
5. 交付前必须做**低版本自检**（见第六节），本地跑通 ≠ 公司跑通。
6. **Ingress 资源现状要单独交代**：`deploy/k8s/base/ingress.yaml` 仍写死 `ingressClassName: nginx` 与 `nginx.ingress.kubernetes.io/*` 注解，既违反「基线不写厂商注解」，现场 `ai-tims/ai-tims` 也没有 controller 认领、ADDRESS 为空。apply 前要么用 overlay 删除该资源，要么明确保留但**不依赖它**。
7. **`commonLabels` 会写入 selector**：`base/kustomization.yaml` 的 `commonLabels` 已注入 Deployment selector（不可变）。往 base 新增组件前，先用 `kubectl -n ai-tims get deploy <name> -o jsonpath='{.spec.selector.matchLabels}'` 核对。

### 3.4 入口：Ingress 对象存在但不生效，只走 NodePort（最容易翻车）

- **公司现实**：`ai-tims/ai-tims` 的 spec 为 `ingressClassName: nginx`、host `tims.company.local`、后端 `ticket-gateway:8080`（path `/`，Prefix），注解 `proxy-body-size: 25m`、`proxy-read-timeout: 3600`、`proxy-send-timeout: 3600`，`status.loadBalancer` 为空；`kubectl get ingressclass` 返回 **`No resources found`**。router 是**按命名空间各自一套**：`kubesphere-router-flink-operator`（NodePort 80:31542 / 443:31086）、`kubesphere-router-yms-test`（80:30373 / 443:31554），另有 `default-http-backend`；`ai-tims` 没有对应 router，也没有 controller 认领。**要域名访问必须为 ai-tims 单独部署 router 并创建 IngressClass；改注解无效。** 对外仍只走 NodePort。
- **对外端口**：`ticket-gateway` NodePort **30204**（8080）；`ai-tims-front` NodePort **31579**（80，`/api`、`/ws` 反代到 gateway）。这两个端口已在现场占用，新增服务不要复用。
- **本地差异**：k3s 自带 Traefik，`svclb-traefik` 已占 NodePort 80/443；本地再起 ingress/NodePort 80/443 会冲突。
- **交付写法**：`Service` 用 `type: NodePort`；如必须写 `nodePort`，用 kustomize patch 固化，避免每次 apply 漂移。**不要**把 `ingressClassName: nginx` 当成交付基线。
- **HTTPS**：公司未提供入口证书，当前对外是 HTTP；证书 `secretName` **待确认**。

### 3.5 运行时差异（Docker 20.10.24 vs containerd 2.3）

- 公司节点用 **Docker 20.10.24 + dockershim**（1.23 仍支持，1.24 才移除）。排查用 `docker ps/images`，不是 `crictl`。
- 镜像格式 OCI 兼容，`docker save` 的包可 `docker load` 后直接跑；不要依赖 containerd 2.x 的 snapshotter / 镜像加速新字段。
- 私有仓库认证：公司是 `/etc/docker/daemon.json` 的 `insecure-registries` + `docker login`；本地 k3s 是 `/etc/rancher/k3s/registries.yaml`。**两套机制不要混用**，也不要把 `registries.yaml` 带进交付。
- `deploy.sh` 的镜像准备走 `docker load` / `docker push`，因此**发布机必须有 Docker 且已登录 Harbor**。

### 3.6 kustomize 版本

- 公司 `kubectl` 为 **1.23**，自带 kustomize **v4.4 系列**；2026-11-16 已用 `kubectl kustomize deploy/k8s/overlays/company` 渲染 **1791 行**通过，`--dry-run=server` 在 1.23 上接收 40 个资源、0 error。
- 只用 `resources` / `namespace` / `commonLabels` / `images` / `patchesStrategicMerge`；不要用 kustomize v5 的 `labels`、新 `patches` 语法。
- `kubectl apply --dry-run=server` 通过**只证明字段兼容**，不证明镜像可拉、PVC 可绑定、节点放得下；这三项已由 2026-11-18 真部署覆盖（10.1）。
