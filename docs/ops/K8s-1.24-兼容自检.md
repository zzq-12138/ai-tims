# K8s v1.24.17 兼容自检

> 交付基线：公司集群 **v1.24.17**、containerd **1.6.24**、6 节点（3 control-plane + 3 worker）。
> 本地 k3s **v1.36.5+k3s1** 只用于「跑得通」验证，**本文不引用 k3s 的任何结果作为 1.24 兼容证据**。
> 检查日期：2026-11-06；检查对象：`deploy/k8s/**`。

## 0. 结论

- 所有 manifest 只使用 **v1 / apps/v1 / networking.k8s.io/v1 / batch/v1** 与 **kustomize.config.k8s.io/v1beta1**，这些 API 在 1.24.17 全部为 GA/稳定版本。
- 未使用任何 Kubernetes 1.25+ 才引入的 API 或字段（见 §3）。
- 本地无 `kubectl` / `kubeconform` / `kustomize` / `docker`，且 GitHub 下载被网络策略阻断，因此**没有**拿到 1.24 schema 的机器校验结果；已有的实际输出只到「YAML 可解析 + 结构检查」级别（见 §4）。
- 环境相关的 12 项标注为 **待公司验证**（见 §5），其中 IngressClass、StorageClass、NetworkPolicy、PSA、镜像仓库是上线前硬门槛。

## 6. 风险与取舍

- **单副本**：所有中间件与业务均 1 副本，节点故障会中断。这是 6 节点共享集群 + 16Gi 内存预算下的取舍，不承诺高可用。
- **Nacos 内嵌 derby**：数据落 PVC，符合毕设规模；生产应换 MySQL 存储。
- **Milvus standalone 三件套**：etcd/minio/milvus 各自 1 副本，PVC 分别 5/20/20Gi；Milvus 首次启动慢，startupProbe 给了 10 分钟。
- **无 NetworkPolicy**：默认允许全部东西向流量；若公司默认 deny，需要按准入清单补放行规则。
- **无 PDB/HPA**：1 副本下 HPA/PDB 意义有限，故意不加，减少 1.24 之外的变量。
- **前端未包含**：本交付只覆盖后端六服务与中间件。
