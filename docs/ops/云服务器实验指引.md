# AI-TIMS 云服务器实验指引（阿里云 4C4G 变体）

> **定位**：本文是 [中间件动手实验.md](中间件动手实验.md) 的**云端变体**。实验内容（L1~L4 四级台阶、验收标准、记录表）**全部沿用该文档，本文不重复**，只补充 4G 内存约束与云上特有差异。读本文前先通读动手实验文档。
>
> **实际安排（2026-11-03 确认）**：云端**只练 Nacos / Milvus / RabbitMQ / registry 四个中间件**；**k3s 不在云端练**，直接在毕设 VM 上做（前置条件与风险见第 6 节，步骤见 [k3s单节点搭建手册.md](k3s单节点搭建手册.md)）。
>
> **环境假设**：阿里云 ECS 4 vCPU / 4G 内存，Ubuntu Server 22.04（与 VM 同版本），有公网 IP。云厂商/规格/计费细节凡无法从命令确认的，一律标「需在控制台确认」。**本文不执行安装动作，只指路。**
>
> **为什么用云**：VM 是毕设生产环境，重装/搞挂代价高；云服务器随便折腾，练完释放即可（见第 5 节）。

## 1. 单机预算表（4C4G 的现实）

先记住两个基数：Ubuntu 22.04 空载约 250~350M，Docker daemon 约 100~150M——**系统底座先吃掉约 0.5G，可用约 3.5G**（实际以 `free -h` 为准）。

| 组件 | 内存占用参考 | 单独跑（4G） | 与谁可同时跑 |
|---|---|---|---|
| registry:2 | 限额 128M，实际 <50M | ✅ 很轻松 | 几乎可与任何组件并存 |
| Redis 7 | <50M（无持久化压力时） | ✅ 很轻松 | 可与轻组件并存 |
| MySQL 8 | 调参后 400~600M（见 2.3） | ✅ 可行 | 可与 Nacos/RabbitMQ 并存 |
| Nacos v3 | JVM 256m~512m + 堆外，实际 500~700M | ✅ 可行 | 可与 MySQL/Redis/registry 并存 |
| RabbitMQ 3-management | 限额 350M，实际 100~200M | ✅ 可行 | 可与 Nacos/MySQL 并存 |
| **Milvus 三件套** | milvus 1536M + etcd 256M + minio 256M = 限额 2G，实际峰值 1.5~2G | ⚠️ 勉强（必须开 swap，见 2.1） | **不与其它重组件并存** |

**结论（务必执行）**：
1. **4G 机器上 Milvus 与其它重组件不要并存**——Milvus 练习期间把它当作这台机器唯一的主角；k3s 不在云端练，不存在与 Milvus 抢内存的问题（k3s 的内存话题移到 VM，见第 6 节）。
2. **轻量组可并存**：registry + Redis（+至多一个 Nacos 或 RabbitMQ）；MySQL 视调参可与一个轻组件并存。
3. 每次换组件前 `free -h` 确认可用内存 ≥1.5G 再动手，不够就先拆掉上一个。

**推荐练习顺序**（由轻到重，与动手实验文档的实验编号对应）：

```
D registry → Redis（可选，仅用于理解数据卷持久化）→ A Nacos → C RabbitMQ → B Milvus（单独窗口，开 swap）
```

## 2. 4G 下的调参（每个组件上线前先做）

### 2.1 先开 2G swap（全组件通用）

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h    # 预期 Swap 行显示 2.0Gi
```

**为什么必须开**：4G 物理内存对 Milvus 三件套是贴着限额跑（限额合计 2G），没有 swap 的话内存峰值直接触发 OOM killer（容器被杀表现为 `docker ps` 里 STATUS 消失/Restarting，`dmesg | grep -i oom` 可见记录）。云端没有 k3s，也就没有 kubelet 与 swap 的兼容问题，放心开。

### 2.2 容器内存限额（写进你自己的实验 compose）

照抄动手实验文档 L1 要求里的限额值即可——它们本来就是按生产口径给的：`mem_limit` Nacos 512m（堆）/ RabbitMQ 350m / registry 128m。**云上额外纪律**：每个重组件必须有 `mem_limit`，否则单容器失控会拖死整机。

### 2.3 MySQL buffer_pool 调小

4G 机器上 MySQL 8 默认 buffer_pool 配置会预占 128M×N 偏多，自定义配置启动（bind mount 挂配置目录）：

```ini
# my.cnf 追加
innodb_buffer_pool_size=128M
performance_schema=OFF
```

```bash
docker run -d --name lab-mysql -p 13306:3306 \
  -v /home/dev/lab/mysql/conf:/etc/mysql/conf.d \
  -v /home/dev/lab/mysql/data:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD=lab12345 mysql:8.0
```

（端口偏移遵循动手实验文档第 0 节思路：云上无生产服务共存问题，但仍建议偏移端口，养成习惯且少暴露。）

### 2.4 Milvus 内存限额下调后的可用性说明

- 三件套限额可从 1536/256/256 下调到 **milvus 1024M / etcd 128M / minio 128M**（约省 0.7G）；
- **可用性如实说**：能起、能建 collection、写入/检索**几十到几百条**向量（毕设种子知识 50 条规模）没问题；但数据量再大、索引重建（HNSW build）时会逼近限额，swap 兜底下变慢而非报错，`docker stats` 看到 milvus 贴 1G 就该收手；
- etcd 的 `ETCD_QUOTA_BACKEND_BYTES=4294967296`（4G 配额）在 128M 容器限额下要同步调小（如 536870912=512M），否则限额先爆，表现为 etcd 重启、milvus 跟着失联。

## 3. 云上特有的坑（VM 上不存在的部分）

### 3.1 安全组：开什么、绝不开什么（第一道墙）

安全组在阿里云控制台配置（**需在控制台确认**实例所属安全组与当前规则）。原则：**按需临时开、用完即关；管理界面类端口一律不对公网开放**。

| 端口 | 用途 | 公网放行？ |
|---|---|---|
| 22 | SSH | ✅ 开，但**限制来源 IP**（只放自己常用出口，控制台配白名单） |
| 5000 / 5500 | registry（无认证 HTTP） | ⛔ **绝不开公网**。无 TLS 无认证的 registry 开公网=任何人可推恶意镜像。需要外部验证时走 SSH 隧道（见 3.2） |
| 15672 / 8849 / 9091 | RabbitMQ/Nacos/Milvus 管理台 | ⛔ 不开公网。要看界面走 SSH 隧道；确需开放则仅内网 VPC 或至少加强认证（**需在控制台确认**是否有内网访问条件） |
| 8848 / 9848 / 19530 / 5672 / 3306 / 6379 | 中间件服务端口 | ⛔ 默认不开；本机 SSH 上去 curl localhost 即可验证（动手实验文档各 L1 验收命令在云上都改成 localhost） |
| **2375 / 2376** | Docker Remote API | ⛔⛔ **绝对禁止**。2375 无 TLS 等于把 root shell 挂公网，是勒索挖矿镜像最经典入侵口。永不启动 `-H 0.0.0.0:2375` |

### 3.2 替代公网暴露的标准姿势：SSH 隧道

管理台/私有端口的正确打开方式（本机执行）：

```bash
# 本机浏览器访问云上的 RabbitMQ 管理台（35672 为云上偏移端口时）
ssh -L 35672:localhost:35672 root@<公网IP>
# 然后浏览器开 http://localhost:35672
```

### 3.3 磁盘

- 默认系统盘（通常 40G ESSD，**需在控制台确认**实际容量与类型）对本文全部实验**够用**——Milvus 三件套镜像约 1G、实验数据都在 MB 级；
- 数据卷挂载：跟随动手实验文档用 bind mount 落在 `/home/dev/lab/<组件>/data`，不要另买数据盘（练习阶段不值）；`df -h /` 低于 80% 就先 `docker system df` 清理；
- 练习产生的**快照/自定义镜像**会持续计费，清理时一并处理（第 5 节）。

### 3.4 Docker 镜像加速（ECS 访问 Docker Hub 慢是常态）

```bash
# 阿里云专属加速地址：登录控制台 → 容器镜像服务 ACR → 镜像加速器（每个账号一个专属地址，需在控制台确认）
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://<你的ID>.mirror.aliyuncs.com",
    "https://docker.m.daocloud.io"
  ]
}
EOF
sudo systemctl restart docker    # 不重启不生效——VM 侧踩过的坑 #8 同款
```

备用前缀：`1ms.run`（VM 上拉 `milvusdb/*` 靠它，云上大概率同样需要，daocloud 对 milvusdb/* 403 的坑不因上云消失）；etcd 走 `quay.io` 官方。

## 4. 镜像与配置怎么搬上云

VM 上已有的镜像/文件不想重新下载时：

```bash
# 在 VM 上导出 → 本机中转 → 传云（走本机做跳板，两边都是内网/代理受限环境时的标准做法）
ssh ubuntu-server "docker save alpine:3.20 | gzip" > alpine.tgz
scp alpine.tgz root@<云公网IP>:/tmp/
# 云上
docker load < /tmp/alpine.tgz
```

compose 文件、`~/lab` 目录同理可 `tar` + scp。注意：**生产 VM 的正本 `docker/docker-compose.yml` 与 `~/secrets/` 不要整包拷上云**——云机按「随时可释放的一次性实验场」对待，只带走实验所需。

## 5. 成本与清理（练完必做，避免持续计费）

按付费模式处理不同（包年包月 / 按量付费，**需在控制台确认**自己的模式）：

| 资源 | 动作 | 说明 |
|---|---|---|
| 实例 | 包年包月：到期不再续费；按量：**「停机不收费」需开启节省停机模式**（普通停机仍收 CPU/内存费） | 停机 ≠ 不计费，是最常见的误解 |
| 云盘 | 随实例释放需在释放对话框**勾选「释放云盘」**（否则系统盘转为按量计费留存） | 有重要产物先打包回本机再释放 |
| EIP（公网 IP） | **解绑后单独释放**。EIP 闲置也计费，是练习后最常见的漏单 | 控制台 → 弹性公网 IP → 释放 |
| 快照 / 自定义镜像 | 手动删除 | 按容量天计费 |
| 安全组 | 随实例释放（若是共享安全组则解绑即可） | |

释放前最后一件事：把要留档的输出/截图拉回本机，并入仓库 `docs/screenshots/` 与 DEVLOG。

## 6. k3s 在毕设 VM 上执行的前置条件与风险（不在云端练）

> k3s 具体步骤照 [k3s单节点搭建手册.md](k3s单节点搭建手册.md) 执行，本节只讲「动手前必须确认的事」。VM 现状：6 个 Java 微服务 + Milvus 三件套 + Nacos/Redis/RabbitMQ/registry 七容器常驻（见 `docker ps`）。

1. **内存预算**：k3s 空载 0.6~1.5G（DEVLOG 的 8.5G 预算是 16G 含监控全家桶的口径，VM 上**不要装监控**）。16G 总量足够，但装前必须看一眼：`free -h`，available ≥2G 再动手；不够就先分时停掉非必需容器（如 Milvus 三件套，用完 `docker start` 恢复）。
2. **端口占用检查**：`ss -lntp | grep -E ':(6443|80|443|8080)\b'`——6443 必须空闲；80/443 历史上空着（tomcat9 已 disable），若被占则 k3s 安装加 `--disable traefik`。**Traefik 与网关 8080 的关系**：Traefik 接管的是 80/443 入口，网关 8080 是应用端口，三者不冲突；真正要防的是 80/443 被其他进程先占导致 Traefik 起不来（k3s 手册阶段七第 4 行的失败对照）。检查命令手册阶段一 1.1 有，装前重跑一遍。
3. **与已有 Docker 共存**：k3s 自带 containerd 与 Docker 并存、镜像互不可见——应用镜像必须推 `localhost:5000` 后经 `registries.yaml` 给 k3s 用（手册阶段五）；不要为 k3s 装第二个 ingress、不要动现有 `tims-*` 容器与 compose 正本。
4. **装前必须拍 VMware 快照**（VMware 界面 → VM → Snapshot → Take Snapshot，建议命名 `aitims-pre-k3s-<日期>`），并在 DEVLOG 记一条快照名与时间。k3s 万一折腾坏（iptables/路由被改），回滚快照比清理现场可靠得多——这是 VM 环境相对云机最大的优势，必须用上。
5. **时机**：建议 **M4 推送压测结束后再做**。k3s 安装期容器反复启停会抢 CPU/内存（4 vCPU 是瓶颈，DEVLOG 已拍板负载分时错开），期间跑 200 单压测会污染 P95 时延数据；压测数据一旦作废重跑成本高。
6. 练完的清理走 k3s 手册阶段八（`k3s-uninstall.sh`，不碰 Docker 侧），异常时回滚快照。

**云 VM 分工一句话**：云机练四个中间件（随时候命、用完释放），VM 练 k3s（有快照兜底、贴近毕设真实部署形态——单节点验证正是 M8 的口径）。

## 7. 快速上手路径（云端流程，不含 k3s）

1. 控制台确认：实例规格/计费模式/安全组/EIP（第 5 节清单）；
2. `free -h && df -h /` 记录底座占用；开 2G swap（2.1）；配 Docker 加速（3.4）；
3. 按第 1 节推荐顺序逐组件做：每个组件 = 动手实验文档对应实验的 L1→L3（云上差异见本文第 2/3 节），做完 `docker compose -p lab-<组件> down -v` 再下一个；Milvus 最后做且单独窗口；
4. 收尾：动手实验文档「清理与收尾」+ 本文第 5 节释放清单 + DEVLOG 记录（含截图并入 `docs/screenshots/`）；
5. k3s 单独排期，在毕设 VM 上按第 6 节前置检查 + k3s 手册执行。
