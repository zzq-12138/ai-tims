# 公司集群准入核查清单（Kubernetes v1.24.17）

> 目标：在把六服务与中间件 apply 进公司集群之前，把所有「集群侧未知项」一次问清/查清。
> 用法：带着第 1 节的 5 个问题找管理员；把答案填到第 5 节；按第 6 节改对应文件；先过第 4 节的 hello-world 准入验证，再谈全量部署。
>
> 已知基线（用户提供，需现场复核）：6 节点（3 control-plane + 3 worker）、Ubuntu 24.04.4、containerd 1.6.24、内网 172.27.17.161–167、业务网段不出外网。

## 1. 这周末必须问到的 5 个问题

1. **namespace 与配额**：能否分配 `ai-tims` namespace？配额（CPU/内存/存储/PVC 数/Pod 数）是多少？我们的账号能创建 Deployment、StatefulSet、PVC、Ingress、Secret 吗？
2. **存储**：默认 StorageClass 叫什么？是否支持动态供给？单个 PVC 上限和集群剩余容量是多少？（我们需要约 87Gi，其中 MySQL 10Gi、Milvus/MinIO 各 20Gi、附件 20Gi。）
3. **入口**：IngressClass 名称是什么（默认是不是 `nginx`）？内网域名/DNS 如何解析？Ingress 是否允许 25MB 请求体和 WebSocket 长连接？
4. **镜像仓库**：仓库地址、项目名、推送账号/Token 是什么？能否给我们 `ai-tims`（或等价）项目？是否已有 mysql/redis/rabbitmq/nacos/etcd/minio/milvus 的镜像 mirror？
5. **网络与安全策略**：集群是否默认拒绝入站 NetworkPolicy？是否有 PodSecurityPolicy / PSA（restricted）限制？节点是否有污点？Pod 能否访问公网（`open.bigmodel.cn`）或必须走代理？

## 2. 完整核查表

| # | 项目 | 为什么需要 | 怎么查 / 问谁 | 查到后填在哪 |
|---|---|---|---|---|
| 1 | namespace 与 ResourceQuota | 配额不足会导致 Pod Pending；缺 requests/limits 会被配额拒绝 | `kubectl get ns`；`kubectl -n ai-tims get resourcequota,limitrange -o yaml`；问集群管理员 | 第 5 节 Q1；按需改 `deploy/k8s/base/resourcequota.yaml` |
| 2 | 默认 StorageClass 与容量 | 7 个 PVC 共约 87Gi，动态供给失败会全部 Pending | `kubectl get sc`；`kubectl get sc -o yaml`；`kubectl get pv`；问存储管理员 | 第 5 节 Q2；无默认 SC 时给 7 处 PVC 补 `storageClassName` |
| 3 | IngressClass 与域名 | `ingressClassName` 写错则 Ingress 永不生效 | `kubectl get ingressclass`；问网络管理员/DNS 负责人 | 第 5 节 Q3；改 `deploy/k8s/base/ingress.yaml` |
| 4 | 镜像仓库地址与权限 | 内网不能拉公网镜像；`ImagePullBackOff` 的首因 | `docker login <registry>`；`curl -k https://<registry>/v2/`；问仓库管理员 | 第 5 节 Q4；改 `deploy/k8s/overlays/company/kustomization.yaml` 与 `images.env` |
| 5 | NetworkPolicy 默认拒绝 | 默认 deny 会导致 gateway 到六服务、服务到中间件全断 | `kubectl get networkpolicy -A`；问网络管理员 | 第 5 节 Q5；如 deny，需额外放行清单（当前未提供 NetworkPolicy） |
| 6 | Pod Security Policy / PSA | `restricted` 会拒绝 root 中间件（MySQL/Redis/MinIO 等） | `kubectl get psp -A`（1.24 仍可能启用）；`kubectl get ns ai-tims -o jsonpath='{.metadata.labels}'`；问管理员 | 第 5 节 Q5；必要时申请 `baseline` 或豁免 |
| 7 | 节点可用资源与污点 | 3 worker 的实际 Allocatable 决定能否放下 8Gi 预留 | `kubectl top nodes`；`kubectl describe node <node> \| sed -n '/Allocatable/,/System Info/p'`；`kubectl get nodes -o custom-columns=NAME:.metadata.name,TAINTS:.spec.taints` | 第 5 节 Q5；必要时给 Deployment 加 tolerations 或下调 requests |
| 8 | 公网出口与 DNS | `ticket-knowledge` 调智谱 embedding、`ticket-ai` 调 GLM、system 发 SMTP | 在任一 Pod 内 `curl -I https://open.bigmodel.cn`（需镜像有 curl）；`kubectl exec ... -- cat /etc/resolv.conf`；问网络管理员 | 第 5 节 Q5；改 `common-configmap.yaml` 的 `LLM_BASE_URL`/`ZHIPU_EMBEDDING_URL` |
| 9 | 时区与 NTP | JVM/MySQL 时区、工单时间线、Token/日志排序 | 节点 `timedatectl`；`kubectl exec <pod> -- date` | 第 5 节 Q5；Pod 已固定 `TZ=Asia/Shanghai`，节点 NTP 由管理员保障 |
| 10 | Service / NodePort 限制 | 部分公司集群禁用 NodePort 或限制端口段 | `kubectl auth can-i create services --subresource='' -n ai-tims`；问管理员 | 第 5 节 Q1/Q5；当前只用 ClusterIP，理论上不受影响 |
| 11 | 准入 Webhook（OPA/Kyverno 等） | 可能强制标签、镜像 digest、禁止 latest | `kubectl get validatingwebhookconfigurations`；问管理员 | 第 5 节 Q1；按规范补标签/改镜像引用 |
| 12 | kubeconfig 权限 | 无 `create` 权限会在 apply 时才暴露 | `kubectl auth can-i --list -n ai-tims` | 第 5 节 Q1；向管理员申请 |
| 13 | 集群版本/CRI 复核 | 交付基线是 1.24.17 / containerd 1.6.24 | `kubectl version --short`；`kubectl get nodes -o wide` | 第 5 节 Q0；若版本不符，回到兼容自检文档复核 |

## 3. 只读自查命令（建议原样执行并留输出）

```bash
kubectl version --short

kubectl describe node <worker-node> | sed -n '/Allocatable/,/System Info/p'

```

## 4. 准入最小验证（全量部署前必须过）

不要一上来 apply 全量。先证明「镜像能拉、Pod 能跑、PVC 能绑、DNS 能通」：

```bash
# 4.1 镜像 + Pod 准入（把镜像换成公司仓库里真实存在的小镜像）
kubectl -n ai-tims run hello --image=harbor.example.com/library/busybox:1.36 \
  --restart=Never -- sleep 3600
kubectl -n ai-tims get pod hello -o wide
kubectl -n ai-tims logs hello
kubectl -n ai-tims delete pod hello

# 4.2 PVC 动态供给
kubectl -n ai-tims apply -f - <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: hello-pvc
spec:
  accessModes: ["ReadWriteOnce"]
  resources:
    requests:
      storage: 1Gi
EOF
kubectl -n ai-tims get pvc hello-pvc
kubectl -n ai-tims delete pvc hello-pvc

# 4.3 集群内 DNS（等 tims-nacos 起来后再执行；也可先用任意 Service 验证）
kubectl -n ai-tims run dns-test --image=harbor.example.com/library/busybox:1.36 \
  --restart=Never --rm -it -- nslookup tims-nacos
```

判定：`hello` 必须 `Running`、`hello-pvc` 必须 `Bound`、DNS 必须返回 ClusterIP。任一失败，先解决准入，不要继续。

## 6. 查到答案后改哪个文件

| 答案 | 要改的文件 | 改什么 |
|---|---|---|
| 镜像仓库地址 | `deploy/k8s/overlays/company/kustomization.yaml` | 所有 `harbor.example.com` → 实际仓库域名 |
| 镜像仓库地址（脚本侧） | `deploy/scripts/images.env` 或执行时 `COMPANY_REGISTRY=` | `REGISTRY_PREFIX` / `COMPANY_REGISTRY` |
| IngressClass | `deploy/k8s/base/ingress.yaml` | `spec.ingressClassName` |
| 域名 | `deploy/k8s/base/ingress.yaml` | `spec.rules[0].host` |
| 默认 StorageClass 不存在/非默认 | `deploy/k8s/base/middleware/*.yaml`、`deploy/k8s/base/apps/order.yaml` | 7 处 PVC/PVC 模板补 `storageClassName` |
| 配额小于当前值 | `deploy/k8s/base/resourcequota.yaml` | 下调 hard 值（优先下调 requests，保证能调度） |
| 节点污点 | 各 Deployment/StatefulSet | 增加 `tolerations` |
| 无公网出口 | `deploy/k8s/base/config/common-configmap.yaml` | `LLM_BASE_URL`、`ZHIPU_EMBEDDING_URL` 改为内网代理；system 保持 `VERIFY_SENDER=mock` |
| PSP/PSA 限制 | `deploy/k8s/base/namespace.yaml` 或管理员豁免 | 中间件镜像需 root 的，申请 `baseline` 或单独 namespace |
| NetworkPolicy 默认拒绝 | 新增 NetworkPolicy 清单 | 放行 gateway→六服务、六服务→MySQL/Redis/Rabbit/Nacos/Milvus |

## 7. 可直接发给管理员的话术

> 您好，我们需要在测试集群（v1.24.17）申请一个 `ai-tims` namespace 做毕业设计部署，想确认 5 件事：
> 1）该 namespace 的 CPU/内存/存储/PVC/Pod 配额是多少，我们的账号能否创建 Deployment/StatefulSet/PVC/Ingress/Secret？
> 2）默认 StorageClass 是什么，是否支持动态供给，单 PVC 上限多少？我们需要约 87Gi。
> 3）IngressClass 名称是什么？内网域名怎么解析？是否允许 25MB 请求体和 WebSocket？
> 4）镜像仓库地址、项目名和推送账号/Token 是什么？是否已有 mysql/redis/rabbitmq/nacos/etcd/minio/milvus 的镜像？
> 5）集群是否默认拒绝 NetworkPolicy、是否有 PSA/PSP 限制、节点有无污点、Pod 能否访问公网（open.bigmodel.cn）？
> 我们会在正式部署前先跑一个 hello-world + 1Gi PVC 的准入验证，通过后再申请全量资源。
