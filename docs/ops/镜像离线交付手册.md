# AI-TIMS 镜像离线交付手册

> 适用对象：不熟悉 Docker / 本项目的交付与运维人员。照着做即可。
> 背景：公司内网集群**不能出外网**，公司 registry **从外部不可访问**，所以镜像必须在开发机上构建好、逐个打成 tar.gz、人工搬进公司内网。

## 1. 开发机：构建 + 导出

```bash
cd ~/ai-tims
bash deploy/scripts/export-images.sh
```

脚本做的事（全部只读宿主，不停止、不删除任何现有容器/镜像，不碰 k3s containerd）：

1. 用 JDK17 跑 `mvn -B -DskipTests clean package`（六个后端）；
2. 用 `deploy/docker/Dockerfile`（`eclipse-temurin:17-jre-jammy`，非 root uid 10001）逐个构建六个后端镜像；
3. 用 `ai-tims-front/Dockerfile` 多阶段构建前端镜像（node 编译 → `nginx:1.27-alpine` 托管）；
4. 检查/拉取四个中间件镜像，并把 `redis:7-alpine` 打成公司自有名 `harbor.xnunion.com/library/tims-redis:7-alpine`（导出前强制核对 `linux/amd64`）；
5. 每个镜像 `docker save | gzip` 导出为一个文件，并做两道自检：`gzip -t`、回读 `manifest.json` 确认 RepoTags 正确；
6. 生成 `MANIFEST.txt`（文件/标签/大小/md5）、`MANIFEST.md5`（`md5sum -c` 格式）、`load-all.sh`。

只补清单不重新构建（比如上次在清单步骤中断）：

```bash
MANIFEST_ONLY=1 bash deploy/scripts/export-images.sh
```

**预期输出**（结尾）：`================ 交付完成 ================` 后紧跟完整清单，且有一行 `自检通过：MD5 全部匹配`。

**常见失败**：

- `未找到 xxx 的可执行 JAR` → Maven 没跑完，往上翻编译错误；
- `docker build` 拉不到基础镜像 → 开发机 Docker 镜像源/代理问题；
- `git` 报 `dubious ownership` 之类 → 只影响清单里的“源码版本”字段，不影响镜像。

## 2. 搬运与校验

拷贝 `tims-images/` 目录下 **12 个 tar.gz + 3 个文本文件** 到 U 盘/摆渡机。**搬运后必须先在任意 Linux 上校验**：

```bash
cd tims-images
md5sum -c MANIFEST.md5
```

**预期输出**：12 行全部 `OK`。

出现 `FAILED` → 该文件传输损坏，重新拷贝那一个文件即可（大文件跨机拷贝损坏并不罕见，务必校验）。

## 3. 公司侧：加载镜像

```bash
bash load-all.sh
```

脚本会先自动跑 `md5sum -c MANIFEST.md5`，全部通过后才逐个 `docker load`，最后逐条核对 12 个镜像是否都在本地（输出 `OK` / `缺失`）。

也可以手动加载单个文件：

```bash
docker load -i ticket-gateway-1.0.0.tar.gz
```

**常见失败**：

- `Cannot connect to the Docker daemon` → `sudo systemctl start docker`；
- `md5sum: FAILED` → 回第 2 步重拷；
- 加载后 `docker images` 里没有对应 tag → 文件拷错/只拷了一半，重新拷贝。

## 4. 公司侧：推送到 Harbor

镜像打的就是 Harbor 地址，装载后直接 push：

```bash
docker login harbor.xnunion.com          # 账号找运维
for f in ticket-gateway ticket-system ticket-order ticket-knowledge ticket-ai ticket-push ai-tims-front; do
  docker push harbor.xnunion.com/library/$f:1.0.0
done
docker push harbor.xnunion.com/library/tims-redis:7-alpine   # 已是公司自有名，无需重打 tag
```

中间件镜像如果也要进公司仓库，先按 k8s 清单里的名字重打 tag 再推：

```bash
docker tag rabbitmq:3-management  harbor.xnunion.com/library/rabbitmq:3-management
docker tag milvusdb/milvus:v2.4.15 harbor.xnunion.com/library/milvus:v2.4.15
docker tag quay.io/coreos/etcd:v3.5.14 harbor.xnunion.com/library/etcd:v3.5.14
docker tag milvusdb/minio:RELEASE.2024-05-28T17-19-04Z harbor.xnunion.com/library/minio:RELEASE.2024-05-28T17-19-04Z
```

**失败判读**：

| 报错关键字 | 原因 |
|---|---|
| `unauthorized` / `authentication required` | 没 login 或密码过期 |
| `denied` / `forbidden` | 账号对 `library` 项目没有 push 权限 |
| `no such host` / `i/o timeout` | Harbor 地址写错或内网 DNS 不通 |
| `blob upload unknown` / `filesystem` | 仓库存储满，找运维 |

换项目（非 `library`）时不必重跑导出，`docker tag` 后 push 即可：

```bash
docker tag harbor.xnunion.com/library/ticket-ai:1.0.0 harbor.xnunion.com/<新项目>/ticket-ai:1.0.0
```

## 5. 验证镜像真的进了仓库

```bash
docker pull harbor.xnunion.com/library/ticket-ai:1.0.0
# 预期：Status: Image is up to date / Downloaded newer image
```

## 6. 已知边界（部署前必读）

- **前端镜像只能在 K8s / 能解析 `ticket-gateway` 的网络里运行**：`ai-tims-front/nginx.conf` 在启动时解析上游 `ticket-gateway:8080`，单机 `docker run` 会因解析失败直接退出（`host not found in upstream`）。这是配置现状，不是镜像损坏。
- **kustomization 前缀与本次 tag 不一致**：`deploy/k8s/overlays/company/kustomization.yaml` 里写的是 `harbor.example.com/ai-tims/...`，本次镜像 tag 是 `harbor.xnunion.com/library/...`。`kubectl apply -k` 前要把每个 `newName` 改成 `harbor.xnunion.com/library/<服务>`，否则 Pod 会 `ImagePullBackOff`。
- **中间件镜像保留上游原名**：与 `deploy/scripts/images.env` 的 `UPSTREAM_IMAGES` 一致；进公司仓库需要上面第 4 节的重打 tag 步骤。**Redis 例外**：本项目在自己的 namespace 内自建 Redis，导出时已直接打成 `harbor.xnunion.com/library/tims-redis:7-alpine`（`linux/amd64`），load 后即为此名，`docker push` 即可。
- **基础镜像**：后端用 `eclipse-temurin:17-jre-jammy`（只含 JRE，非 root 运行）；前端运行层是 `nginx:1.27-alpine`。node 只用于构建，不进最终镜像。
- **逐文件导出会重复携带基础层**：六个后端每个都含一份 JRE 层，所以 12 个文件总体积略大于合并单包；换来的是单个文件损坏只需重拷一个。
