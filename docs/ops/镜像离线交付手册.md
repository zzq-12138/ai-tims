# AI-TIMS 镜像离线交付手册

> 适用对象：不熟悉 Docker / 本项目的交付与运维人员。照着做即可。
> 背景：公司内网集群**不能出外网**，公司 registry **从外部不可访问**，所以镜像必须在 VM 上构建好、打成 tar 包、人工搬进公司内网。

## 0. 角色与文件总览

| 谁执行 | 在哪 | 用什么 |
|---|---|---|
| 开发侧（VM） | 开发 VM `~/ai-tims/scripts/images/` | `build-images.sh`、`save-images.sh` |
| 搬运 | U盘 / 内网摆渡 | tar + tar.sha256 + 三个脚本 + images.env |
| 公司侧 | 内网任一装了 Docker 的机器 | `load-images.sh`、`push-images.sh` |

交付包清单（save 完成后从 `~/image-delivery/` 拷走）：
`tims-images-<版本>.tar`、`tims-images-<版本>.tar.sha256`

另需拷贝：`scripts/images/` 下的 `load-images.sh`、`push-images.sh`、`images.env`（三个小文本文件）。

---

## 1. VM 侧：构建镜像

```bash
cd ~/ai-tims/scripts/images
vim images.env          # 只改 APP_VERSION，如 0.3.0（禁止 latest）
./build-images.sh
```

**预期输出**（结尾）：

```
== 构建完成清单 ==
tims/ticket-gateway:0.3.0   xxxMB
tims/ticket-order:0.3.0     xxxMB
...（共 6 个后端）
tims/ai-tims-front:0.3.0    xxxMB
```

每行镜像后应显示 `linux/amd64`（`docker image inspect <镜像名> --format '{{.Architecture}}'` 核对）。

**常见失败**：
- `找不到 xxx/target/xxx-1.0.0-SNAPSHOT.jar` → Maven 没跑完或编译失败，往上翻 mvn 输出的 `[ERROR]` 行；
- `APP_VERSION 未设置或为 latest` → 编辑 images.env；
- 拉基础镜像超时 → VM 代理/镜像源问题，重试或换源（本项目有国内加速源策略）。

只改了某个服务时可增量构建：`./build-images.sh ticket-order`（前端：`./build-images.sh front`）。

## 2. VM 侧：打 tar 包 + 生成校验

```bash
./save-images.sh
```

**预期输出**：

```
== 交付包清单（目录：/home/dev/image-delivery）==
-rw-r--r-- 1 dev dev 1.2G tims-images-0.3.0.tar
-rw-r--r-- 1 dev dev    88 tims-images-0.3.0.tar.sha256
总体积：1.2G
```

包里含 **7 个业务镜像 + JRE/nginx 2 个基础镜像**，公司侧 load 后不再需要外网。

## 3. 搬运：U盘拷贝与校验

拷贝两个文件到 U盘。**拷完必须先在任意 Linux 上验一次**：

```bash
sha256sum -c tims-images-0.3.0.tar.sha256
```

**预期输出**：

```
tims-images-0.3.0.tar: OK
```

显示 `FAILED` → 传输损坏，重新拷贝（大文件跨机拷贝损坏并不罕见，VM 有过文件尾字节丢失前科，务必验）。

## 4. 公司侧：load + tag

```bash
mkdir -p ~/tims-delivery && cd ~/tims-delivery
# 把 U盘两个 tar 文件和三个脚本拷进来
vim images.env          # 填 REGISTRY_PREFIX=公司仓库地址/tims（问运维要）
./load-images.sh ./tims-images-0.3.0.tar
```

**预期输出**：

```
tims-images-0.3.0.tar: OK
== docker load ==
Loaded image: tims/ticket-gateway:0.3.0
...（8 个：7 业务 + 基础镜像若干条）
== tag -> 公司前缀 ==
OK  registry.corp.example.com/tims/ticket-gateway:0.3.0
...
== load + tag 全部完成，可执行 ./push-images.sh ==
```

**常见失败**：
- `sha256sum -c` 失败 → 包坏了，回到第 3 步重拷；
- `[缺失] tims/xxx:0.3.0` → tar 不全，找开发侧确认 save 是否成功；
- `Cannot connect to the Docker daemon` → 这台机器 Docker 没起：`sudo systemctl start docker`。

## 5. 公司侧：push 到公司仓库

```bash
docker login registry.corp.example.com    # 账号找运维
# 或免交互：REG_USER=xxx REG_PASS='xxx' ./push-images.sh
./push-images.sh
```

**预期输出**（每个镜像一段，结尾汇总）：

```
== push: registry.corp.example.com/tims/ticket-gateway:0.3.0 ==
0.3.0: digest: sha256:xxxx size: 1571
================ push 汇总（版本 0.3.0）================
成功 7 个：...
失败 0 个：无
[结果] 全部推送成功
```

**失败判读**（脚本会打印失败镜像名 + 错误原文最后 5 行）：

| 错误原文关键字 | 原因 |
|---|---|
| `unauthorized` / `authentication required` | 没 login 或密码过期，重新 `docker login` |
| `denied` / `forbidden` | 账号对目标项目没有 push 权限 |
| `no such host` / `i/o timeout` | 仓库地址写错或内网 DNS 不通 |
| `blob upload unknown` / `filesystem` | 仓库存储空间满，找运维 |

失败的镜像单独重跑 `./push-images.sh` 即可（push 幂等，已成功的重复推无副作用）。

## 6. 验证镜像真的进了公司仓库

任选其一：

```bash
# 方法 A：重新拉一遍（最可靠）
docker pull registry.corp.example.com/tims/ticket-gateway:0.3.0
# 预期：Status: Image is up to date / Downloaded newer image

# 方法 B：查 manifest
docker manifest inspect registry.corp.example.com/tims/ticket-gateway:0.3.0 > /dev/null && echo EXISTS
```

再到集群部署时使用 `imagePullPolicy: IfNotPresent` + 本仓库 tag，集群节点不需要外网。

## 7. 附：常见问题

- **为什么禁止 latest？** 集群回滚与版本追溯都需要明确版本号；版本号只在 `images.env` 一处改。
- **为什么 VM 上 save 要带基础镜像？** 公司侧只 load，不再 build；带上 JRE/nginx 基础镜像可保证任何后续操作（如在本机重建镜像）都不依赖外网。
- **前端镜像为什么没有 node 基础镜像依赖？** 前端是多阶段构建，公司侧拿到的最终镜像只含 nginx，编译用的 node 镜像只在 VM 上需要。
