# AI 应用层·语义缓存（第 3 项）落地说明

## 1. 能力边界

- **两级匹配**：先做问题归一化后的精确 hash（零成本），未命中再取 embedding 做余弦相似度匹配；相似度 ≥ 阈值才算命中。
- **命中后直接复用历史答案**：不再调用对话模型，token 计 0，`ai_call_log` 落一行 `status=CACHE_HIT`。
- **缓存桶 = 租户 + 检索上下文指纹 + 模型**。上下文指纹由工单号、历史轮次、本次命中的知识引用（id + 标题）哈希得到，问题本身不参与指纹。这样同义改写可以命中，跨租户/跨工单/跨模型不会串答案。
- **只缓存“干净”的答案**：检索降级、知识不可用、护栏拦截、空答案一律不写缓存，避免把“无知识兜底话术”缓存下来反复命中。
- **默认关闭**：`tims.ai.cache.enabled=false`。关闭时不调用 embedding、不写缓存、响应不新增 `cache` 字段，接口契约与改动前一致。
- **不做的**：多实例共享缓存、知识发布时主动失效、按用户维度的个性化缓存。当前是单实例进程内缓存，靠 TTL 与容量上限控制。

## 3. 怎么开

```bash
AI_CACHE_ENABLED=true                 # 总开关，默认 false
AI_CACHE_THRESHOLD=0.92               # 余弦阈值，默认 0.92
AI_CACHE_TTL_SECONDS=86400            # 默认 1 天
AI_CACHE_MAX_ENTRIES=2000             # 单租户条目上限
AI_CACHE_EMBEDDING_MODEL=embedding-3
AI_CACHE_EMBEDDINGS_PATH=/embeddings
AI_CACHE_MIN_QUESTION_CHARS=6
AI_CACHE_EMBEDDING_TIMEOUT_MS=3000
```

所有开关都只影响 AI 模块内部；未配置的租户/环境沿用原行为。

## 4. 实测数字

**评测口径**：50 族 × 6 行 = 300 条。每族 1 条标准问法（缓存种子）、3 条同义改写（应命中）、1 条近邻负例（同设备同子系统、不同部件/指标，不应命中）、1 条无关对照（其他设备，不应命中）。回放 250 条查询，答案模型 `glm-5.3-flash`，向量模型 `embedding-3`，判分为“规格数值必须全部出现在答案中”。本轮实跑 300 次模型调用，**实测费用 0.1567 元**。数据与逐条明细见 `缓存评测报告.md` / `缓存评测.json`。

### 4.1 总体

| 指标 | 无缓存 | 阈值 0.92 | 阈值 0.90 | 阈值 0.86 |
|---|---|---|---|---|
| 同义改写命中率 | 0% | 46.67% | 73.33% | 96.0% |
| 负例误命中率 | 0% | 0% | 0% | 2.0% |
| 准确率 | 100% | 100% | 100% | 99.2% |
| 质量损失 | 0 | 0 pp | 0 pp | 0.8 pp |
| 省下调用（250 条） | 0 | 70 | 110 | 146 |
| 省下费用 | 0 | 0.0354 元 | 0.0562 元 | 0.0748 元 |
| 命中平均延迟 | — | 284 ms | 284 ms | 281 ms |
| 未命中平均延迟 | 5970 ms | 5981 ms | 6131 ms | 6045 ms |

精确 hash 基线在同义改写上命中 **0 条**：只有把问题原样重复才能命中，说明“只做 hash 缓存”在本场景几乎无效。

### 4.2 阈值扫描（完整表见评测报告第 2 节）

- **0.80**：改写全中，但 10/100 负例误命中，准确率掉到 96.0%，质量损失 4.0 pp。
- **0.86**：命中 96%，误命中 2%，质量损失 0.8 pp；这是“要命中率”的可选档。
- **0.90**：命中 73.33%，误命中 0，质量损失 0。这是本评测集上**零损失的最高命中率**。
- **0.92**：命中 46.67%，误命中 0；默认取它，是为了在负例最大相似度 0.8845 之上留 0.0355 的安全边际。
- **0.94 及以上**：命中率快速衰减到 24% / 6% / 0%，收益基本消失。

同义改写相似度分布：min 0.8292 / p10 0.8774 / 中位 0.9179 / max 0.9712；负例：max 0.8845 / p90 0.7986 / 中位 0.6363。两条分布的重叠区是 0.8292–0.8845，阈值只要压进这个区间，就开始用质量换命中率。

### 4.3 命中但答错（逐条可查）

- 默认阈值 0.92：**0 条**。
- 阈值 0.90：0 条。
- 阈值 0.86：2 条（均为近邻负例），质量损失 0.8 pp。
- 阈值 0.80：10 条（均为近邻负例），质量损失 4.0 pp。

全部 10 条错误样本在 `缓存评测报告.md` 第 3.3 节逐条列出（问题、命中的标准问法、最高相似度、首次命中阈值、缺失规格值、缓存答案截断），JSON 的 `wrong_hits_by_threshold` / `wrong_hit_index` 可机读。典型例子：

| 行 | 问题 | 命中的标准问法 | 相似度 | 缺失规格 |
|---|---|---|---|---|
| F12-N | 贴合机贴合辊表面辊面粗糙度是多少？ | 贴合机贴合辊与背辊辊间平行度是多少？ | 0.8845 | 0.4 |
| F01-N | 蚀刻机排液管路与阀门的排液流量标准？ | 蚀刻机废液液位与排液管路的废液液位标准？ | 0.8736 | 85 |
| F25-N | AOI 相机镜头与对焦机构的对焦偏差？ | AOI 相机与光源的漏检率？ | 0.8436 | 0.02 |

这些样本的共同点：**同一台设备 + 同一子系统 + 同一个句式模板，只有“部件/指标”两个词不同**。embedding 对这种“实体替换”不敏感，是语义缓存在工业知识问答里最需要防的失败模式。

### 4.4 成本与延迟

- 无缓存：250 次调用，0.1304 元，平均 5970 ms。
- 阈值 0.92：省 70 次调用 / 0.0354 元；命中平均 284 ms，比未命中快 **21 倍**。
- 向量费用：`embedding-3` 已购 5000 万专属包，`application.yml` 单价记 0，本轮按 0 计；若按标准价另算需以账单为准。

**结论要这么读**：在 `glm-5.3-flash` 这个价位上，省下的钱很小（250 条只省 3 分钱），缓存的真实价值是**延迟**——工单诊断场景里 6 秒和 0.3 秒是可用性差异。若换成价格更高的模型，费用收益会按单价等比例放大。

## 5. 写进论文时的结论

1. 工业知识问答里，用户问法高度模板化但实体组合多变。精确 hash 覆盖不了改写（本集 0 命中），语义缓存能覆盖 46.67%（保守阈值）到 73.33%（零损失最优阈值）。
2. **阈值不是越高越好，也不是越低越好**：0.90 是本评测集的质量/命中率拐点；0.86 以下开始为 0.8–4.0 pp 的质量损失买单。
3. **质量损失几乎全部来自“同设备 + 同子系统 + 不同部件/指标”的近邻负例**，不是来自同义改写的答案漂移。这为后续优化指了方向：在相似度之外再加一层实体/指标一致性校验，比继续调阈值更有效。
4. 经济性：本轮模型单价低，费用节省只有 0.0354 元/250 次；延迟收益（5970 ms → 284 ms）才是主要收益。这个结论要按模型单价做敏感性，不能直接外推。

## 6. 局限

1. 只回放了“标准问法预热 + 单次查询”，没有模拟多轮里缓存条目增长后的相互干扰。
2. 生产实现比评测多一层“检索上下文指纹”；评测按同桶处理，因此负例误命中率是**上界**，线上更低。
3. 命中直接复用旧答案；知识库在 TTL 内更新时用户会看到旧结论，需要靠 TTL 和发布侧失效控制。
4. 单实例进程内缓存，多实例不共享，命中率按实例计。
5. 质量判定只看规格数值是否出现，不判表述完整性与额外错误信息。
6. 评测集是规则生成的，不是真实工单日志；改写的多样性有限。

## 7. 接口契约（前端对接）

**同步接口**（`POST /api/ai/chat`）响应新增可选 `cache` 字段，仅在 `AI_CACHE_ENABLED=true` 时出现：

```json
{
  "answer": "...",
  "model": "glm-5.3-flash",
  "refs": [],
  "fallback": false,
  "degraded": false,
  "retrievalMs": 120,
  "latencyMs": 284,
  "usage": { "promptTokens": 0, "completionTokens": 0, "totalTokens": 0 },
  "cache": {
    "hit": true,
    "similarity": 0.9341,
    "exact": false,
    "matchedQuestion": "贴片机供料器的供料间距规格是多少？",
    "ageSeconds": 3600,
    "threshold": 0.92
  }
}
```

未命中时为 `{"hit": false, "threshold": 0.92}`；关闭缓存时该字段不返回。

**流式接口**（SSE）：

- `meta` 事件里带同一个 `cache` 对象；
- `usage` 事件新增 `cacheHit`、`cacheSimilarity`，命中时 `promptTokens/completionTokens/totalTokens` 均为 0。

**观测**：命中调用在 `ai_call_log` 落 `status=CACHE_HIT`、token 为 0；后续观测面板可直接按 `status` 统计命中率，按“同场景命中行的平均费用”估算节省。
