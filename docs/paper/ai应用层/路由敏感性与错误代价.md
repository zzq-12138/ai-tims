# 路由敏感性分析与错误代价（第 2 项补充）

- 数据：300 条，每行都有大模型答案与大模型/小模型的实测 token 费用
- 方法：**离线反事实回放**。换阈值、换流量画像只是改变「这一行用哪份已有答案」，不新增模型调用，**本轮分析零 API 费用**
- 口径：与主报告一致（简单题比规格值、计算题比数值 ±0.06、联合诊断题语义阅卷）；路由与全小**共用同一份小模型答案**，避免同一模型两次采样的波动混进对比

**三个发现：**

1. **准确率在 0.3–0.9 完全不变（都是 93.67%）**，因为 30 条计算题的得分是 0.1，任何 ≥0.3 的阈值都拦不住它们。
2. **成本却随阈值一路下降**：0.5 时 0.2112 元，0.9 时 0.0792 元，1.0 时 0.0225 元。原因是把诊断题也丢给小模型——而那 120 条题小模型本来就会做（119/120）。
3. 所以 0.5 这个默认阈值**既没保住准确率，也没省到钱**：同准确率下，阈值 1.0 比 0.5 省 89.3%。

148 条简单题 0.0 分、26 条计算题 0.1 分、120 条诊断题 0.6–1.0 分，中间是空的。
**双峰分布决定了阈值只能整体平移，无法把「计算题」单独切出来**——这正是第 3.5 节信号上限的由来。

### 3.3 盈亏平衡：在默认阈值 0.5 下路由被双向支配

- 路由 vs 全大：省 0.0973 元，多 19 条错误 → 只有单次错误成本 **< 0.0051 元**（约合 0.3 秒人工）时路由才更好
- 路由 vs 全小：多花 0.2041 元、错误数相同（19 vs 19）→ **不存在任何错误成本让路由更好，全小严格支配路由**
- 合并：错误成本 < 0.0051 元时全大更好，否则全小更好 → **0.5 阈值下路由在任何错误成本下都不是最优**
- 全大 vs 全小的分界点：单次错误成本 **0.0159 元**（约合 0.5 分钟人工复核）

### 3.4 把阈值推到最优（1.0）后的结论

- 最优阈值 1.0：准确率 93.67%、成本 0.0225 元（相对全大省 92.7%）
- 此时路由优于全大需错误成本 < **0.0151 元**；对全小仍是错误数相同、成本更高，**没有占优区间**
- 结论：即便把阈值推到成本最低的 1.0，路由也只能在「单次错误成本低于 1.5 分钱」时优于全大，对全小始终劣势；而任何以分钟计的人工复核（单次 ≥1 元）都让全大模型胜出

### 3.5 信号上限：路由的价值全在信号质量

- Oracle 路由（只有小模型真会答错的题才给大模型）只需给大模型 **19 条**，准确率 100.0%、成本 0.0221 元（省 92.84%）
- 当前规则路由：93.67% / 0.2112 元，给大模型 120 条
- 同一条流水线、同一批答案，**只要分流判得准，就能 100% 准确率下省 90%+**；
  现在的规则两头都错：120 条诊断题白送大模型（本来小模型就会），30 条计算题全给小模型（本来必须给大模型）

## 4. 可写进论文的结论

1. 在当前价格与评测集上，**规则路由不是最优解**：相对全大省 31% 掉 6.33pp；相对全小准确率完全相同（281 vs 281 条），成本贵 29.7 倍。
2. 原因是得分双峰 + 信号与难度错位：阈值在 0.3–0.9 之间准确率零变化，只能调成本，不能调质量。
3. 引入错误代价后，默认阈值 0.5 的路由被全大与全小双向支配（错误成本 < 0.0051 元时全大更好，否则全小更好，而路由与全小的错误数完全相同）；即使把阈值调到成本最低的 1.0，路由也只能在「单次错误成本 < 0.0151 元」时优于全大，对全小始终严格劣势。
4. 路由真正的空间由信号决定：oracle 路由 0.0221 元即可 100% 准确率。下一步应把「是否需要数值计算」做成显式特征，而不是继续调阈值。

## 5. 局限

1. 反事实回放假设「某行的模型输出与是否被路由无关」，对无状态问答成立；引入缓存或多轮上下文后不成立。
2. 画像从 300 条评测集有放回抽样，计算题样本池只有 30 条，50% 画像下重复抽样较多，区间只反映抽样波动。
3. 错误成本全部为假设，无项目真实复核工时/人工成本数据；已给 3–16 元/次的敏感性区间。
4. 未计入延迟差异：全大模型平均 10.3 s，简单档明显更快，报告未把响应时间折成业务价值。
5. 未计入第 3 项语义缓存的成本下降。
