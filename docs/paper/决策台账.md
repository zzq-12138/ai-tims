## 二、决策条目

### DEC-01 行业方向选型：SMT / 精密电子制造

- **决策结论**：保持现状，论文统一定位为「SMT / 精密电子制造设备维保」，不换行业。
- **备选方案**：CNC 机加工 / 汽车维修（OBD）/ IT 运维工单 / 电梯·暖通·电力 / 航空 ATA。
- **决定性数据**：六方向五维评分（可得性 / 字段完整度 / 规模 / 复杂度 / 迁移成本）：SMT **19**、CNC 15、汽车 19、IT 运维 19、电梯暖通 12、航空 18。仓库实测：8 类设备（贴片机 11、AOI 10、涂布 10、贴合 10、蚀刻 10、回流焊 2、MES 2、SPI 1），56 条记录去重后 54 条唯一知识点。同象异因可构造性：贴装偏移（锡膏印刷/贴装/炉温）、蚀刻不均（喷嘴/浓度/温度）、AOI 模糊（对焦/光源/镜头）。
- **为什么不选另一边**：汽车与 IT 运维总分同为 19，但迁移成本仅 1 分——换方向会作废 54 条知识、100 条评测、8 类设备与 M7 八轮消融；且 CNC/电梯/航空的公开数据是振动/电流时序，缺「措施-验证-适用条件」文本字段。
- **论文建议表述**：「本文面向 SMT / 精密电子制造设备维保场景，覆盖贴片、AOI、SPI、回流焊、涂布、贴合、蚀刻与 MES 共 8 类对象。」
- **局限与答辩风险**：总分与汽车/IT 并列，必须用「迁移成本 + 同象异因可构造性」做 tie-break 说明，不能只说「SMT 最好」；`glassId` 等面板命名残留需在论文中清理口径。
- **证据出处**：`docs/paper/研究方向/数据与基线决策_v1.md` §1–§2。

### DEC-02 基线嵌入模型：BGE-M3 与 embedding-3 双报

- **决策结论**：论文主基线写 **BGE-M3（CPU，1024 维）**；现网部署继续用 **embedding-3（API，1024 维）**；两者在同一评测集上同时报告。
- **备选方案**：①只报 BGE-M3；②只报 embedding-3；③换其他开源 embedding。
- **决定性数据**（61 条 PUBLISHED + 100 条 query，同一余弦检索）：BGE-M3 Hit@3 **98.0%**（95% CI 95–100）、Hit@1 97.0%、Recall@5 99.0%、MRR 0.979；embedding-3 Hit@3 **100%**、Hit@1 98.0%、Recall@5 100%、MRR 0.990。McNemar：BGE 独有命中 0、embedding 独有命中 2，**p=0.5 不显著**。分风格 Hit@3：colloquial 93.8% vs 100%、missing 93.3% vs 100%。延迟（4 vCPU CPU-only）：BGE 均值 **203.4ms** / P95 **364.5ms**；embedding-3 均值 **293.1ms** / P95 **379.9ms**。建库：570ms/条 vs 27ms/条（BGE 慢约 21×，但离线一次性）。
- **为什么不选另一边**：只报 embedding-3 会被质疑「为什么不用导师指定的 BGE-M3 / 是否挑模型」，且 API 不可离线复现；只报 BGE-M3 会丢掉现网已建索引与吞吐优势。
- **论文建议表述**：「本文以 BGE-M3 作为可复现的 dense 基线，另以现网 embedding-3 作为部署对照；两者 Hit@3 分别为 98.0% 与 100.0%，McNemar p=0.5，差异不显著。部署选择 embedding-3 基于批量建库吞吐与现网稳定性，而非检索精度显著更优。」
- **局限与答辩风险**：n=54/100，2pp 差异不显著，不能写「embedding-3 更准」；BGE-M3 的 P95 364.5ms 是单并发 CPU 值，与 M7 的 279.7ms（含服务链路、embedding-3）不可跨表直接比较。
- **证据出处**：`docs/paper/评测/_baseline_compare.json`；`scripts/eval/compare_embedding_baseline.py`；`docs/paper/研究方向/数据与基线决策_v1.md` §5。

### DEC-03 去重阈值：0.85 召回档 vs 0.92 生产档

- **决策结论**：论文「基线」写 **0.85**（候选生成/召回档）；系统配置用 **0.92 + 人工确认**（生产/精度档）。二者是不同层面口径，不矛盾。
- **备选方案**：①统一 0.85；②统一 0.92 无人工确认；③0.75 松阈值。
- **决定性数据**：现有 `ai_extracted` 256 条有分数样本中，3 条 MERGE 全部在 **0.9385**（同标题 MES 重复），0.92–0.98 共 3 条，**0.85–0.92 为 0 条**，<0.85 共 253 条 → 两档在真实日志上无行为差异。成对相似度（56 条有效记录）：BGE-M3 在 ≥0.92 有 2 对且全为同标题真重复；0.85–0.92 有 **12 对**，逐对判读**可直接合并 0 对**（6 对因果/变体、6 对不同故障或跨设备）。embedding-3 ≥0.92 有 3 对，其中 **0.9262 为假合并反例**（贴片机贴装偏移 vs 锡膏印刷偏移）；0.85–0.92 有 **46 对**。漏合并：两档均覆盖 2 组真重复，**漏合并 0**。
- **为什么不选另一边**：统一 0.85 会引入 12/46 对候选且 0 对可合并，纯增人工负担；统一 0.92 无人工确认会出现 0.9262 这类假合并直接入库。
- **论文建议表述**：「0.85 为文献基线的候选生成阈值（召回优先），0.92 为生产入库阈值（精度优先，所有 MERGE 需人工确认）。两档的敏感性对比见 §x：0.85 额外引入 12 对候选，人工判读 0 对可直接合并。」
- **局限与答辩风险**：12/46 对的「可合并」为单人语义判读，非双人独立标注；样本仅 56 条，扩库后需重算；不得把 0.85 说成「系统阈值」。
- **证据出处**：`docs/paper/评测/_baseline_compare.json`（`dedup_similarity`）；`docs/paper/研究方向/数据与基线决策_v1.md` §5.4；DEVLOG 人工合并实测（MERGE 0.9385）。

### DEC-04 数据规模方案：知识点 54→310、评测集 100→250

- **决策结论**：知识点扩到 **310**（10 类设备 × 31 主题），评测集扩到 **250**（100 正例 + 150 负例四类）；先补内容结构再扩容。
- **备选方案**：①维持 54 条只用 100 评测；②纯合成一次性扩到 500+；③换行业拿外部数据。
- **决定性数据**：现有 56 条字段覆盖：现象 53/56、原因 50/56、步骤 53/56、预防 52/56、**验证/复测 1/56、适用条件 0/56**；平均 150.2 字（58–326）。评测集 100 条 = formal 54 / colloquial 16 / noisy 15 / missing 15。负例分层：N1 跨设备同象异因 40、N2 同设备同象异因 40、N3 知识未覆盖 40、N4 信息不足/多故障 30。
- **为什么不选另一边**：54 条撑不起「同象异因」的分层统计（每类不足 3 条无法报 CI）；纯合成会放大模板泄漏、答辩无法解释分布；换行业与 DEC-01 冲突。
- **论文建议表述**：「知识库由现有 54 条种子知识、56 条公开手册锚点、160 条受控合成与 40 条同象异因困难对构成，共 310 条；评测集 250 条，含 100 条正例与 150 条四类负例。」
- **局限与答辩风险**：**没有企业真实工单**，R/P 层也是种子/手册改写，禁止写「真实工单验证」；合成的具体构造与质检规则见配套文档，论文 Limitations 必须写模板泄漏与构造负例偏差。
- **证据出处**：`docs/paper/研究方向/数据与基线决策_v1.md` §1.3、§3。

### DEC-05 检索路由：保留 VECTOR 单路，不宣称加权/RRF 有增益

- **决策结论**：检索默认走 **VECTOR（topK=5）**；HYBRID 作为可用但非最优配置保留；论文明确写「设备加权与 RRF k 无显著增益」。
- **备选方案**：①HYBRID + 设备×1.5 + 标签×1.2 作生产默认；②KEYWORD（低延迟）；③调 RRF k（30/60/100）。
- **决定性数据**（M7 八轮，100 query，61 条知识）：KEYWORD Hit@3 **90.0%**、P95 16.4ms；VECTOR **100.0%**、P95 281.6ms；HYBRID（k=60 无加权）**96.0%**、P95 296.8ms；HYBRID + 设备×1.5 + 标签×1.2（生产配置）**96.0%**、P95 281.5ms；设备加权增量 **0.0pp**、标签加权 **0.0pp**；RRF k=30/60/100 均 **96.0%**，增量 **0.0pp**。最优组合 VECTOR topK=5：Hit@3 100%、P95 **279.7ms**。
- **为什么不选另一边**：HYBRID 比 VECTOR 低 4pp（关键词一路在语义歧义 query 上把正确条目挤出前 3）；加权与 RRF k 实测 0pp，写「调参提升」会被复现打脸。
- **论文建议表述**：「在本评测集上，纯向量检索（Hit@3 100.0%，P95 279.7ms）优于混合检索（96.0%）；设备/标签加权与 RRF k 的增量均为 0.0pp，故不作为默认配置。」
- **局限与答辩风险**：HYBRID 的 E3/E4/E6/E7 为离线复算，与真实接口前 3 集合一致率 94%（6/100 因同分并列差异）；不得把「离线复算」写成「接口实测」。
- **证据出处**：`docs/paper/评测/评测报告.md` §2–§3；`docs/paper/评测/消融结果.csv`。

### DEC-06 门控阈值：不抬全局阈值，改「间隔 + 根因一致性」

- **决策结论**：放弃「继续抬高全局余弦阈值」的路线；改用 **top1−top2 间隔 + 根因一致性校验**，并把论文论证轴从「Hit@3」切到「错误推送率 / 覆盖率」。
- **备选方案**：①0.75 门控上线；②抬到 0.80/0.85/0.92；③无门控全返回。
- **决定性数据**（300 条：100 正例 + 100 leave-gold-out + 四类负例各 25）：0.75 门控下混合等权错误推送率 **21.4%**（25/117），正例流 1.3%、负例流 60.0%；**无门控全返回时 61.7%**（185/300）。0.80 时错误率 **0%** 但正例覆盖仅 **31%**；0.85 覆盖 **1%**、0.92 覆盖 **0**。正例 top1 余弦：**median 0.786**、p25 0.756、max 0.852；leave-gold-out：median 0.695、p25 0.669、max 0.7885。间隔 ≥0.08 规则：leave-gold-out 误推 6→0、负例错误 18→6、正例覆盖仍 **47%**，错误率 **9.2%**。
- **为什么不选另一边**：分数分布决定了单阈值没有空间——0.85 已在正例分布最右端，抬阈值等于放弃覆盖；0.80 虽 0% 错误但只覆盖 31%，业务不可用。
- **论文建议表述**：「单阈值在 0.80 时可达 0% 错误推送，但正例覆盖仅 31%；0.75 门控的错误推送率为 21.4%。引入 top1−top2 间隔 ≥0.08 与根因一致性校验后，错误率降至 9.2%，覆盖率保持 47%。」
- **局限与答辩风险**：**0.75 从未上线**，只是反事实评估（`关键技术点.md` 明确「设计提出、代码未实现」）；今天现网是无门控全返回。不得写「现网 0.75 门控」。
- **证据出处**：`docs/paper/评测/阈值错误率评估.md` §1–§4；`docs/paper/评测/threshold_eval.csv`；commit `3af9213`。

### DEC-07 错误集中度：主战场是同象异因

- **决策结论**：问题三应用章节的改进重点锁定 **N2 同象异因**（同设备、现象相同、根因不同），而不是领域外或噪声。
- **备选方案**：①优先处理缺字段/噪声；②优先处理领域外；③靠提高阈值通吃。
- **决定性数据**：0.75 下 25 条错误推送的构成：**同象异因 11 条（44%）**、同因异象 7 条（28%）、leave-gold-out 6 条（24%）、正例 1 条（4%，且 top1 是库内同题重复而非语义跑偏）。分切片：同象异因 **11/25 推送且 100% 错误**；同因异象 7/25 且 100% 错误；领域外 **0/25**；缺字段/噪声 16/25 但 16 条全部命中原始 gold（**0 错误**）。
- **为什么不选另一边**：领域外已被向量检索天然挡住（0/25）；缺字段/噪声虽然推得多但推得对（0 错误），不是错误来源；只有同象异因是「推得出去且推错」。
- **论文建议表述**：「错误推送高度集中于同象异因样本（11/25，44%），该类样本推送后 100% 错误；领域外样本推送率为 0，缺字段/噪声样本虽有推送但 0 错误。因此三态决策的关键判别对象是同象异因。」
- **局限与答辩风险**：25 条错误的样本量小，44% 的比例 CI 很宽；负例是构造样本，分布不等于真实故障分布。
- **证据出处**：`docs/paper/评测/阈值错误率评估.md` §2–§3。

### DEC-08 问题二 GPU 方案：24GB 单卡 LoRA（已拍板）

- **决策结论**：**已拍板**：问题二（现行主线）采用 **Qwen-7B + LoRA 24GB 单卡**（16GB 为 QLoRA 下限），1000 条 × 3 epoch，总成本 **<¥20**。运行环境已确认可用：24G 4090、torch 2.8.0+cu128、算力 (8,9)、25 核 90G 内存。
- **备选方案**：①全参微调（80–112GB，需 A100 多卡）；②QLoRA 16GB；③纯 API few-shot 不微调。
- **决定性数据**：显存估算 LoRA fp16 16–24GB、QLoRA 4-bit 8–12GB、全参 80–112GB。价格：AutoDL 4090/3090 **¥1.88/h**；阿里云 A10 24G ¥10.18–11.78/h；腾讯云单卡 ¥6.15/h；RunPod 4090 $0.34–0.74/h、A100 80G $1.79/h。时长估算（max_len 1024、batch 1–2、grad accum 8）：4090 **2–4h**、A10 3–5h、A100 1–2h → AutoDL 总成本约 **¥7.5–10**。硬件实测口径见 `技术路线四步_v2_问题二.md` §2.1（24G/25 核/90G 内存）。
- **为什么不选另一边**：全参微调显存需求 ≥80GB，租 A100 多卡成本翻 10 倍且毕设无必要；纯 API few-shot 无法产出可交付的微调模型，答辩缺技术含量。选 24GB LoRA 是因为**本地/单卡可复现、成本 <¥20、且与问题二的 1000 条标注规模匹配**。

### DEC-09 检索/推送性能：并发扩容 + 超时分离

- **决策结论**：性能问题不靠加机器，靠 **消费并发 4-8→16-32** + **Milvus connect/rpc 超时分离（3s/1s）** + 检索失败 1s 快速失败。
- **备选方案**：①加节点/加副本；②延长超时；③降级关闭检索。
- **决定性数据**（200 样本）：端到端 P95 **4293ms → 507ms**（并发 1，降幅 **88.2%**）、**943ms**（并发 10，相对单并发 1.86×），P99 687/1212ms；分段均值「创建 373ms、消费→推送 361ms」定位消费瓶颈。Milvus 停机场景：改造前请求堆积 P95 4293ms，改造后 **P95 2538ms 且 50/50 全部降级成功**，恢复后无残留损坏通道。
- **为什么不选另一边**：单条消息处理是 I/O 等待型，加机器边际收益低；延长超时会让故障时堆积更严重（原 4293ms 正是「重建信道→超时→再重建」死循环）。
- **论文建议表述**：「通过消费并发扩容与 gRPC 连接/调用超时分离，端到端 P95 由 4293ms 降至 507ms（并发 1）/943ms（并发 10），并在 Milvus 停机时实现 50/50 全量降级。」

### DEC-14 标注方案：人工标注 → 构造真值（弱监督）+ 三层核验

- **决策结论**：**人工标注方案作废（2026-11-06）**。1000 条工单与 300 对关系集的真值在生成时即确定，存于 `_gold_draft.jsonl` / `_gold_relation_draft.jsonl`；验证改为三层：L1 程序化自洽核验、L2 独立模型盲评、L3 10 条生成器保真度抽检；另加 200 条跨模板留出集。统一口径为 **construction-based gold（弱监督）**，论文禁止出现「人工标注 / 专家标注 / 双人标注 / 标注者间 κ」。
- **备选方案**：①按原计划人工标注 1000 条（+ 第二人 κ）；②只标 200–300 条子集并做小样本 κ；③降低标准，只标根因一个字段；④构造真值 + 三层核验（现行）。
- **决定性事实**：①1000 条 × 每条 1–2 分钟 ≈ **17–33 小时**纯阅读，且「根因是否被证据确认」「条件属哪一类」需要领域判断，对非专业者是硬门槛；②用户实测标完 5 条后确认无法继续，属可执行性问题而非意愿问题；③第二读者同样需要领域判断，无可用人力，外行复核仅覆盖 2 个二值字段、性价比低；④真值本来就在生成脚本中确定，人工重标属重复劳动且引入新口径噪声。
- **为什么不选人工**：人工方案的关键路径不可压缩——做不完就没有数据，做完了也只有 2 个二值字段的 κ，仍拿不到全槽位一致性；而构造真值方案可复现、可扩展、成本 ¥0.1 量级，且验证点（自洽、可复现、跨模板）全部可程序化或可低成本完成。
- **论文建议表述**：「工单语料的五元组与排除假设在生成时由场景表确定，构成基于构造的真值（construction-based gold），属弱监督标签，未经人工标注；本文以程序化自洽检查、独立模型盲评与 10 条生成器保真度抽检对其质量进行核验，并以跨模板留出集检验模板依赖。」
- **局限与答辩风险**：①失去全槽位人工 κ；②失去真实语料外部效度（全部合成）；③失去「现象是否符合设备原理」的人工闸门；④失去争议条目的仲裁记录。以上四条必须写入 Limitations。
- **答辩应对话术（被问「ground truth 谁标的」）**：「真值不是标出来的，是构造出来的——生成工单时用同一张场景表同时确定现象、根因、措施、验证与条件，文本与真值物理隔离。所以这是 construction-based gold / 弱监督，不是人工标注。为证明它不自说自话，我们做了三层核验：程序化自洽检查五项 100%、与生成器无关的独立模型盲评、10 条保真度抽检；另用一套完全不同的模板生成 200 条留出集，检验模型学的是能力还是模板。代价是没有全槽位人工 κ、也没有真实语料外部效度，这两点已写进 Limitations。」
- **证据出处**：`docs/paper/问题二/标注方案变更说明.md`；`构造真值自检报告.md`；`盲评一致性报告.md`；`heldout_cross_template.csv`；`人工抽检_10条.md`；`scripts/annotation/{export_constructed_gold,verify_gold,blind_eval,gen_heldout_cross_template}.py`。

### DEC-21 外部验证（R2）取代数据替换（R1）

- **决策结论**：**不替换训练集**；把公开真实工单集只当**外部验证集（只测不训）**，用于证明方法可迁移性。
  R1（替换训练）已评估并否决。
- **备选方案**：①R1 用真实集替换 1000 条构造集；②R2 只测不训；③维持现状、不引用外部数据。
- **决定性依据（31 个平台逐条检索留痕，见 `外部数据集调研.md`）**：
  - 满足硬标准（有自然语言现象 + 措施或根因）且可自助下载的只有 3 个：**MaintNet 6,169 条**、
    **Fujitsu ManufacturingRCA 100 条**、**中文电梯工单 2,875 条**；
  - 规模/字段都不足以替代训练集（Fujitsu 仅 100 条）；电梯集无 LICENSE、`method/cause` 覆盖仅 17/16 条（200 抽样）；
  - 替换代价：作废 310 条 KB、100 条评测、M7 八轮消融、v1/v2 盲评与门控基线，重跑约 **13–20 人日**；
  - R2 代价：600 次调用、276,553 tokens、≈¥0.03，且**不动**任何既有资产。
- **R2 实测结果（S1 = glm-4-flash 零样本，temperature=0，同一 INSTRUCTION）**：
  JSON 合法率与字段齐全率 **均 100%**；现象语义一致率 MaintNet **89.3%** / Fujitsu **89.1%** / 电梯 **76.7%**；
  措施 F1 MaintNet **77.7%**；Fujitsu 根因一致率 **59.8%（n=100）**；电梯根因 n=16 不作结论。
- **S3 缺一列（如实记录）**：adapter **已训练**（4090D，1000×3 epoch）且在 200 条留出集上完成 S1/S2/S3 对比
  （`S3评测_heldout.md`），但外部集 600 条**未跑 S3**：本轮环境为 CPU 虚拟机（`nvidia-smi` 不存在、`lspci` 仅
  VMware SVGA、无 torch/transformers、adapter 权重未回传），补齐步骤见 `外部验证报告.md` §3.2。
- **不可得的指标**：排除假设误抽率、三关系判别、verification/conditions 一致率——外部集无对应标注，
  **已在报告 §4.4 与 §7 明确写「不可得」，不得用内部集数字冒充外部验证**。
- **答辩可说**：「在 MaintNet 300 / Fujitsu 100 / 中文电梯 200 条上做了只测不训的外部验证，
  现象语义一致率 76.7%–89.3%，Fujitsu 根因 59.8%（n=100）。」
- **答辩不可说**：❌「用真实工单训练」；❌「微调模型外部验证通过」（S3 未在外部集上跑）；
  ❌「根因 F1 59.8% 可生产使用」；❌「排除假设/三关系也在外部集验证」。
- **证据出处**：`docs/paper/问题二/外部验证报告.md`、`docs/paper/问题二/外部数据集调研.md`、
  `scripts/annotation/ext_eval.py`、`/tmp/ext-eval/*.jsonl`（哈希见报告 §1）。
