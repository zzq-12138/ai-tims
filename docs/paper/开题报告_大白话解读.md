## 一、整篇在讲什么（三句话）

1. **题目挂的是系统，正文研究的是一个转化问题**：把维修工单里的文字，变成能查、能判断条件成不成立、能放心推给师傅的"知识条目"。
2. **系统只是载体**：六微服务那套是把它跑起来的工程壳子，不是研究贡献本身。
3. **真正的难点不在"让大模型多说点"，而在"让它敢说不知道"**：证据不够时留空、留空之后还能查出依据，这才是全文反复绕回来的那根线。

下面按正文五段走。

## 二、研究现状及发展态势

### 原文关键句

> 总体态势是由"抽取更多字段"转向"抽取可追溯、可判定的知识单元"，由"固定阈值"转向"可迁移判据"。
> 本论文据此把重点放在抽取、表示、供给三层，而不是继续调整排序权重。

### 这段其实在说什么

这段是"占位"用的：告诉评审"这五摊子事，别人做到哪一步了，还差什么"。它按五个领域分块——信息抽取、维修领域、知识表示、去重与冲突、大模型——每块都是同一套写法：**先说谁做到了什么，再说它到这儿就停了**。

为什么非得这么写？因为开题报告得证明你的选题不是拍脑袋。评审想看的潜台词是："你说的这个缺口，是真缺口，还是你没读文献？"所以每块末尾那句"但……"，就是缺口所在。

最后那句"总体态势"是在收口：**不是要抽更多字段，而是要抽出来的东西能追溯、能判定**。这句一落，第 4、5 段的选题就顺理成章了。

### 名词逐个解释

| 词 | 人话 | 打个比方 |
|---|---|---|
| 微服务 | 把一个系统拆成若干能独立跑、独立改的小服务 | 不是一个大厨房，而是配菜、炒菜、装盘各一个档口 |
| 信息抽取 | 从自由文本里把结构化信息挑出来，填进固定栏目 | 从一段病历里挑出"症状、用药、剂量" |
| 实体 | 文本里值得单独拎出来的名词性东西，如设备型号、故障现象 | 一份名单上的"人名" |
| 关系 | 两个实体之间的连接，如"某现象 由 某部件 引起" | 名单上两人之间的"父子""同事" |
| BERT-BiLSTM-CRF | 三个部件串起来的经典抽取模型：BERT 读句子，BiLSTM 看上下文，CRF 保证标签序列合法 | 三个人接力：一个读懂意思，一个看前后文，一个负责不让答案出现"半截词" |
| 多任务学习 | 几个相关任务一起训，互相借力 | 一个人同时练跑步和游泳，心肺能力共享 |
| 联合建模 | 实体和关系不分两步，一起抽 | 不是先认人再查关系，而是边认人边连关系 |
| 文档级关系抽取 | 关系可能跨句子、跨段落才看得出来，得看整篇而不是一句 | 一句话里看不出两人是同事，得读完整封邮件 |
| 指代 | "它""该部件"这类代称，得知道指的是前面哪个东西 | 文章里说"该设备"，你得知道是哪台 |
| 知识图谱 | 用"点—边"存知识的图结构，点是实体，边是关系 | 一张巨大的关系网，不是一本书 |
| 工单挖掘 | 对工单做分类、聚类、相似召回这类分析 | 把一堆报修单按"像不像"归档 |
| 相似工单召回 | 给一条新工单，找出历史上像的那些 | 搜索框里的"猜你想找" |
| named graph（命名图） | 允许给一组三元组挂一个"名字/来源"，让知识带出处 | 给每条知识贴一张来源便签 |
| qualifier（限定词） | 给一条关系加附注，如"何时、何地、多大把握" | 便签上再写一行小字："2023 年、A 车间、八成确定" |
| 同象异因 | 症状一样，原因不同 | 都"打不着火"，一个没油、一个火花塞坏 |
| 近重复文本 | 意思几乎一样、只是写法略有差别的两段话 | "机器异响"和"设备有异响" |
| 加权 Jaccard | 比较两段文本"重合多少"的相似度算法 | 两筐水果按重量比有多少是重的 |
| MinHash | 一种快速估算集合相似度的近似算法，省时间 | 不逐一比对，先抽几个指纹快速判断像不像 |
| 文本蕴含 | 判断一句话是否在语义上"推出"另一句 | "设备停机"是否蕴含"设备不能用" |
| 跨文档知识冲突 | 两篇资料对同一件事说法不一致 | 一份说扭矩 5 牛米，另一份说 8 牛米 |
| 相似度阈值 | 相似度超过某个数就判为"同一条" | 及格线 |
| LoRA | 冻结大模型原参数，只训一小块"低秩"补丁，成本低 | 不改原著，只贴一本薄的批注本 |
| 低秩适配 | 就是 LoRA 那类"只加小补丁"的微调思路 | 同上 |
| 领域适配 | 让通用模型熟悉某个行业的说法 | 让通才去学行业黑话 |
| RAG（检索增强生成） | 回答前先去资料库检索，把查到的内容一起给模型看 | 开卷考试，先翻书再答题 |
| 外挂证据 | 不从模型记忆里答，而是从外部资料里找依据 | 同上 |
| 投毒 | 往资料库里塞坏数据，让模型学到错的东西 | 往参考书里偷偷改错一页 |
| 级联与路由 | 简单问题走小模型、难问题才走大模型，分层处理 | 分诊台：小病去社区，大病去三甲 |
| 可追溯 | 每条结论都能指回原文哪一句 | 引用要有页码 |
| 可判定 | 能明确判断"这条知识在这台设备、这个工况下成不成立" | 不是"大概能用"，而是"符合条件就能用" |
| 可迁移判据 | 在一批数据上定的判断标准，换一批还能用 | 不是给这场考试划的线，而是能通用的标准 |

### 这段的难点在哪

这段是全文最"挤"的一段：五块内容、每块两三句话，还要带十几个文献号。读起来像文献清单，但它的功能其实是**铺路**——每一块都要留一个"但是"，后面的第 3、4 段才有地方落。

## 三、选题依据及意义

### 原文关键句

> 研究上把抽取方法由"强制填满字段"改为"先判证据是否充分"；工程上把能力做成可开关、可回滚、可追查的服务。本论文较难的不是接入大模型，而是判断它何时不应作答。

### 这段其实在说什么

这段回答两个问题：**为什么值得做**、**拿什么数据做**。

"背景"讲的是现实痛点，落点是两个具体困难：同一故障十几种写法（说法不统一）、写下的处置不交代前提（换个工况就不成立）。这两个困难其实就是后面技术路线要打的两个靶子。

"数据"这段要特别注意语气：**它是在说明"为什么没有企业真实数据、那我们用什么替代"**。这一步必须写清楚，否则评审第一个问题就是"你的数据哪来的、真的假的"。

"意义"那句是全篇的题眼："较难的不是接入大模型，而是判断它何时不应作答。"——把研究重心从"能力"挪到"判断"，后面第 3、5 段全靠这句撑着。

### 名词逐个解释

| 词 | 人话 | 打个比方 |
|---|---|---|
| construction-based gold | 真值不是人一条条标的，而是"造数据时就已经知道答案"，是构造过程自带的 | 自己出题自己留答案，答案和题面分开放 |
| 弱监督 | 标签来源不那么"硬"，靠规则、模板、程序生成，不是专家逐条认定 | 用参考答案批卷，而不是请老师逐份手改 |
| 真值与文本分开存放 | 答案文件和题目文件物理隔离，防止"偷看答案" | 出卷人和阅卷人分房间 |
| 只测不训 | 外部数据只用来考试，不拿来训练 | 用没做过的卷子模拟考，不是把题背下来 |
| MaintNet / Fujitsu RCA / 中文电梯工单 | 三个公开的维修领域数据集，分别来自维护语言资源库、制造根因分析、电梯报修 | 借别人的真题来验自己的解法 |

### 补充一句

第 2 段里"由AI协助构造的1000 条工单"这句，是全文合规上最要紧的一处——它明确了数据是**构造的**，不是企业真实工单、也不是人工标注。这句不能省，省了性质就变了。

## 四、论文研究内容

### 原文关键句

> 围绕把"工单变知识"，本论文分五个方向，前三个为主体。

### 这段其实在说什么

这段是"我要做哪几件事"的清单，但它不是并列的：**前三个是研究，后两个是配套**。

- （1）抽取：解决"从文字里拿到什么、拿不到怎么办"。
- （2）表示：解决"拿到的知识怎么存，才能表达'在什么条件下成立'"。
- （3）供给：解决"什么时候该推、什么时候不该推"。
- （4）去重与冲突：解决"两条知识像但不一样，合还是不合"。
- （5）工程实现：解决"上面这些怎么装进系统里，还能关掉、能回滚"。

逻辑链条是：**先抽得出来 → 再存得住条件 → 才能判断该不该推**。前一步不做，后一步没法谈。这就是为什么（1）（2）（3）是主体，（4）更像（2）的补丁，（5）是承载。

注意这段**通篇是"拟"字辈**——"目标字段定为""评测拟定义""拟设 A、B、C 三档门控"。这不是躲，是开题报告该有的时态：**说计划，不说进度**。

### 名词逐个解释

| 词 | 人话 | 打个比方 |
|---|---|---|
| 五元组 | 一条维修知识固定拆成五个槽：现象、根因、措施、验证、适用条件 | 一张固定五栏的表格，缺栏就是没抽全 |
| 反向项 | 不只记"查出了什么"，还记"排除了什么""有没有定论" | 病历上不写"排除了肺炎"是不合格的 |
| 证据依赖切分 | 按"哪一步必须先有上一步的结论"来拆步骤，不是按字段顺序拆 | 先确诊再开药，不能反过来 |
| 逐环校验 / 未过即停 | 每一小步单独检查，不合格就停，不带着错往下走 | 流水线每道工序都有质检，不合格不流入下一道 |
| 根因一致率 | 抽出来的根因和标准答案对得上的比例 | 判对了几个"为什么坏" |
| F1 | 准确率和召回率的折中值，衡量"抽得准不准、全不全" | 既不能乱抽，也不能漏抽，两头都要看 |
| 结论回溯率 | 结论能定位回原文的比例 | 每句话都能翻到出处那一行 |
| 证据不足即留空 | 允许模型输出"不知道"，而不是硬编一个 | 医生可以说"需要再查一项" |
| 条件字段化 | 把"适用范围、型号、工况"这类前提，从正文里拎出来单独成列 | 药品说明书上的"适应症/禁忌"，不是散在正文里 |
| 同因异象 | 原因一样，表现不同 | 同一个轴承磨损，有的响、有的发热 |
| 门控 | 一道闸门，决定这条知识能不能推到人面前 | 检票口，票不对就不让进 |
| A、B、C 三档 | 按证据强度和条件匹配度分三档，档位不同处理不同 | 绿灯直接走、黄灯提示、红灯不放行 |
| 覆盖 | 有多少比例的提问能被知识库答上 | 命中率 |
| 错误推送 | 推了但推错了的比例 | 误报率 |
| 小库定参、大库迁移 | 先在少量数据上把参数定下来，再原样拿到完整数据上看还灵不灵 | 小样本试课，再上大班 |
| 六微服务 | 系统拆成六个可独立部署的服务 | 六个档口，各管一摊 |
| Milvus | 专门存"向量"的数据库，用于相似检索 | 按"意思像不像"来搜，而不是按关键字 |
| 向量 | 把一段文字的语义变成一串数字，方便算距离 | 给每句话定一个坐标，近的表示意思像 |
| 条件键 | 存条件字段用的索引键，便于按条件筛 | 抽屉上的标签 |
| 开关形式交付 / 可回滚 | 新能力默认不启用，出问题能一键退回原样 | 电闸，随时能拉 |

### 这段的难点在哪

（3）"A、B、C 三档门控"只说了分档，没说每档具体什么条件放行、什么条件拦。写开题报告时这不算硬伤（后面做的时候再定），但评审很可能会问一句"三档的界线怎么划"。

## 五、关键问题、技术路线、实施方案

### 原文关键句

> 有三个问题：证据不足时能否留空、事后能否查回依据；"同象异因"如何由"看着相似"转为"条件相符"；小库判据能否迁移至大库。

### 这段其实在说什么

这段是全文最"硬"的部分，干三件事：

1. **把问题收敛成三个问句**——注意三个都是"能不能"，是可以用实验回答的，不是"很重要的研究方向"这种空话。开题报告里，问题写成判断题比写成名词短语更有说服力。
2. **四步路线**：看趋势 → 比方案 → 设计实验 → 跑对比。第一步是"为什么这么选"，第二步是"为什么不选别的"，第三步是"怎么保证结论可信"，第四步是"跟谁比"。
3. **落地与风险**：系统怎么拆、工具链是什么、成本怎么算、最大的风险是什么。

第二步那段值得单独说：它列了 S1–S5 五个候选，每个都写"是什么 + 好在哪 + 差在哪"，然后一句"五者均难答'证据不足怎么办'"把前四个都否定掉。这一句是全段的转折——**不是选最好的那个，而是选唯一能回答关键问题的那个**。S3（LoRA 微调）效果可能最好，但只能当"上界"参考；S2（规则）能力有限，但稳、可审计，所以当"兜底"。主线走两者之外的可降级链式路线。

第四步的 B1–B5 是基线对比：**现网、NER 加规则、大模型直调、纯阈值、本方案**，同数据同脚本同口径，再加一组"去掉条件字段"的对照。有对照，才能说清"是这套方法管用，还是数据本身简单"。

### 名词逐个解释

| 词 | 人话 | 打个比方 |
|---|---|---|
| 零样本 | 不训练、不举例，直接给模型任务让它做 | 没培训就上岗 |
| 提示模板 | 把提问方式固定成一套句式，减少模型自由发挥 | 给一张答题卡，而不是空白纸 |
| 禁编造后处理 | 生成完再用规则查一遍，明显没依据的内容剔掉 | 交卷前先自查一遍 |
| 不占 GPU | 不用显卡算力，纯 CPU 或纯规则就能跑 | 不用大灶，电磁炉也能做 |
| 序列标注 | 给每个字/词打标签，再拼成字段，是传统 NER 路线 | 逐字圈重点，最后连成句 |
| NER | 命名实体识别，就是"把实体圈出来"这件事 | 划重点 |
| 逐槽位标注 | 每个字段都要有对应的标注数据，标注成本高 | 每一栏都得有人手填标准答案 |
| 上界 | 拿它当"最好大概能到哪"的参照，不当最终方案 | 天花板，用来量自己离顶有多远 |
| 兜底 | 主路线失效时还能顶上的一套保底方案 | 备用电源 |
| 可降级 | 条件不够时能退到更简单但可用的处理方式 | 网速差就降清晰度，但不卡死 |
| 可回溯 | 输出的每条结论都能翻回原文证据 | 结论后面挂着出处链接 |
| 链式路线 | 按步骤一环扣一环地做，而不是一步到位 | 流水线，不是手工作坊 |
| 跨域退化 | 换个领域/数据分布，效果明显掉下来 | 在本地考得好，换套卷子就不行 |
| B1—B5 | 五组对照基线，用来量"本方案比它们好多少" | 五个陪练 |
| 三层核验 | 程序自检、独立模型盲评、抽检保真，三道关 | 三重复核 |
| 冻结口径 | 先把评测规则、指标定死，再跑实验，防止事后改标准 | 先定规则再开赛 |
| 留出集（held-out） | 留一部分数据完全不参与调参，只在最后考一次 | 押题卷之外的真题 |
| 不重叠 | 训练、调参、测试用的数据不能交叉 | 考过的题不能当模拟题 |
| Bootstrap | 反复重采样估算结果的波动范围，给出区间而非单点 | 多抽几次样，看答案稳不稳 |
| McNemar | 比较两个方法在同一批样本上谁对谁错的配对检验 | 同一个班两次考试，逐人比进步 |
| 对照实验（去条件） | 故意去掉某个设计，看效果掉多少，以此证明它必要 | 拆掉一个零件看机器还转不转 |
| 路由与缓存 | 简单请求走便宜的，重复请求直接复用上次结果 | 分诊 + 备忘录 |
| 语义缓存 | 按"意思相同"命中缓存，而不是按字面完全相同 | 换个说法问同一件事也能命中 |

### 这段的难点在哪

（1）里的"三个问题"其实和（4）里的"三个问题"是同一组，只是（4）更具体。写的时候容易让人觉得重复，但作用不同：第 3 段是"要做什么"，第 4 段是"卡在哪、怎么解"。

## 六、特色与创新

### 原文关键句

> （3）判据迁移是可证伪命题：小库定参、大库复核，看能否沿用，阈值便由经验值转为假设。
> （4）条件字段是知识可用的前提，非可选项，以去条件对照实验检验必要性。

### 这段其实在说什么

四条创新，其实是三种"新"：

- （1）（2）是**做法上的新**：把"证据不足"当成一种合法输出；把"适用条件"从正文里拎出来变成字段。
- （3）是**论证方式上的新**：不承诺"我的阈值一定好"，而是说"这个判断标准能不能迁移，是可以被证伪的"。这是把工程经验变成一个科学问题。
- （4）是**边界命题**：不说"我做得更好"，而说"少了这个字段，这类判断根本做不了"，并且用去条件对照来证明。

第（4）条其实是最"敢"的一条：它赌的是"条件字段不是加分项，是入场券"。赌错的风险也有，所以配了对照实验。

最后那句"AI 应用层四项按应用处理，不计入创新点"，是主动划界——**把工程包装和学术贡献分开**，这比把什么都算创新更容易过评审。

那段"闭环未做，仅作设想"也是同一个思路：明确写"这条路需要真实用户连续使用、工单关闭必须回填、至少一个季度的复发观测，本课题不具备这三个前提"。**写清没做什么，比假装做了更可信。**

### 名词逐个解释

| 词 | 人话 | 打个比方 |
|---|---|---|
| 可证伪 | 一个说法必须能被设计出实验来反驳，否则不算科学命题 | "努力就会成功"没法证伪；"这批数据上阈值 0.8 更好"能证伪 |
| 判据 | 判断用的标准 | 尺子上的刻度 |
| 阈值 | 判据里的那个临界数 | 及格线 |
| 经验值 | 凭经验拍出来的数，没经过系统验证 | 老师傅的"手感" |
| 假设 | 可以被检验对错的说法 | 待验证的猜想 |
| 去条件对照 | 把条件字段整个拿掉，再跑一遍，看结果掉多少 | 拆掉安全带再撞一次，看它到底有没有用 |
| 必要条件 / 前提 | 没有它就不成立 | 入场券，不是加分项 |
| 输出护栏 | 在输出外面加一层过滤，挡住明显不该说的话 | 出口的安检门 |
| 模型路由 | 按问题难易把请求分给不同大小的模型 | 分诊台 |
| 可观测性 | 系统内部发生了什么能被看到、能查日志 | 仪表盘 + 行车记录仪 |
| 复发 | 同一个故障过一段时间又出现 | 治好了又犯 |

## 七、17 条文献逐条交代

写作顺序按正文编号，每条都回答三件事：**它做了什么 / 本文引它说明什么 / 不引会怎样**。

**[1] 陈鹏等（2023，电网技术）：用 BERT-BiLSTM-CRF 抽电力设备缺陷文本里的实体**
- 做了什么：把"读句子的 BERT + 看上下文的 BiLSTM + 保证标签合法的 CRF"这套组合，用在中文电力设备缺陷文本上做实体抽取。
- 本文拿它说明：领域文本做实体抽取，这套组合是**常用基线**。
- 换成不引：只能空口说"这是常规做法"，没有中文工业领域的实证支撑。评审一问"依据呢"，答不上来。

**[2] 纪鑫等（2024，北京航空航天大学学报）：多任务学习做电力文本信息抽取**
- 做了什么：让几个相关的抽取任务一起训练，共享底层表示，互相借力。
- 本文拿它说明：**多任务学习可以实现联合建模**。
- 换成不引："联合建模"这个词就落不到具体工作上，成了口号。

**[3] 谢国波等（2025，广东工业大学学报）：ET-FSUIE 关系抽取模型，服务于变压器缺陷知识图谱构建**
- 做了什么：提出一个把实体和关系一起抽的模型，目标是直接喂给知识图谱。
- 本文拿它说明：实体与关系可以**在模型层面联合抽取**（[2] 是任务层面，[3] 是模型层面，两条合起来才撑住"联合建模"这个判断）。
- 换成不引：只有任务层面的证据，没有模型层面的例子，说服力不够。

**[4] YAO 等（2019，ACL）：DocRED，大规模文档级关系抽取数据集**
- 做了什么：把关系抽取从"一句话内"推到"一整篇文档"，并给出大规模标注数据。
- 本文拿它说明：**跨句、多实体**的场景是真实存在且必须处理的。
- 换成不引："句子级抽取不够用"这个判断就缺一个公认的数据集做锚点。

**[5] ZHONG 与 CHEN（2021，NAACL）：PURE，两段式抽取流水线**
- 做了什么：先识别实体、再抽关系，两步分开做，结构简单但效果很强。
- 本文拿它说明：**分步做是有效路线**，同时说明跨句场景必须显式建模证据与指代。
- 换成不引：本文"把一次生成拆成三步"的做法就缺一个方法学先例——评委会问"为什么不一次抽完"。

**[6] 蒲昊苒等（2025，机械科学与技术）：维修知识图谱 + 深度学习做发动机故障推理**
- 做了什么：把维修知识组织成图谱，再结合深度学习做故障推理。
- 本文拿它说明：**维修领域已有用知识图谱做推理的先例**。
- 换成不引：选题的领域合理性缺一个直接例证，容易被认为是硬套通用方法。

**[7] 洪睿洁等（2025，电力与能源）：BERT-TextCNN 做工单挖掘**
- 做了什么：用文本分类模型对工单做挖掘（归类）。
- 本文拿它说明：工单侧的工作**多停留在分类与相似工单召回**，没有走到知识化。
- 换成不引：就没法说明"工单 → 知识"这一段是缺口。这条是"缺口"论证的落点，不能删。

**[8] HOGAN 等（2022，ACM Computing Surveys）：知识图谱综述**
- 做了什么：系统梳理知识图谱的概念、表示、查询与生态。
- 本文拿它说明：知识表示的**整体框架**有公认说法。
- 换成不引：谈"知识表示"就没有权威入口，显得只读过零散论文。

**[9] CARROLL 等（2005，Journal of Web Semantics）：named graph 原始论文**
- 做了什么：提出"给一组三元组挂一个名字/来源"的表示方式。

- 换成不引：就只能说"业界没考虑条件"，而这个说法是不准确的——表示层早有方案，问题在工程落地。

**[10] ZHANG 等（2026，PVLDB）：加权 Jaccard 下的近重复文本对齐**

- 换成不引："相似度方法有一定用"这句就变成印象之谈；也拿不到"近重复"这个具体问题的技术基线。

**[11] XU 等（2024，EMNLP）：大模型知识冲突综述**
- 做了什么：把"模型内部知识与外部证据冲突"这件事系统梳理成体系。
- 本文拿它说明：冲突研究**已从文本蕴含扩展到跨文档知识冲突**。
- 换成不引：本文把冲突分成"事实冲突/条件冲突"就没有学术脉络，像是自己发明的分类。

**[12] HU 等（2022，ICLR）：LoRA，低秩适配**
- 做了什么：冻结原模型参数，只训练一小块低秩补丁，用很小成本完成领域适配。

## 八、我觉得还能再改顺的句子

只给建议，不动原文。

1. **第 2 段"在背景方面"那句**："企业积累多年工单，有大量设备需要维修，为简化维修流程，降低误判和维修成本，在以上前提下，大量有机会有希望可以转为可查、可推的维保知识……"——三个"有"、两个"大量"、一个"在以上前提下"，读起来喘不上气。原本想说的大概是：**工单攒了很多，但没变成能查的知识；如果能转，就能少误判、少返工。** 建议拆成两句。

2. **第 3 段（3）"A、B、C 三档门控"**：只说了分三档，没说界线。原本想说"按证据强度和条件匹配度分档"，但这两者怎么合成一个档位没交代。建议补半句"以证据是否齐全、条件是否匹配各占一个维度"，否则评审一定会追问。

3. **第 4 段"五者均难答'证据不足怎么办'"**：这句是整段的转折，但"五者"指代要靠读者自己数回去（S1–S5）。建议改成"这五条路都答不了同一个问题：证据不足时该怎么办"，读起来更顺。

4. **第 3 段（2）"确定度"**：五类条件里"确定度"和其他四类不同质——前四个是事实属性，它是把握程度。原本想说的可能是"这条知识的可信程度"。建议要么改名叫"可信度"，要么在括号里点一句。

5. **第 5 段末尾"闭环未做，仅作设想"**：内容没问题，但"闭环"这个词在正文里第一次出现就是在这里，前面没交代过什么叫闭环。建议前面加半句，或改成"把这条链路接成闭环（建议 → 回填 → 入库）这件事没做，仅作设想"。

## 九、解读时觉得原文没讲透的地方

不是错，是"读者会卡住"的点，供你答辩时预备：

1. **A、B、C 三档门控的具体界线**——正文只说"按证据强度与条件匹配度分层放行"，两层怎么合成一档没写。
2. **"确定度"字段的定义**——五类条件里唯一非事实型字段。
3. **"三层核验"的第三层"保真抽检"**——抽多少、谁抽、抽检不合格怎么处理，正文没展开。
4. **"去条件对照"具体去掉哪些字段**——是只去"适用条件"，还是五类条件全去，会影响结论强度。
5. **小库到大库的"迁移"是原样搬还是重新拟合**——正文说"原样迁移"，但没说明如果大库分布不同怎么办。

以上五点在开题阶段可以不写死，但答辩时最好能各答一句。
