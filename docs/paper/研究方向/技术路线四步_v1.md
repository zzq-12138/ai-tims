# 技术路线四步 v1（问题三主线）

- 日期：2026-11-05
- 主线：问题三「检索-生成分流的三态决策（A 直接推送 / B 仅供参考 + 后台预生成 / C 弃权转慢通道）」
- 与 [`数据与基线决策_v1.md`](file:///g:/JAVA/Code/ai-tims/docs/paper/研究方向/数据与基线决策_v1.md) 保持一致：论文检索基线 BGE-M3、现网 embedding-3；去重论文基线 0.85、系统 0.92 + 人工确认；评测集 250（100 正 + 150 负四类）。
- 说明：文献的卷期/页码未逐条核对，统一标「待核对卷期」；正式开题前用 Google Scholar/DBLP 补齐。本文不编造任何实验结果，所有指标位置留给实验填数。

## 一页结论

1. **趋势上，问题三不是「RAG 应用」，而是「带风险约束的选择性决策」**：检索只提供证据，真正决定 A/B/C 的是「证据是否足够 + 答错的代价是否可接受」。因此技术路线必须把 selective prediction、calibration、cost-sensitive decision、conformal risk control 四条线并起来，而不是只调相似度阈值。
2. **选型上，主方案是「多信号分类器 + 概率校准 + 代价阈值 + conformal 风险控制」**：硬编码阈值只做基线；单信号校准做消融；LLM 自反思只做上界与离线标注器。卖点是「用可证明的风险上界，把错误推送率压到业务可接受区间，同时尽量少弃权」。
3. **实验上，用 250 条分层评测 + 分层 5 折 × 3 seed + 锁定 holdout + leave-gold-out**，主指标是错误推送率、A 档准确率、C 档触发率，显著性用 McNemar + bootstrap 95% CI，代价矩阵做区间扫描而不是拍一个数。
4. **对比上，必须打过五类对象**：现网余弦阈值 0.75/0.85/0.92、单信号无校准 LR、CRAG 式 LLM 三态、LlamaIndex/LangChain 默认相似度阈值、LLM-as-judge 上界。结果用「分层错误推送率柱状图 + risk-coverage 曲线 + 可靠性图」三件套呈现。
5. **量化口径模板**：A 档准确率从基线 X% 提升到 ≥90%，错误推送率从 Y% 降到 ≤3%，均附 95% CI 与 McNemar 结论；达不到就报实际值并写限制，不改写为达标。

## 第 1 节 技术发展趋势分析

> 写法：每条按「脉络是什么 → 代表工作 → 对应我们哪个环节 → 因此我们做什么 → 可引用点 → 我们的差异点」组织。代表工作的作者/年份/出处已给，卷期标「待核对卷期」。

### 1.1 脉络一：RAG 从「检索增强」走向「检索-判别-弃权」

- **脉络**：早期 RAG 默认「检索到就生成」；2023 年后出现两类修正：①生成前判断「要不要检索/检索够不够」（Adaptive-RAG、Self-RAG）；②生成后判断「检索对不对/要不要纠正」（CRAG）。共同点是把「检索」从固定步骤变成可决策动作，但多数工作仍是「生成质量」导向，不是「错误推送代价」导向。
- **代表工作**：
  - Gao Y. et al., 2023, *Retrieval-Augmented Generation for Large Language Models: A Survey*, arXiv:2312.10997（待核对卷期）。
  - Asai A. et al., 2023/2024, *Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection*, ICLR 2024 / arXiv:2310.11511（待核对卷期）。
  - Yan S.-Q. et al., 2024, *Corrective Retrieval Augmented Generation (CRAG)*, arXiv:2401.15884（待核对卷期）。
  - Jeong S. et al., 2024, *Adaptive-RAG: Learning to Adapt Retrieval-Augmented Large Language Models through Question Complexity*, NAACL 2024 / arXiv:2403.14403（待核对卷期）。
- **对应环节**：我们的「检索 → 三态路由」环节；特别是 C 档（弃权）与 B 档（参考但不确定）。
- **因此我们做什么**：把 CRAG 的「检索质量判别」降成一个**可校准的检索充分性信号**（top1 相似度、top1-top2 margin、证据覆盖、设备/工艺匹配），但不让 LLM 在线自反思决定 A/B/C；LLM 只用于离线造标签与上界对照。
- **可引用点**：「RAG 系统需要显式的检索质量判别与纠正机制」；「Self-RAG 用反思 token 决定是否检索/是否支持生成」；「CRAG 用轻量检索评估器触发纠正」。
- **我们的差异点**：上述工作优化生成事实性，我们优化**错误推送率 + 弃权率的业务权衡**；我们给出的是三态（A/B/C）而不是二态（答/不答），并把 B 档定义为「给参考 + 后台预生成」而不是「直接答」。

### 1.2 脉络二：选择性预测与拒识理论（risk-coverage）

- **脉络**：分类器可以「拒识」而不是强行预测；最优拒识阈值由后验概率与代价决定（Chow 1970）；深度模型上出现 SelectiveNet（把拒识头写进网络）、选择性分类的 risk-coverage 分析。核心量是「覆盖率（coverage）」与「选中样本上的风险」之间的权衡。
- **代表工作**：
  - Chow C.K., 1970, *On Optimum Recognition Error and Reject Tradeoff*, IEEE Transactions on Information Theory, 16(1):41–46（待核对卷期）。
  - El-Yaniv R. et al., 2010, *On the Foundations of Noise-free Selective Classification*, JMLR 11:1605–1641（待核对卷期）。
  - Geifman Y., El-Yaniv R., 2017, *Selective Classification for Deep Neural Networks*, NeurIPS 2017（待核对卷期）。
  - Geifman Y., El-Yaniv R., 2019, *SelectiveNet: A Deep Neural Network with an Integrated Reject Option*, ICML 2019（待核对卷期）。
- **对应环节**：A 档（自动推送）与 C 档（弃权）的边界；B 档是「低风险覆盖」的中间层。
- **因此我们做什么**：把三态写成「两个阈值切三段」：高置信 → A；中间 → B；低置信 → C。阈值不由人拍，由代价矩阵 + 校准后的概率/风险上界决定；用 risk-coverage 曲线选工作点。
- **可引用点**：「拒识可以降低选中样本的风险，但会牺牲覆盖率」；「选择性分类的性能应用 risk-coverage 曲线而不是单一 accuracy 评价」。
- **我们的差异点**：经典选择性预测是二态（预测/拒识），我们是三态，且 B 档不是「拒识」而是「低成本人工兜底」；我们把 B 档的预生成成本也算进代价矩阵。

### 1.3 脉络三：置信度校准（从分数到概率）

- **脉络**：模型输出的 similarity / logit / softmax 不是概率；Platt scaling、isotonic regression、temperature scaling 把分数校准成可信概率；评价用 ECE / Brier / NLL。校准是「代价阈值」和「conformal」的前提。
- **代表工作**：
  - Platt J., 1999, *Probabilistic Outputs for Support Vector Machines and Comparisons to Regularized Likelihood Methods*, in Advances in Large Margin Classifiers, MIT Press（待核对卷期）。
  - Zadrozny B., Elkan C., 2002, *Transforming Classifier Scores into Accurate Multiclass Probability Estimates*, KDD 2002（待核对卷期）。
  - Naeini M.P. et al., 2015, *Obtaining Well Calibrated Probabilities Using Bayesian Binning*, AAAI 2015（ECE 的代表性提出/普及，待核对卷期）。
  - Guo C. et al., 2017, *On Calibration of Modern Neural Networks*, ICML 2017（temperature scaling + ECE，待核对卷期）。
- **对应环节**：把「余弦相似度 0.78」变成「这条知识正确的概率是 0.62」；三态阈值的输入。
- **因此我们做什么**：主方案用**多信号 → 概率 → 校准 → 代价阈值**；校准器在验证折上拟合，测试折只用；同时报可靠性图与 ECE。不要直接用原始 cosine 当概率。
- **可引用点**：「现代模型的置信度普遍过度自信，需要 post-hoc calibration」；「temperature scaling 在保持 accuracy 的同时显著降低 ECE」。
- **我们的差异点**：我们校准的不是单模型分类概率，而是**检索证据 + query 完整度 + 设备匹配**融合后的三态概率；并检验校准对「错误推送率」而非仅对 ECE 的影响。

### 1.4 脉络四：代价敏感决策与级联推理

- **脉络**：不同错误的代价不同，最优决策不是 argmax 概率，而是 argmin 期望代价（Elkan 2001）；LLM 场景出现「便宜模型先上、不确定再升级」的级联（FrugalGPT、RouteLLM），把成本与质量一起优化。
- **代表工作**：
  - Elkan C., 2001, *The Foundations of Cost-Sensitive Learning*, IJCAI 2001（待核对卷期）。
  - Chen L., Zaharia M., Zou J., 2023, *FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance*, arXiv:2305.05176（待核对卷期）。
  - Ong I. et al., 2024, *RouteLLM: Learning to Route LLMs with Preference Data*, ICLR 2025 / arXiv:2406.18665（待核对卷期）。
- **对应环节**：A/B/C 三态本质是「快通道 / 人工兜底 / 慢通道」的级联；B 档的后台预生成就是「便宜先跑、慢通道再补」。
- **因此我们做什么**：用代价矩阵定义三态：`E[cost(A)] = p_wrong * c_FN + c_A`，`E[cost(B)] = c_B + p_wrong_after_B * c_FN`，`E[cost(C)] = c_C`；取期望代价最小。代价矩阵不给死值，做区间扫描（见第 3 节）。
- **可引用点**：「代价敏感学习把决策阈值从 0.5 移开，移到代价比决定的位置」；「级联/路由可以在不显著损失质量的前提下降低平均成本」。
- **我们的差异点**：RouteLLM 是「强弱模型二选一」，我们是「直接推送 / 人工参考+预生成 / 弃权转慢通道」三态，且 B 档有后台预生成成本；我们把「错误推送的业务代价」显式写进矩阵。

### 1.5 脉络五：无分布假设的风险控制（conformal）

- **脉络**：split conformal 用留出集校准，给预测集/预测区间的覆盖率保证；conformal risk control（CRC）把「覆盖率」推广到任意有界损失（如错误推送率），在有限样本下给期望风险上界。
- **代表工作**：
  - Papadopoulos H. et al., 2002, *Inductive Confidence Machines for Regression*, ECML 2002（待核对卷期）。
  - Lei J. et al., 2018, *Distribution-Free Predictive Inference for Regression*, JASA 113(523):1094–1111（待核对卷期）。
  - Angelopoulos A.N., Bates S., 2021, *A Gentle Introduction to Conformal Prediction and Distribution-Free Uncertainty Quantification*, arXiv:2107.07511（待核对卷期）。
  - Angelopoulos A.N. et al., 2024, *Conformal Risk Control*, ICLR 2024 / arXiv:2208.02814（待核对卷期）。
- **对应环节**：给「错误推送率 ≤ 3%」一个**有限样本、无分布假设**的保证；不是拍阈值，而是校准一个风险上界。
- **因此我们做什么**：主方案 C3 之上加一层 CRC：用校准集选 A 档阈值，使 `E[1{wrong push}] ≤ α`（α=3% 或业务给定），并报告实际覆盖率/弃权率；与经验阈值对比，验证「风险控制是否真的更稳」。
- **可引用点**：「split conformal 只需可交换性假设，不依赖模型/分布」；「CRC 可把任意有界损失（含错误率）控制在目标水平」。
- **我们的差异点**：把 CRC 用在**三态路由的错误推送率**上，而不是回归区间/分类集；并处理「B 档部分正确」这种非 0/1 损失的边界（B 档不计入 A 的错误推送，但要单独报 B 档二次错误率）。

### 1.6 脉络六（辅助）：LLM-as-judge 与自反思的边界

- **脉络**：用 LLM 判断「检索是否支持答案 / 答案是否可靠」；MT-Bench/Chatbot Arena 系统化了 LLM-as-judge 的用法，但也暴露位置偏好、冗长偏好、自我偏好等偏差。
- **代表工作**：Zheng L. et al., 2023, *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena*, NeurIPS 2023 Datasets and Benchmarks（待核对卷期）。
- **对应环节**：离线造标签、上界对照、错误案例分析；不作为在线 A/B/C 决策器。
- **因此我们做什么**：LLM-as-judge 只做两件事：①离线给 1000 条种子打弱标签（再人工复核）；②作为「上界」对照，证明我们的轻量方案离上界有多远。在线不用，原因是延迟 2–5 s、成本高、且 judge 本身有偏差。
- **可引用点**：「LLM-as-judge 与人类偏好有较高一致性，但存在系统性偏差」。
- **我们的差异点**：我们把 judge 当「上界/标注工具」，而不是「生产决策器」；生产决策器必须可校准、可复现、低延迟。

## 第 2 节 方案选型

### 2.1 候选方案对比

| # | 方案 | 做法 | 延迟（单 query，不含 LLM） | 成本 | 预期效果 | 风险 | 是否采用 |
|---|---|---|---|---:|---|---|---|
| C1 | 硬编码余弦阈值 | 用 top1 cosine 切三档：≥0.92 A，0.75–0.92 B，<0.75 C（现网 0.75/0.85/0.92 三档对照） | <1 ms | 0 | 基线；实现最简单 | 阈值随数据漂移；同象异因时 cosine 仍高，假 A；无法给风险保证 | 仅作基线，不作最终 |
| C2 | 单信号校准 + 代价阈值 | 只用 top1 cosine → Platt/isotonic 校准 → 按代价比切 A/B/C | <1 ms | 极低 | 比 C1 稳，ECE 明显下降 | 单信号欠拟合：同象异因、缺字段、跨设备都看不出来 | 作消融，不作最终 |
| C3 | **多信号分类器 + 校准 + 代价阈值** | 特征：top1 sim、top1-top2 margin、检索熵、证据覆盖、设备匹配、query 完整度、关键词重叠、抽取置信度；LR/GBDT → 三态概率 → 校准 → 代价阈值 | 1–5 ms | 低（模型 KB 级） | **主方案**；预期错误推送率最低、覆盖率可调 | 特征工程与标注成本；小样本过拟合；需跨设备泛化验证 | **采用（主）** |
| C4 | C3 + conformal risk control | 在 C3 概率上，用校准集选 A 档阈值，使错误推送率 ≤ α；B/C 用代价阈值 | 1–5 ms + 一次查表 | 低 | 给有限样本风险上界；答辩时最硬 | 需要独立校准集；样本少时上界保守、弃权多 | **采用（安全层/可选模式）** |
| C5 | LLM 自反思 / CRAG 式三态判别 | 让 LLM 看 query + top-k 证据，输出 A/B/C + 理由 | 2–5 s | 高（token） | 上界；语义判断最强 | 延迟/成本高；judge 偏差；不可复现；不适合在线 | 仅作上界/离线标注 |

补充对照（不作为候选主方案，但必须出现在实验里）：
- **现网配置**：余弦 0.75/0.85/0.92 三档（C1 的工程版）。
- **LlamaIndex/LangChain 默认做法**：`similarity_top_k` + `similarity_cutoff`（常见 0.7–0.8），本质是 C1 的库默认版。
- **单信号无校准 LR**：只用 top1 sim 的 LR，不校准，直接 0.5 切；用来证明「校准」不是摆设。

### 2.2 选型结论

**主方案 C3，安全层 C4，上界 C5，基线 C1/C2。**

一句话卖点：**「用多信号把『检索像不像』变成『答错代价可不可接受』，再用校准 + conformal 给错误推送率一个可解释的上界；在同样覆盖率下，错误推送率比硬阈值低一个量级。」**

### 2.3 为什么不选其他

- **不选 C1 作为最终**：它把「相似度」当「正确概率」，同象异因时 top1 仍可能很高（本次实测 12 对 0.85–0.92 的困难对就是证据），会假 A；且阈值随知识库扩容漂移，答辩无法回答「为什么是 0.92」。
- **不选 C2 作为最终**：单信号校准只能修「分数尺度」，修不了「信号缺失」；N1/N4 类（跨设备、缺字段）需要设备匹配与完整度特征。
- **不选 C5 作为在线**：2–5 s 延迟与 token 成本不可接受；且 judge 有位置/冗长偏差，不能作为生产决策器。它的价值是上界和离线标签。
- **C4 不作为唯一主方案**：conformal 需要独立校准集，250 条规模下上界偏保守，可能弃权过多；因此 C4 作为「风险控制模式」与 C3 并列报告，由业务选工作点。

## 第 3 节 实验设计

### 3.1 数据分层与规模

| 层 | 数量 | 用途 | 来源 |
|---|---:|---|---|
| 正例 A 档 | 100 | 测 A 档准确率/覆盖率 | 现有 `eval_set.csv` 100 条（formal 54 / colloquial 16 / noisy 15 / missing 15），逐条补 `gold_route=A` |
| 负例 N1 跨设备同象异因 | 40 | 测「设备不明确/错设备」是否弃权 | 10 类设备同名现象去除设备词/替换设备 |
| 负例 N2 同设备同象异因 | 40 | 测 B 档是否触发、A 档是否误推 | H 层 20 组同象异因对 + 可观测区分线索 |
| 负例 N3 知识未覆盖 | 40 | 测 C 档弃权 | 设备手册/FAQ 中 KB 未收录的故障；新型号/新工艺 |
| 负例 N4 信息不足/多故障 | 30 | 测 C/B 档 | 模板删字段；两个故障拼接 |
| **评测合计** | **250** | 主实验 | 双人 100% 标注 + 第三人仲裁 |
| 训练辅助（可选） | 500 | C3 分类器训练/调参 | 同分布构造、独立 seed、与 250 评测不重叠；若不用则 5 折 CV |

分层：按设备 10 类 × 负例 4 类交叉分层，保证每个「设备 × 负例类型」至少 3 条；正例按 4 种 query 风格分层。

### 3.2 标注与一致性检验

- **校准集**：先标 20 条（每类 4 条），三人对齐口径；不计入 κ。
- **评测集**：标注者 A、B 对 250 条 100% 独立标注 `gold_route`、`gold_support_ids`、`negative_type`、`reason`；不一致由 C 仲裁。
- **训练集**：A 100% 复核 LLM 种子标签；B 抽检 20%（分层 200 条）；不一致仲裁。
- **一致性指标**：Cohen's κ（route 三分类、negative_type 四分类）；目标 route κ ≥ 0.70、negative_type κ ≥ 0.65；另报每类 F1。低于阈值就重写标注指南，不硬堆数据。
- **一致性抽检**：30 条锚点题，同一模型 3 次独立生成 + 2 人复核，一致率 <90% 的条目剔除。

### 3.3 实验协议

1. **分层 5 折交叉验证**：按「设备 × 负例类型」分层，保证每折分布一致；重复 3 个 seed（42/2026/7），报告均值 ± 标准差。
2. **锁定 holdout**：从 250 中留出 20%（50 条，分层），全程不参与调参/校准，只在最后评估一次，防止「调参泄漏」。
3. **leave-gold-out**：对每个正例，把其 `expectedIds` 对应的知识从索引中移除，再跑一次；检验系统是否从「A 直接推」降为「B/C」——这是问题三最关键的反事实实验，能证明系统不是靠「标题词面匹配」。
4. **跨设备泛化**：留一设备（leave-one-device-out）：每次移除一类设备的知识与样本，测其余设备；检验特征是否过拟合到某类设备。
5. **校准协议**：校准器（Platt/isotonic/temperature）只在训练折拟合，测试折只用；conformal 的校准集与测试集严格分离。

### 3.4 指标口径

**主指标（答辩必须报）**：

| 指标 | 定义 | 目标 |
|---|---|---:|
| 错误推送率（Wrong-Push Rate） | A 档中被判为「不应 A」的比例 = FP_A / 所有 A | ≤3% |
| A 档准确率 | A 档中 gold_route=A 且 support 正确的比例 | ≥90% |
| C 档触发率 | 判 C 的比例；分 N3/N4 报 | 与业务约定（如 N3 ≥80%，N4 ≥70%） |

**次指标**：

- 覆盖率（coverage）：A+B 占比；A 单独占比。
- ECE（Expected Calibration Error，15 bins）与可靠性图；Brier。
- risk-coverage 曲线与 AURC（area under risk-coverage curve）。
- B 档二次错误率：进入 B 后后台预生成仍错的比例。
- 延迟：P50/P95/P99（编码 + 检索 + 分类器；不含 LLM；LLM 上界单独报）。

### 3.5 显著性检验

- **McNemar**：对「错误推送」的 0/1 结果做配对检验（我们的方法与每个对比方法各一次），报 b/c 与精确 p 值；n=250 时最小可检测差异约 4–5 个百分点（需在论文中说明功效限制）。
- **Bootstrap 95% CI**：1000 次重采样，按「设备 × 负例类型」分层重采样；主指标、次指标都给 CI。
- **多种子**：5 折 × 3 seed 的均值 ± 标准差；若 seed 间波动 >2pp，增加 seed 到 5 个。
- **报告规范**：`指标 = 点估计（95% CI）`，显著性写 `McNemar p=...`；不写「显著提升」而没有 p 值。

### 3.6 代价矩阵敏感性扫描

不给固定值，给扫描区间与依据：

| 代价项 | 含义 | 扫描区间 | 取值依据 |
|---|---|---|---|
| c_FN | 错误推送的代价（返工/停线/信任损失） | c_FN : c_B = **5:1 – 50:1** | 错误推送通常导致一次返工/停线；B 档只是一次人工参考（5–10 min）。比值下限按「1 次返工 ≈ 5 次参考」，上限按「停线 1 h ≈ 50 次参考」 |
| c_B | B 档人工参考 + 后台预生成成本 | 基准 1 | 定义为「一名工程师 5–10 min 复核 + 一次预生成」 |
| c_C | C 档慢通道成本（转人工/跨部门） | c_C : c_B = **1:1 – 10:1** | C 档要走慢通道（30–60 min），但不会错误推送；下限按「同价」，上限按「慢通道 1 h」 |
| c_A | A 档自动推送成本 | 0（或极小） | 自动推送无人工成本 |

**扫描方式**：固定 c_B=1，c_FN 取 {5,10,20,30,50}，c_C 取 {1,2,5,10}，共 20 个组合；画「错误推送率-C 档触发率」热力图，选业务可接受的工作点（如错误推送 ≤3% 且 C 档 ≤30%）。论文写「工作点由代价扫描选出，而非拍定」。

### 3.7 消融矩阵

| 维度 | 设置 | 目的 |
|---|---|---|
| 特征 | ①只用 top1 sim；②+margin；③+检索熵/覆盖；④+设备匹配；⑤+query 完整度；⑥+关键词重叠；⑦全量 | 证明多信号不是堆特征 |
| 校准 | ①无校准；②Platt；③isotonic；④temperature scaling | 证明校准对错误推送率/ECE 的作用 |
| 阈值 | ①固定 0.75/0.85/0.92；②固定 0.5 概率；③代价阈值；④CRC 阈值 | 证明「代价阈值/风险控制」优于硬阈值 |
| conformal | ①无；②split conformal；③CRC（α=3%/5%） | 证明风险上界是否更稳、弃权代价多大 |
| 类别 | 分别报 N1/N2/N3/N4 的错误推送率 | 定位失败模式（同象异因是主战场） |

## 第 4 节 对比现有方法的改进效果实验

### 4.1 对比对象与「为什么选它」

| # | 对比对象 | 具体配置 | 为什么选它 |
|---|---|---|---|
| B1 | **我们自己的现网配置** | 余弦阈值 0.75 / 0.85 / 0.92 三档；embedding-3 + Milvus | 最直接的「现状基线」；答辩必须回答「比现在好多少」 |
| B2 | **单信号无校准 LR** | 只用 top1 cosine 作为特征，LR 不校准，0.5 切三态 | 证明「不是随便加个分类器就行」；隔离「校准」与「多信号」的贡献 |
| B3 | **CRAG 式 LLM 三态判别** | query + top-5 证据 → LLM 输出 A/B/C | 代表「LLM 自反思」路线；作为强语义对照 |
| B4 | **LlamaIndex / LangChain 默认相似度阈值** | `similarity_top_k=5` + `similarity_cutoff=0.7/0.8` 三态 | 代表「开源 RAG 框架默认做法」；审稿人最熟悉 |
| B5 | **LLM-as-judge 上界** | 给 gold 证据与 query，让强 LLM 判「是否可直接推送」 | 上界；证明我们的轻量方案离上限多远；也暴露 judge 偏差 |

补充：B1 的 0.75/0.85/0.92 三档与数据与基线文档一致；B4 的 0.7/0.8 是框架常见默认值，不写成「LlamaIndex 官方唯一值」，实验时固定为 0.7 和 0.8 两档。

### 4.2 结果呈现（三件套）

1. **分层错误推送率柱状图**：x 轴为方法（B1–B5 + ours），y 轴为错误推送率；按 N1/N2/N3/N4 分组（4 组柱），每柱带 95% CI 误差线。用于回答「哪类负例上提升最大」。
2. **risk-coverage 曲线**：x 轴 coverage（A+B 或 A），y 轴 risk（错误推送率/选中风险）；每个方法一条曲线，标出工作点（代价阈值/CRC 阈值）。用于回答「同等覆盖率下风险低多少」。
3. **可靠性图（reliability diagram）**：x 轴预测概率分箱，y 轴实际正确率；画对角线；同时报 ECE。用于回答「校准是否真的把分数变成概率」。
4. **补充表**：A 档准确率、C 档触发率、P50/P95/P99 延迟、B 档二次错误率；每个指标给点估计 + 95% CI + 与 B1 的 McNemar p。

### 4.3 公平性控制

- **同一数据、同一划分、同一评测脚本**：所有方法共用 250 条与 5 折 × 3 seed 的划分文件。
- **同一检索结果**：B3/B4/B5 都用同一 BGE-M3/embedding-3 top-5，避免「检索不同」混淆。
- **同一校准集**：C2/C3/C4 用同一校准折；B1/B2 不校准（按定义）。
- **同一代价矩阵**：所有需要阈值的方案用同一扫描区间；B1/B4 用固定阈值，单独标注。
- **不调对比方法的超参**：B3/B5 用固定 prompt 与 temperature=0；B4 用框架默认参数；避免「把对手调弱」。

### 4.4 「准确率提升」量化结论口径模板

> 正式论文按下面模板填数；未跑之前不填数字。

**主结论模板**：

> 在 250 条分层评测集（100 正 + 150 负四类）、分层 5 折 × 3 seed 上，本文方法将 **A 档准确率从基线 B1 的 X%（95% CI [a, b]）提升至 ≥90%（95% CI [c, d]）**，将 **错误推送率从 Y%（95% CI [e, f]）降至 ≤3%（95% CI [g, h]）**；与 B1 的 McNemar 检验 p = \[p 值\]（b/c 对数 = \[...\]），差异\[显著/不显著\]。C 档触发率为 Z%，覆盖率为 W%，ECE 为 E。

**分类型模板**：

> 提升主要来自 N2（同设备同象异因）：错误推送率从 Y2% 降至 ≤3%；N1（跨设备）从 Y1% 降至 ≤2%；N3/N4 的 C 档触发率分别为 Z3/Z4%。

**风险控制模板（C4）**：

> 在 α=3% 的 CRC 设置下，错误推送率的经验值为 X%（95% CI [a,b]），低于目标 α；代价是覆盖率下降 ΔC 个百分点（从 W1% 到 W2%）。

**延迟模板**：

> 端到端 P95 延迟为 \[...\] ms（编码 + 检索 + 分类器，不含 LLM）；B3/B5 的 LLM 路线 P95 为 \[...\] s，不作为在线默认。

### 4.5 如果达不到目标：降级表述（不许编数据）

- **A 档准确率未到 90%**：写「实际为 X%（95% CI [a,b]），未达到 90% 目标；主要失败在 N2 类（同象异因），原因是……；在代价约束下建议将工作点右移（更多 B/C）」。不要写「接近 90%」或「达到约 90%」。
- **错误推送率未到 ≤3%**：写「实际为 Y%（95% CI [e,f]），高于 3%；在 α=5% 的 CRC 下为 Y'%；若业务坚持 3%，需将覆盖率从 W 降到 W'」。
- **提升不显著**：写「点估计优于基线，但 McNemar p=\[...\]，在 n=250 下不足以判定显著；需扩到 500 条或增加 seed」。不要写「有提升趋势，因此有效」。
- **conformal 上界保守**：写「CRC 在 250 条上给出保守上界，弃权率比经验阈值高 Δ 个百分点；这是有限样本保证的代价，不作为系统默认，只作为安全模式」。

## 第 5 节 若改选问题二：四步怎么变（差异点）

> 只写差异，不重写全文；与 [`数据与基线决策_v1.md`](file:///g:/JAVA/Code/ai-tims/docs/paper/研究方向/数据与基线决策_v1.md) 的 GPU/数据方案一致。

### 5.1 第 1 节趋势分析怎么变

- 主线从「检索-弃权」换成「**知识抽取 → 关系判别 → 条件化入库**」；三条脉络：
  1. **信息抽取/文档级关系**：DocRED（Yao et al., 2019）、PURE（Zhong & Chen, 2021）、REBEL（Cabot & Navigli, 2021）——对应「从工单/手册抽现象-根因-措施」。
  2. **实体解析/去重**：Fellegi & Sunter, 1969（概率记录 linkage）、Deep Entity Matching（Mudgal et al., 2018）——对应 duplicate/variant 判别。
  3. **知识冲突与条件化**：知识冲突综述（Xu et al., 2024 类，待核对卷期）、条件化知识图谱/规则入库——对应 conflict 判别与「什么条件下用哪条」。
- 对应环节：`ai_extracted` 抽取服务、`kb_knowledge` 入库、duplicate/variant/conflict 三关系。
- 可引用点：「文档级关系抽取需要跨句上下文」；「实体解析的匹配阈值应由代价决定」；「知识冲突需要来源/时间/条件三元信息」。
- 差异点：我们不是抽通用三元组，而是抽**维保五段式**（现象/根因/措施/验证/适用条件）+ 三关系；并把「条件」作为一等字段。

### 5.2 第 2 节方案选型怎么变

| 候选 | 做法 | 是否采用 |
|---|---|---|
| 规则/正则抽取 | 按设备手册模板正则 | 仅冷启动 |
| LLM API 抽取（GPT/GLM） | few-shot JSON 抽取 | 对照/种子 |
| **Qwen-7B LoRA 抽取 + 三关系分类头** | 24 GB 单卡 LoRA；输出五段式 + duplicate/variant/conflict | **主方案** |
| LoRA + 规则后处理 | 关系阈值 + 条件互斥检查 | 采用（后处理） |
| 人工全标 | 1000 条全人工 | 只做 gold/抽检 |

卖点：**「用 7B LoRA 把非结构化维保文本抽成带条件的三关系知识，入库前先判 duplicate/variant/conflict，避免把『同象异因』误合并成一条。」**

### 5.3 第 3 节实验设计怎么变

- 数据：1000 条抽取训练（AI 种子 + 人工复核）+ 250 条关系/入库评测（duplicate/variant/conflict 各 50 + 100 正常）。
- 协议：分层 5 折 × 3 seed + 锁定 holdout 20% + leave-device-out；抽取用 seqeval F1，关系用 macro-F1，入库用 merge precision/recall。
- 指标：抽取字段 F1（现象/根因/措施/验证/条件各一列）；三关系 macro-F1；duplicate 合并 precision ≥95%、recall ≥85%；conflict 检出率；下游检索 Hit@3 增益。
- 显著性：bootstrap CI + McNemar（关系分类）。
- 消融：有无 LoRA、有无条件字段、有无关系判别、固定阈值 vs 代价阈值。

### 5.4 第 4 节对比对象怎么变

| 对比 | 为什么 |
|---|---|
| 正则/模板抽取 | 传统基线 |
| LLM API few-shot | 强基线（不微调） |
| Qwen-7B 全参微调（若资源允许） | 上界 |
| 无关系判别直接入库 | 证明三关系的必要性 |
| 人工 gold | 上界/质检 |

结果呈现：抽取 F1 柱状图、关系混淆矩阵、merge precision-recall 曲线、下游 Hit@3 前后对比。

**问题二量化模板**：

> 在 1000 条训练 / 250 条评测上，三关系 macro-F1 从基线 X% 提升到 ≥Y%；duplicate 合并 precision 从 P1% 提升到 ≥95%，recall 从 R1% 到 ≥85%；conflict 检出率 ≥Z%；下游检索 Hit@3 从 H1% 提升到 H2%（95% CI，McNemar p=...）。
