# 标注手册 v1（问题二：五元组抽取 + 排除假设 + 三关系）

- 日期：2026-11-05
- 适用对象：**非本专业标注人员**（无需懂 SMT 工艺，按规则照标即可）；导师抽检与仲裁共用同一口径。
- 配套：`技术路线四步_v2_问题二.md` §3.1–§3.2；`决策台账.md` DEC-03/DEC-04。
- 原则：**只标文本里写了的，不补常识、不猜、不美化**。拿不准 → 标 `uncertain=1` 并写 `note`，交给仲裁，不要硬填。

## 0. 开始前你需要拿到的东西

1. 待标工单（JSON/CSV，字段至少含 `ticket_id`、`device_type`、`content`）。
2. **设备与根因受控词表**（`vocab_device.csv`、`vocab_root_cause.csv`）：根因必须从词表里选，选不到才新建并标 `new_term=1`。
3. 关系候选对清单（`relation_pairs.csv`，含 `pair_id`、`kb_a`、`kb_b`、`cosine`）。
4. 本手册 + 20 条校准样例的已裁定答案。

标注顺序：**通读全文 → 划证据句 → 填五元组 → 判排除假设 → 判 `root_cause_present` → 关系对单独标注**。

---

## 1. 标注单位

- **抽取**：一条工单 = 一条记录。工单里可能描述多个故障，**只标「本次工单最终处理的那个故障」**；其他故障写入 `note`，不另开记录。
- **关系**：一对知识 = 一条记录（`kb_a`、`kb_b` 为两条知识点的标题+正文摘要）。
- 时间口径：以工单**关闭时的最终结论**为准，不以报修时的初判为准。

## 2. 字段定义（总表）

| 字段 | 必填 | 定义 | 允许值 |
|---|---|---|---|
| `device_type` | 是 | 设备大类 | 贴片机 / AOI / SPI / 回流焊 / 涂布机 / 贴合机 / 蚀刻线 / MES |
| `symptom` | 是 | 可观测的异常状态（现象），不含原因与动作 | 文本 + `symptom_evidence`（原文句） |
| `root_cause` | 条件必填 | **经处置/验证确认**的直接原因，规范化标签 | 词表标签 + `root_cause_evidence` |
| `root_cause_present` | 是 | 该工单是否存在最终确认根因 | 1=有；0=没有（只有排除假设/待厂家回复等） |
| `measures[]` | 是（可空数组） | 实际执行过的处置动作，一条一个动作 | 动作文本 |
| `verification` | 条件必填 | 处置后的客观复测方法与结果 | 文本 + `verification_evidence` |
| `conditions[]` | 否 | 该结论成立的前提，五类 | `device_model` / `process_stage` / `material_or_batch` / `param_range` / `precondition` |
| `excluded_hypotheses[]` | 否 | 被明确排除的原因 + 排除证据 | 词表标签 + 证据句 |
| `unverified_hypotheses[]` | 否 | 文中提到但未验证的猜测（**不得进 root_cause**） | 文本 |
| `uncertain` | 是 | 标注者是否有把握 | 0/1 |
| `note` | 否 | 歧义说明、多故障、需仲裁点 | 文本 |

## 3. 逐槽位规则（正例 2 条 / 反例 2 条）

### 3.1 现象 `symptom`

**规则**：写「哪台设备 + 对什么对象 + 出现什么可观测异常 +（有数字就写数字）」。不能写原因、不能写处置动作。

- ✅ 正例 1：`贴片机在 0402 电阻贴装时出现 X 方向偏移，偏移量约 0.15mm，连续 3 片。`
- ✅ 正例 2：`AOI 对 2 号线的板首件复判时，连续 5 片报「图像模糊、无法识别焊点」。`
- ❌ 反例 1：`贴片机贴装偏移，原因是吸嘴堵塞。`（把根因写进现象）
- ❌ 反例 2：`调整贴装头参数后偏移恢复正常。`（这是措施+结果，不是现象）

### 3.2 根因 `root_cause`

**规则**：只写**最终确认的直接原因**，必须有证据句（拆检、参数读数、复测排除）。优先用词表标签；多因时写主因，次因放 `note`。**排除假设、未验证猜测一律不得写入。**

- ✅ 正例 1：`吸嘴堵塞导致真空压力不足`（证据：`拆检吸嘴发现锡膏残渣，真空压力由 -80kPa 降至 -45kPa`）
- ✅ 正例 2：`回流焊三温区热电偶漂移导致实际炉温偏低`（证据：`实测峰值 228℃，设定 245℃`）
- ❌ 反例 1：`怀疑供料器卡料。`（未验证 → 应进 `unverified_hypotheses`）
- ❌ 反例 2：`贴装偏移。`（这是现象，不是原因）

### 3.3 措施 `measures[]`

**规则**：只写**实际做过**的动作，一条一个动作，动词开头；不写结果、不写计划。

- ✅ 正例 1：`更换 0402 吸嘴并清洁真空通道。`
- ✅ 正例 2：`将贴装压力由 0.3N 调整为 0.2N，并重新校准贴装头零点。`
- ❌ 反例 1：`检查设备。`（太笼统，无法复现）
- ❌ 反例 2：`偏移已改善。`（这是结果，不是动作）

### 3.4 验证结果 `verification`

**规则**：必须同时有**方法**和**结果**。方法指复测手段（首件/AOI 复判/连续 N 片/参数读数/试产 N 小时）；结果是可判定的数值或状态。只有主观「好了」且无任何手段时，标 `uncertain=1` 并在 `note` 写明。

- ✅ 正例 1：`连续 5 片首件 AOI 复判偏移 ≤0.05mm，CPK 1.33。`
- ✅ 正例 2：`恢复生产后连续 2 小时无抛料报警，抛料率由 1.8% 降至 0.3%。`
- ❌ 反例 1：`已修复。`（无方法、无结果）
- ❌ 反例 2：`应该没问题了。`（猜测）

### 3.5 适用条件 `conditions[]`

**规则**：写「这条结论在什么范围内成立」，五类各取所需：设备型号 / 工艺段 / 材料或批次 / 参数区间 / 前置状态。**没有写就留空，不要写「所有设备」**。

- ✅ 正例 1：`device_model=SIPLACE SX；param_range=偏移 0.1–0.3mm；material_or_batch=0402 电阻。`
- ✅ 正例 2：`process_stage=锡膏印刷后 30min 内；precondition=钢网已清洗。`
- ❌ 反例 1：`所有设备、所有情况。`（无依据的泛化）
- ❌ 反例 2：`设备故障时。`（循环定义，等于没写）

### 3.6 排除假设 `excluded_hypotheses[]`

见第 4 节专项。

## 4. 「排除假设」专项（本课题最关键的新字段）

### 4.1 定义

工单在排查过程中**明确提出、但最终被证据否定**的原因。它不是根因，也不是「没查过的怀疑」。

### 4.2 三个判定信号（满足任一即算排除）

1. **明确否定词**：`排除…`、`不是…`、`确认与…无关`。
2. **处置后无效**：`更换供料器后现象不变`、`清洁吸嘴后仍偏移`（说明该原因不成立）。
3. **检测数据否定**：`供料器张力实测 12N，在标准范围 10–15N 内`、`真空压力 -80kPa 正常`。

> 只有「怀疑/待查/建议检查」而没有任何否定证据 → 进 `unverified_hypotheses`，**不抽、不进根因**。

### 4.3 标注要求

- 每条排除假设必须带 `hypothesis`（词表标签）+ `evidence`（否定证据原文句）。
- **禁止**把排除假设写进 `root_cause`；这是「排除假设误抽率」指标的统计对象。
- 困难条（`root_cause_present=0`）：全文只有排除假设、没有最终结论（如「转厂家处理，待回复」）→ 根因留空，排除假设照标。

### 4.4 正例 / 反例

- ✅ 正例 1：`已排查供料器，手动盘料张力正常、无卡料，排除供料器卡料。` → `excluded_hypotheses=[供料器卡料]`
- ✅ 正例 2：`更换新吸嘴后偏移未改善，排除吸嘴堵塞；后查为贴装头零点漂移。` → 排除 `吸嘴堵塞`，根因 `贴装头零点漂移`
- ❌ 反例 1：`怀疑供料器卡料，明天再查。` → 应进 `unverified_hypotheses`，不是排除
- ❌ 反例 2：`供料器卡料导致抛料，更换供料器后恢复。` → 这是**根因**，不是排除

## 5. 三关系判定（duplicate / variant / conflict / unrelated）

### 5.1 判定表（按顺序判，先满足先定）

| 顺序 | 关系 | 充要条件（全部满足） | 入库动作 |
|---:|---|---|---|
| 1 | **duplicate** | 同设备 + 同现象 + 同根因 + **条件等价** + 措施重叠 ≥80% | 可合并（MERGE，仍需人工确认） |
| 2 | **conflict** | 同设备 + 同现象 + **根因互斥** + **条件重叠**；或旧结论被新权威来源替代（时效型） | 不合并，进冲突队列，保留双方来源 |
| 3 | **variant** | 同现象族 + 根因同族或不同，但**措施/条件/粒度不同**；或条件互斥（各管一段） | 不合并，建 variant 边 |
| 4 | **unrelated** | 不同设备 / 不同现象 / 不同工序，且无共享根因 | 不建关系 |

> 记忆口诀：**同因同条件 → 重复；同现象不同因且条件打架 → 冲突；同族但条件/措施分家 → 变体；都不是 → 无关。**

### 5.2 边界案例（必须按此口径）

| # | 案例 | 判定 | 理由 |
|---:|---|---|---|
| 1 | 「MES 终端报工接口超时处理」两条，正文几乎一致，仅措辞不同，余弦 0.9385 | **duplicate** | 同设备/同现象/同根因/同条件/措施等价；现网 3 条 MERGE 均属此类 |
| 2 | 「贴片机抛料」→「供料器卡料」vs「供料器齿轮磨损导致卡料」 | **variant** | 同根因族，后者更具体；措施不同（清洁 vs 更换齿轮） |
| 3 | 「贴片机抛料」→「供料器卡料」vs「吸嘴真空不足」 | **conflict** | 同设备同现象、根因互斥、条件重叠（都会在常规产线发生） |
| 4 | 同为「贴装偏移」，一条条件 `0402 元件`，另一条 `0603 元件`，根因不同 | **variant**（条件分叉） | 条件互斥，两条都成立；不构成冲突，但不能合并 |
| 5 | 「贴片机贴装偏移处理」vs「贴片机锡膏印刷偏移处理」，embedding-3 余弦 **0.9262** | **unrelated** | 不同工序（贴装 vs 印刷）、不同现象对象；这是最典型的**假合并反例**，不得判 duplicate |
| 6 | 贴片机「抛料」与插件机「抛料」，根因同为供料器 | **unrelated** | 跨设备默认无关；除非正文明确写「跨设备通用」且同部件同机理，才可判 variant |
| 7 | 旧知识「炉温峰值 245℃」vs 新知识「同型号改为 235℃」，其余相同，新来源为厂家 2026 通告 | **conflict（时效型）** | 条件重叠、结论互斥；建 `supersedes` 边，旧条目不删除只降权 |

### 5.3 标注动作

- 每条对子填：`relation`（四选一）、`confidence`（0–1）、`evidence`（一句话理由）、`condition_overlap`（重叠/互斥/不适用）、`uncertain`。
- **不允许**用余弦分数直接当关系标签；`cosine` 只作参考列，不参与判定。

## 6. 一致性检验与 κ

1. **校准**：20 条（每设备 ≥2）三人对齐，不计入 κ。
2. **双标**：A、B 100% 独立标注 1000 条 + 300 对；C 仲裁分歧。
3. **κ 计算**（Cohen's κ）：
   - 公式：`κ = (p_o − p_e) / (1 − p_e)`；`p_o` 为一致率，`p_e` 为按两边边际分布相乘得到的期望一致率。
   - 用 `sklearn.metrics.cohen_kappa_score(y1, y2)` 复算，保留脚本输出。
   - 分别算：①各槽位「是否应填」二分类 κ；②根因词表标签多分类 κ（按设备内标签集）；③关系四分类 κ；④conflict vs 非 conflict 二分类 κ。
4. **目标线**：槽位存在性 κ ≥0.75；根因标签 κ ≥0.65；关系 κ ≥0.65；conflict 二分类 κ ≥0.70。**未达标先改手册，不进训练。**
5. **导师抽检**：按「设备 × 含排除假设 × 难度」分层抽 **10%（≥100 条）**；单切片不通过率 >10% 整层返工。
6. **自一致性**：同一人隔 7 天重标 5%（50 条），intra-rater κ <0.70 的槽位重写规则。

## 7. 常见错误清单（标注前先看一遍）

1. 把「怀疑」写成根因（应进 `unverified_hypotheses`）。
2. 把「已排除原因」写成根因（应进 `excluded_hypotheses`）。
3. 把现象写成根因（「偏移」「抛料」「模糊」都是现象）。
4. 把措施写成验证（「更换吸嘴」是措施，「连续 5 片复判合格」才是验证）。
5. 验证只写「已修复/正常」，没有方法与数值。
6. 条件写「所有设备」「一般情况下」等无依据泛化。
7. 一条工单里的多个故障混标成一条（只标本工单最终处理的那个）。
8. 用余弦分数代替关系判定（分数只作参考）。
9. 跨设备同现象直接判 duplicate（默认应判 unrelated）。
10. 拿不准不标 `uncertain`、不写 `note`，导致仲裁无法定位。

## 9. 数据文件与标注工作台

### 9.1 样本来源（2026-11-06 拍板）

| 项 | 决定 | 理由 |
|---|---|---|
| 主体 | **工单模拟器模板生成**（5 设备 × 10 故障主题，扩展过程性叙述） | 更接近真实报修文本：有排查过程、有排除、有复测 |
| 补充 | 知识库反推 query **只作补充，不作主体** | 反推 query 天然「库里有答案」，会把 M7 的 VECTOR Hit@3=100% 天花板偏差带进训练集 |
| 影响 | 外部效度更高（叙述真实），但**现象描述的真实性依赖人工保证**：标注时若发现现象与设备原理不符，标 `uncertain=1` 并在 `note` 写明 | 合成语料不能宣称"真实企业工单" |
| 成本 | 全部为合成语料，不含任何真实企业信息 | 论文需注明「合成语料」 |

### 9.2 文件清单（`docs/paper/问题二/`）

| 文件 | 用途 | 是否含真值 |
|---|---|---|
| `annotation_set_v1.csv` | 1000 条工单，标签列全空 | 否 |
| `_gold_draft.jsonl` | 生成真值（structure/style/root_cause/…） | 是，**标注者不得打开** |
| `annotation_data.js` | 工作台自动加载的数据（`window.ANNOTATION_DATA`） | 否 |
| `annotation_workbench.html` | 单文件标注工作台 | — |
| `annotation_relation_v1.csv` | 300 对关系集，`relation` 列空 | 否 |
| `_gold_relation_draft.jsonl` | 关系真值 | 是，**标注者不得打开** |
| `s1_suggestions.jsonl` | S1 零样本参考值（可选，默认关闭显示） | 否（可能有错） |
| `_dataset_stats.json` / `_relation_stats.json` | 分层统计与相似度落点 | 聚合，无逐条真值 |

### 9.3 CSV 字段与手册 schema 的对应

CSV 列名与手册字段一一对应，唯一差异：手册中的 `root_cause_present` 在数据文件里叫 **`has_final_root_cause`**（同义，1=有最终根因，0=只有排除假设/待跟进）。`label` 列为总体判定（pass / uncertain / no_root_cause），供抽检与 κ 使用，可留空。

### 9.4 工作台用法

1. 双击 `annotation_workbench.html`（Chrome/Edge 直接打开，无后端、无外网）。
2. 正常情况下自动加载 `annotation_data.js`；若被浏览器拦截，点右上「导入数据」选择 `annotation_set_v1.csv`（工单）或 `annotation_relation_v1.csv`（关系对）。
3. 左侧只读工单原文，右侧填槽位；每次改动自动存 `localStorage`（刷新不丢）。
4. `Alt+←/→` 上一条/保存并下一条；`Ctrl+S` 立即保存；底部可跳转序号或 ID。
5. 关系集自动切换成「知识 A / 知识 B + 四选一」界面。
6. 「预填建议值」默认**关闭**；打开后显示 S1 零样本参考值并标注「可能错误，以你的判断为准」，可一键填入再逐项核对，用于加速而非替代。
7. 收工点「导出 JSONL」（推荐，保留结构）或「导出 CSV」（表格核对），导出文件直接交给 `compute_kappa.py`。
