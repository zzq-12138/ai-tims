## 一、一句话现状

旧阈值 0.75 是「智谱 embedding-3 + 55 条知识库」标定的；现网换成「Qwen3-Embedding-8B + 310 条」，**分数的尺子换了、题的难度也换了**，0.75 不再对应原来的含义。公司环境已实测到正确 top1 只有 0.6751 却被判 C 档清空。要给出新阈值，必须在同一套 embedding 服务上重扫一遍；本执行包把这一步压缩成「拷两个文件、敲一条命令、回传五个文件」。

## 二、为什么 0.75 在 Qwen3 上失效

### 2.1 0.75 的来源（历史事实，不改写）

| 项 | 2026-11-05 标定 | 现在 |
|---|---|---|
| embedding | 智谱 embedding-3 | 公司 vLLM `Qwen/Qwen3-Embedding-8B`，1024 维 |
| 知识库 | 55 条 PUBLISHED | 310 条 PUBLISHED |
| 0.75 的成绩 | 正例覆盖 77%、混合错误推送率 20.9% | 尚未重测 |

旧曲线（真实 `vectorScore`，来源 `门控基线B0.md` 第四节）：

| T | 0.70 | 0.75 | 0.78 | 0.80 |
|---|---|---|---|---|
| 正例覆盖 | 85% | 77% | 54% | 31% |
| 混合错误推送率 | 46.9% | 20.9% | 8.2% | 0% |

0.75 当时是「偏松但可用」的点：77% 的问题能被回答，代价是约两成错误推送。

### 2.2 现在发生了什么

公司环境实测（310 库、Qwen3-8B、1024 维）8 条 query 的 `maxVectorScore`：

| 类型 | 观测值 |
|---|---|
| 有答案（正例） | 0.7858 / 0.6753 / 0.6446 |
| 无答案（负例） | 0.5523 / 0.5149 / 0.5031 / 0.4422（另 1 条 0.5299 待定） |

典型故障：工单问题「回流焊8温区温度偏低 焊点虚焊」，正确 top1《回流焊温区温度偏低》**只有 0.6751**，被 0.75 判 C 档、前端 refs 为空。

三条机理（不是"分数略降"这么简单）：

1. **模型换了，尺子变了。** 余弦分数的绝对刻度由模型决定，Qwen3-Embedding 在中文短 query 上的同题相似度整体低于 embedding-3；0.75 这个数字本身没有跨模型的可比性。
2. **库从 55 扩到 310，竞争变强。** 同设备族、同故障族的条目变多，第一名与第二名的分差被压缩；即使 top1 仍是正确条目，它的分数也会被"更像的邻居"分走一部分。
3. **查询侧没有按 Qwen3 协议加 instruction。** Qwen3-Embedding 的检索用法是「查询加 `Instruct: <任务>\nQuery: <问题>`，文档保持原文」；当前 `EmbeddingService.embed()` 对查询和文档用同一段裸文本。是否真的需要改，要靠这次的 raw/instruct 两组分数对比来判断，不能凭官方文档直接下结论。

### 2.3 用 8 个点只能给出粗区间，不能定阈值

若只按这 8 条：阈值必须 **> 0.5523**（排除最大的已知负例）且 **≤ 0.6446**（保住最小的已知正例），即候选区间约 **(0.5523, 0.6446]**。但 n=8、每类只有 3–4 条，且"无答案"的 0.5299 尚未定性，这个区间只能说明「0.75 明显偏高」，**不足以作为上线值**。所以必须做完整的三池扫描。

## 四、方法与口径

### 4.1 三池（与 `门控基线B0.md` 完全一致，保证新旧曲线可比）

| 池 | 条数 | 分数 | "可用"判定 |
|---|---|---|---|
| 正例 P | 100 | 全库 top1 余弦 | top1 ∈ expectedIds |
| leave-gold-out LG | 100 | **在内存中排除该 query 的 gold 后**取 top1 | 按构造不可用（模拟"库里没有"） |
| 负例 N | 100（有效 87） | 全库 top1 余弦 | N4 命中原 gold 才算可用；N1/N2/N3 一律不可用 |

- **不删除任何 Milvus 数据**：LG 只是把 gold 的 id 从候选数组里跳过再排序，等价于旧脚本"删 gold→检索→恢复"，但没有写入风险。
- 负例有效性按 `知识库310敏感性对照.md` §2.2 复核：扩库后有 13 条负例的"根因/主题关键词"已进库，不再成立（N1 10 条、N2 3 条）。脚本同时输出「全部 100」与「有效 87」两套口径，**不丢掉原始口径**。
- 正例有 4 处 gold id 在 310 库中已不存在（每条仍有存活 gold），bundle 已过滤为存活 id，原始 id 保留在 `expectedRaw`。

### 4.2 一次运行产出两组查询向量

| 组 | 查询侧文本 | 文档侧文本 |
|---|---|---|
| raw | `query` 原文 | `title\nsummary\ncontent` 原文 |
| instruct | `Instruct: Given a web search query, retrieve relevant passages that answer the query\nQuery: {query}` | 同上（不加前缀） |

文档向量只算一次，两组共用；查询向量各算一次。因此一次进内网即可拿到"加前缀前/后"的完整对比。

### 4.3 阈值与指标

- 扫描 **0.40 → 0.85，步长 0.01**（46 个点）；控制台另打 0.50/0.55/0.60/0.65/0.70/0.75/0.80/0.85 关键点。
- 推送 = top1 余弦 ≥ T；错误推送率 = 推送中不可用的比例（分母是推送量）。
- 混合等权 = P + LG + N 各 100 条；另给「有效负例」口径（87 条）。
- 额外记录 top2 与 `top1−top2` 间隔，便于后续评估间隔规则（本包不改门控逻辑）。

### 4.4 自检锚点

脚本固定跑一条 sanity query：「回流焊8温区温度偏低 焊点虚焊」，公司环境实测 top1 = **0.6751**。

> **问句写法提醒（2026-11-23 补）**：该 query 的 11-19 原始记录为**全角逗号版**「回流焊8温区温度偏低，焊点虚焊」；半角空格版同条件约低 **0.015**（空格 0.7497 vs 逗号 0.7647）。复现 sanity 时请固定一种写法，并在结果里注明，避免把标点差异当成模型漂移（详见 `Qwen3Embedding门控阈值实测结果.md` §4.2）。

- 若复现值在 0.6751 ± 0.02：说明模型、维度、文档文本与公司服务口径一致，曲线可用。
- 若偏差 > 0.02：**先别用这批数据定阈值**，把 `qwen3_gate_summary.json` 的 `sanity_check` 发回来排查（模型名/维度/是否误加了 prompt 模板）。

## 六、回传后怎么定阈值（本地分析口径）

1. **主口径**：混合等权（P+LG+N 各 100）错误推送率 ≤ 3%，且正例覆盖率 ≥ 30%；在该集合内取覆盖率最高的阈值。覆盖率 < 30% 的 ≤3% 点视为「把问答关掉」，不算可用工作点。
2. **稳健性**：用「有效负例 87 条」口径复算；两个口径结论方向必须一致，否则以更保守的（错误率更高）为准。
3. **可解释性**：同时报告该阈值下正例/负例的分数分布（p10/中位数/p90）与 top1 准确率，说明阈值落在两个分布之间的哪一段。
4. **前缀决策**：比较 raw 与 instruct 的 AUC、Hit@1、以及各自可用工作点的覆盖率。只有 instruct 在「区分度更好且工作点可用」时才启用前缀；否则保持原文，避免无收益的改动。
5. **回验 0.75**：在新数据上算出 0.75 的正例覆盖率与错误推送率，作为"旧值为什么失效"的直接证据（预期覆盖显著低于 77%）。
6. **不改"唯一阈值"以外的门控结构**：软带 0.07 是否随阈值平移、是否引入间隔规则，等曲线出来再单独决策，不在本包中预判。

> 选阈值不是挑最高分：若 ≤3% 与 ≥30% 覆盖无法同时满足，就如实报告「单阈值无可用工作点」，并把候选前沿（如 0.62/0.65/0.68 的覆盖率与错误率）交给产品取舍；不得为了凑 3% 而把覆盖压到个位数。

## 九、局限（必须和数字一起看）

1. **样本量**：正例/负例/LG 各 100 条，单次运行；错误推送率的 95% 置信区间约 ±4–5pp，不足以支撑「3.0% vs 3.1%」这类精细结论。
2. **负例前提已部分失效**：扩库后 13/100 条不再是合法负例，主口径保留原始 100 条以对齐 B0，同时给出 87 条口径；两者必须并列报告。
3. **分数口径是 VECTOR top1**：生产默认 HYBRID，门控用 `maxVectorScore`（RRF TopK 内最高余弦）；本包与 B0 的 VECTOR 行对齐，不模拟 RRF 排序影响。
4. **与公司服务的可比性依赖三点**：同一模型名、同一 `dimensions=1024`、同一文档文本拼接方式（`title\nsummary\ncontent`）。sanity 自检是唯一守门人；偏差 >0.02 时数据作废。
5. **instruction 的效果只对"查询侧"成立**：文档侧若也加 instruction 会与公司现有 310 条向量不一致，本包明确不做。
6. **一次运行一套数**：回传后只用同一批文件出图出表，不与旧运行的中间结果拼接。
