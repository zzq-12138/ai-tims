# 方法与调优说明（论文写作素材）

> 本文档面向论文“方法/实验”章节，说明知识提炼链路、RAG 效果消融的定义、每轮真实增益与失败归因。所有数字均来自 `docs/paper/评测/消融结果.csv` 与 `_metrics.json`（2026-11-04 快照，100 条 query）。

## 1. 知识提炼链路

关单事件 → LLM 结构化抽取 → 余弦相似度去重（阈值 0.92，人工确认）→ 人工审核 → 向量化入库 → 30s 内可检索。

| 步骤 | 触发/输入 | 算法与工具 | 关键参数 | 输出与保障 |
| --- | --- | --- | --- | --- |
| 1. 关单事件 | 工单状态变为已关闭 | RabbitMQ `ticket.closed` 事件，`TicketClosedConsumer` 消费 | 按 tenantId 隔离 | 进入抽取队列，失败重试 1 次，仍失败转 `MANUAL_REQUIRED` |
| 2. LLM 结构化抽取 | 工单标题+故障描述+处理记录 | 智谱 `glm-5.3-flash`（`LLM_EXTRACT_MODEL` 可切换；S1 基线为 glm-4-flash 的 316 条现成数据，S3 为 glm-5.3-flash），Prompt 约束输出四段结构 | temperature/模型由 `ticket-ai` 配置；批量并发 16 | 生成“故障现象 / 排查步骤 / 解决步骤 / 关键要点”草稿，状态 `PENDING_REVIEW` |
| 3. 余弦去重 | 新草稿与库内同设备已发布知识 | embedding-3 向量 + 余弦相似度 | ≥0.98 建议跳过；≥0.92 建议合并；其余建议新建（**仅建议，不自动合并**） | 审核人确认，避免误合并 |
| 4. 人工审核 | 草稿 + 去重建议 | 审核中心状态机 `PENDING_REVIEW → PUBLISHED / REJECTED` | 非法迁移拒绝（30401） | 只有 `PUBLISHED` 进入检索索引 |
| 5. 向量化入库 | 发布事件 | 智谱 embedding-3，HTTP `/api/paas/v4/embeddings` | **1024 维**；批量 ≤16；单条文本截断留余量 | 写入 Milvus 集合（pk + 标量 + 向量） |
| 6. 可检索保障 | 定时扫描 | `VectorSyncService` 扫描未同步条目 | 扫描间隔 10s；失败退避 30s | 发布后 **30s 内**可被向量检索命中 |

### 检索侧参数（消融的固定背景）

| 组件 | 实现 | 参数 |
| --- | --- | --- |
| 关键词检索 | MySQL FULLTEXT `MATCH ... AGAINST`（NATURAL LANGUAGE MODE） | ngram 分词 `token_size=2`；单字查询直接返回空；取 Top10 |
| 向量检索 | Milvus + HNSW | 距离 `COSINE`；建索引 `M=8`、`efConstruction=64`；查询 `ef=64`；取 Top10 |
| 融合 | RRF（Reciprocal Rank Fusion） | `score = Σ 1/(k + rank + 1)`，默认 `k=60`；两路各取前 10 |
| 加权 | 设备类型、标签命中 | 设备名出现在 query 中 ×1.5；知识标签（长度≥2）出现在 query 中 ×1.2 |
| 输出 | 截断 | `topK` 默认 3，可配 1~20 |

## 2. “RAG 效果消融”是什么

一句话：**逐项打开/关闭或调整检索链路中的某个配置（关键词、向量、融合、加权、RRF k、topK），在固定评测集上观察 Hit@3 等指标变化，从而量化每个设计环节各自贡献了多少**。

## 3. 每轮改了什么、提升了多少（真实数字）

评测集 100 条，主指标 Hit@3，`Δ` 为相对上一轮的绝对百分点变化；负值表示回落。

| 轮次 | 相对上一轮改了什么 | Hit@3 | Δ Hit@3 | 其他指标变化 | 平均/P95 耗时 |
| --- | --- | ---: | ---: | --- | ---: |
| E1 KEYWORD | 基线：仅关键词 | 90.0% | — | Hit@1 82.0%，MRR 0.859 | 11.1 / 16.4 ms |
| E2 VECTOR | 检索模式换为纯向量 | 100.0% | **+10.0pp** | Hit@1 82→98（+16pp），MRR 0.859→0.990（+0.131） | 218.3 / 281.6 ms（+207.2ms） |
| E3 HYBRID(k=60,无加权) | 关键词+向量 RRF 融合 | 96.0% | **−4.0pp** | Hit@1 98→91（−7pp），MRR 0.990→0.943（−0.047） | 229.4 / 296.8 ms |
| E4 +设备加权×1.5 | 仅增加设备类型加权 | 96.0% | **0.0pp** | Hit@1、MRR 与 E3 完全相同（91.0%、0.943） | 229.4 / 296.8 ms（复算不增加网络耗时） |
| E5 +标签加权×1.2 | 在 E4 上增加标签加权（生产配置） | 96.0% | **0.0pp** | 同配置离线复算（E6-k60）：Hit@1 91→90（−1pp）、MRR 0.943→0.938（−0.005）；真实接口受并列排序影响为 Hit@1 89.0%、MRR 0.929 | 227.8 / 281.5 ms |
| E6 k=30 | RRF k 由 60 改 30 | 96.0% | 0.0pp | Hit@3/Recall@5/MRR 三项与 k=60 完全一致 | 229.4 / 296.8 ms |
| E6 k=60 | RRF k=60 | 96.0% | 0.0pp | 同上 | 同上 |
| E6 k=100 | RRF k=100 | 96.0% | 0.0pp | 同上 | 同上 |
| E7 topK=1 | 展示条数由 3 改 1 | — | — | **Hit@1=90.0%**，MRR 0.938 | 229.4 / 296.8 ms |
| E7 topK=3 | topK=3 | 96.0% | 0.0pp | Hit@5=99.0%，Recall@5=99.0% | 同上 |
| E7 topK=5 | topK=5 | 96.0% | 0.0pp | **Hit@5=99.0%**（较 Hit@3 +3pp） | 同上 |
| E8 最优复跑 | 按 Hit@3 选择 VECTOR，topK=5 | 100.0% | **+4.0pp**（相对 E7） | Hit@1 90→98，MRR 0.938→0.990 | 220.8 / **279.7** ms |
| E8H 生产复跑 | HYBRID 生产配置 topK=5 | 96.0% | 0.0pp（相对 E7） | Hit@1 90→89（−1pp），MRR 0.938→0.929 | 228.1 / 290.6 ms |

> 注：E5 由真实接口测得，E4/E6 为同一候选快照的离线复算。两者在 6/100 条样本上因 RRF 同分并列的排序差异，前 3 集合不一致，因此 E4→E5 的 Hit@1/MRR 逐项差值不宜直接解读；Hit@3 持平这一点在两种口径下一致。

### 3.1 结论摘要（可直接引用）

1. 最大单项增益来自**关键词→向量**的模式切换：+10.0pp Hit@3，但延迟从 11.1ms 增至 218.3ms（约 20 倍）。
2. RRF 融合当前是**负增益**：相对纯向量 −4.0pp Hit@3；融合后的 96.0% 也没有超过任一单路的最高值（向量 100%）。
3. 设备加权、标签加权、RRF k 三项调参在本评测集上**均为 0.0pp**，其中标签加权在离线口径下使 Hit@1 下降 1pp、MRR 下降 0.005，属于**中性偏负**，不能表述为提升。
4. 展示条数 topK 不改变排序：topK=1/3/5 的 Hit@1/3/5 分别为 90.0%/96.0%/99.0%，第 4~5 名额外贡献 3pp。
5. 达标判定：主指标 Hit@3 ≥80%，E8（100.0%）与生产配置 E8H（96.0%）均达标；但 KEYWORD 基线也达 90.0%，说明评测集整体偏易（见第 4 节与《评测集说明》的偏差项）。

## 4. 失败样本归因（生产 HYBRID 配置，96.0%）

按 query 风格拆分（E8H）：

| 风格 | 条数 | Hit@3 | Hit@1 | Recall@5 |
| --- | ---: | ---: | ---: | ---: |
| formal（正式提问） | 54 | 100.0% | 98.1% | 100.0% |
| colloquial（口语化） | 16 | 100.0% | 100.0% | 100.0% |
| noisy（含噪声） | 15 | 86.7% | 80.0% | 100.0% |
| missing（缺设备字段） | 15 | 86.7% | 53.3% | 93.3% |

失败集中的 4 条生产配置未命中样本：

| query | 应命中 | 实际前 3 | 归因 |
| --- | --- | --- | --- |
| AOI检测机跟上位机断联了，数据传不过去 | AOI通讯中断 | 算法阈值漂移 / 误报率过高 / 漏检 | 术语不一致（断联 vs 通讯中断） |
| 喷头喷不出来，喷得很不均匀 | 蚀刻机喷嘴堵塞 | 涂布厚度不均 / 蚀刻不均 / 涂布头堵塞 | 术语不一致 + 缺设备字段，跨设备混淆 |
| 料送进来是歪的，走不正 | 贴合机送料偏斜 | 贴片机抛料 / 贴装偏移 / 抛料 | 缺设备字段，被贴片机近邻吸走 |
| 涂布机料跑偏了纠不回来 | 涂布机纠偏失灵 | 边缘漏涂 / 厚度不均 / 涂布头堵塞 | 术语不一致（跑偏 vs 纠偏） |

关键词基线（E1，90.0%）另有 6 条独有失败，集中在缺设备字段（“不良品没检出来”“板子边上一圈没涂上”）与同设备相近故障（“位置整体偏” vs 印刷偏移/立碑/抛料），其中 1 条因两条同名重复知识同时进入前 3 被挤占。

### 归因归类与下一步

| 类型 | 占比 | 说明 | 优化方向 |
| --- | ---: | --- | --- |
| 口语术语与知识术语不一致 | 4/10 | 断联/通讯中断、喷头/喷嘴、歪/偏斜、翘起来/立碑 | 维护同义词表，做关键词查询扩展；抽取阶段补充口语别名 |
| 缺失设备字段 | 4/10 | 无设备名时跨设备近邻抢占 | 设备槽位推断（工位/用户画像/近期工单），推断后做过滤或加权 |
| 同设备相近故障混淆 | 2/10 | 位置偏/印刷偏移/立碑/抛料语义接近 | 引入对象词/部位词特征，或对标题做实体增强 |
| 重复条目挤占 | 1/10 | 两条同名“回流焊炉温失控”同列前 3 | 知识治理：清理 5 条测试残留与同名重复，去重阈值 0.92 的人工确认需落实到存量数据 |

**优先级建议**：知识去重与存量清理（成本最低、可解释）→ 术语同义扩展 → 缺设备槽位推断 → 再评估融合权重（关键词降权或条件启用），而不是继续调 RRF k。

## 5. 成本与可复现性

- 评测全程使用标准答案匹配，无 LLM 打分；embedding 调用约 950 次（快照 400 次 + 调试重跑约 550 次），按 0.0005 元/千 tokens 估算 **≈0.01 元**。
- 评测集与脚本入库，可一键复跑：`scripts/eval/gen_eval_set.py`、`scripts/eval/run_eval.py`；快照缓存 `_candidates.json` 保证同一份候选数据可重复计算所有轮次指标。
- 评测期间 `ticket-knowledge` 被并行会话重启，脚本采用 HTTP 重试 + 快照缓存，最终 100/100 采集完整、`fallback=0`，无缺失样本。
