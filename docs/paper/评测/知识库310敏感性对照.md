# 知识库 310 条敏感性对照（VECTOR 单路 + 门控 B0）

> 目的：M7 八轮消融与门控 B0 都跑在 2026-11-04/11-05 的 54/61 条快照上，知识库于 2026-11-06 扩到 310 条。本文只回答一个问题——**换到 310 库后，VECTOR 单路的 Hit@1/3、Recall@5 与门控 B0 的覆盖率/错误推送率变了多少，原结论是否稳健**。
> 不做：不重跑 8 轮全表、不动训练集、不改代码、不重标定阈值上线。
> 执行日期：2026-11-07 ｜ 执行环境：VM `ubuntu-server`，`ticket-knowledge` :8103，PUBLISHED 310 条 / 向量 310 条 ｜ 产物：`docs/paper/评测/_kb310/`

---

## 〇、一句话结论

> **M7 主表基于 54 点快照；310 库敏感性对照的 Hit@3 差异为 −5.0pp（原始 gold ID 口径；其中 3/5 的失败是同题新条目竞争，按语义口径约 −2.0pp），检索结论基本稳健；但门控 B0 的错误推送率由 19.1% 升至 48.5%（剔除扩库后失效负例仍有 45.9%），门控结论不稳健——0.75 是按 54/55 库标定的，必须按目标库规模重标定，且单阈值在 310 库上没有可用工作点。**

## 二、前置校验

### 2.1 gold ID 是否仍在 310 库

100 条 query 中 **4 条**各缺 1 个 gold ID，涉及 **2 个 ID**（均为旧 54 库条目，扩库时未保留）：

| query | 缺失 gold ID | 存活 gold ID | 处理 |
|---|---|---|---|
| P-001 / P-055 | `2117918161331044354`（MES 终端报工接口超时） | `2117984477438107650` | 保留 query，按存活 gold 计算；不用新条目顶替 |
| P-003 / P-057 | `2117522070425055234`（回流焊炉温失控） | `2117518330221625345` | 同上 |

- 影响面：4/100 条，且每条仍有存活 gold，**Hit@k / Recall@5 可正常计算**；缺口在文中如实标注。
- leave-gold-out 的 4 行状态为 `RESTORE_FAILED`：删除的是存活 gold，恢复后用**原始 gold 列表**回查必然缺 1 个 ID，属校验口径问题；结束后 `#N1 = 310`，**无数据丢失**。这 4 行的 top1 分数仍计入（见 §3.2）。

### 2.2 负例集「根因关键词全库 0 命中」的前提是否仍成立

原负例集按 54 库构造。扩到 310 后，**13/100 条负例的根因关键词已在库中出现**，这些样本不再是合法负例：

| N2 同因异象 / 缺字段噪声 | 0/25、0/25 | 不受影响 |

## 三、结果

### 3.1 检索（100 条正例，VECTOR 单路）

| 指标 | 54 点快照 | 310 库 | 差值 |
|---|---:|---:|---:|
| Hit@1 | 98.0% | **85.0%** | **−13.0pp** |
| Hit@3 | 100.0% | **95.0%** | **−5.0pp** |
| Recall@5 | 100.0% | **96.5%** | **−3.5pp** |
| MRR | 0.990 | **0.902** | −0.088 |
| P95 延迟（topK=5） | 279.7 ms | **292.9 ms** | +13.2 ms |

- topK=10 与 topK=5 的命中指标一致（85.0 / 95.0 / 96.5），说明差距不是 topK 截断造成。
- 延迟上升 13.2 ms，与库规模 ×5 的 ANN 搜索开销一致，量级可接受。

### 3.2 门控 B0（VECTOR，T=0.75，300 = 100 正例 + 100 负例 + 100 leave-gold-out）

| 指标 | 54 点快照 | 310 库（原始） | 310 库（剔除 13 条失效负例） |
|---|---:|---:|---:|
| 正例推送 / 正确 | 77 / 77 | 74 / 70 | 74 / 70 |
| 正例错误推送 | 0 | **4** | 4 |
| 负例推送 / 错误 | 34 / 18 | 51 / 36 | 43 / 28 |
| 负例错误率 | 52.9% | **70.6%** | 65.1% |
| leave-gold-out 推送 | 4 | **40** | 40 |
| C 档（不推送）占比 | **61.7%** | **45.0%** | 45.3%（分母 287） |
| 总推送 / 总错误 | 115 / 22 | 165 / 80 | 157 / 72 |
| **错误推送率** | **19.1%** | **48.5%** | **45.9%** |

**阈值扫描（310 库，供重标定参考；54 点同口径见 `阈值错误率评估.md`）**

| T | C 档占比 | 总推送 | 错误推送率 |
|---:|---:|---:|---:|
| 0.75 | 45.0% | 165 | 48.5% |
| 0.78 | 76.7% | 70 | 27.1% |
| 0.80 | 89.0% | 33 | 12.1% |
| 0.82 | 97.0% | 9 | 0.0% |
| 0.85 | 99.3% | 2 | 0.0% |

> 54 库上 0.80 即可做到 0% 错误、覆盖 31%；310 库上要做到近似 0% 错误需抬到 0.82，但正例覆盖只剩 8%（8/100，9 条推送中另 1 条为负例正确推送）。**单阈值在 310 库上没有可用工作点**，这正好复现并强化 DEC-06 的结论：应改「top1−top2 间隔 + 根因一致性」，而不是继续抬阈值。
>
> 口径更正（2026-11-07）：本节初稿把「C 档占比 97%」反推为「覆盖 3%」，属口径误用——97% 的分母是 300 条全样本，而正例覆盖的分母是 100 条正例。按 `_kb310/_collect.json` 复算，T=0.82 的正例覆盖为 8/100。`多信号门控原型.md` 与 `创新点.md` 已同步改为 8%。

### 3.3 分数分布（解释门控失效的直接原因）

| 分布量 | 54 点快照 | 310 库 | 差值 |
|---|---:|---:|---:|
| 正例 top1 余弦中位数 | 0.7831 | 0.7710 | −0.0121 |
| 负例 top1 余弦中位数 | 0.7368 | 0.7514 | **+0.0146** |
| 正负例中位数间隔 | **0.0463** | **0.0196** | **−0.0267** |
| 正例 ≥0.75 | 77 | 74 | −3 |
| 负例 ≥0.75 | 34 | **51** | **+17** |

扩库后正例分数略降、负例分数明显上升，**正负例分数分布重叠加剧**（间隔腰斩），0.75 这个绝对阈值随之从「可用」变成「几乎不可用」。

## 四、归因：−13.0pp 的 Hit@1 掉在哪里

15 条 Top1 未命中，逐条人工判读（单人语义判读，非双人标注）分三类：

| 类型 | 条数 | 例子 | 是否算检索失败 |
|---|---:|---|---|
| 同题/同现象，新增条目根因表述不同 | **10** | P-023 top1「贴合机压合时间不足导致脱胶」vs gold「贴合机脱胶维修」；P-080 top1「蚀刻机蚀刻时间过长导致过蚀刻」vs gold「蚀刻机过蚀刻处理」 | 语义上不算跑偏，属**知识条目版本竞争**（扩库引入同题多版本） |
| 同设备、不同故障 | 3 | P-055 top1「MES 重复提交导致数据重复」vs gold「MES 终端报工接口超时」；P-099 top1「贴片机破真空带起元件」vs gold「贴片机立碑处理」 | 严格 gold 口径算错 |
| 跨设备、真跑偏 | **2** | P-063（AOI 查询 → 贴合机）；P-081（贴合机查询 → 贴片机） | **算错，且是真实退化** |

**未进 Top3 的 5 条**：P-055（MES 同设备不同题）、P-063（跨设备）、P-075（蚀刻机同题不同根因）、P-078（AOI 同题不同根因）、P-081（跨设备）——其中 **3 条是同题条目竞争，2 条是跨设备真错**。

因此：

- **原始 gold ID 口径**：Hit@1 −13.0pp、Hit@3 −5.0pp（保守、可复算，论文主表用这个）。
- **语义口径（人工判读）**：Hit@1 约 95.0%（−3.0pp）、Hit@3 约 98.0%（−2.0pp）。该口径**不能替代原始指标**，只能作为解释性说明，且必须标注为单人判读。

门控侧同样有两条腿：13 条负例失效（结构性）+ 分数分布上移（规模性）。剔除失效负例后错误率仍从 19.1% 升到 45.9%（+26.7pp），**扩容导致的分数重叠是主因**；leave-gold-out 推送 4→40 是最直接的证据（同一批 query，去掉 gold 后 310 库里的同题邻居大量越过 0.75）。

## 五、对论文的影响（可直接搬运）

### 5.1 稳健性判定

| 结论 | 是否稳健 | 论文写法 |
|---|---|---|
| 「VECTOR 单路优于 HYBRID / 加权无增益」 | **基本稳健**（Hit@3 −5.0pp，语义口径 −2.0pp） | 可在 5.4 加一句「扩到 310 后 VECTOR Hit@3 由 100% 降至 95%，排序结论不变」 |
| 「VECTOR 绝对命中率 100%」 | **不稳健** | 必须标注「该 100% 是 54/61 库快照值」 |
| 「门控 0.75 错误推送率 19.1%」 | **不稳健** | 必须标注「54/55 库标定值；310 库同阈值为 48.5%，需重标定」 |
| 「单阈值无法兼顾覆盖与错误率」 | **更稳健**（310 上更明显） | 可作为 DEC-06 路线的加强证据 |

### 5.2 可写 / 不可写

- ✅「M7 主表与门控 B0 均在 54/61 条快照上完成；在 310 条库上做了 VECTOR 单路 + 门控 B0 的敏感性对照，Hit@3 下降 5.0pp，门控错误推送率上升 29.4pp。」
- ✅「扩库后正负例 top1 分数中位数间隔由 0.046 收窄到 0.020，0.75 阈值失效；需按库规模重标定或改用间隔+根因一致性。」
- ❌「M7 的 100% Hit@3 适用于当前 310 库。」
- ❌「0.75 门控在 310 库上错误率 19.1%。」
- ❌ 把语义口径的 95%/98% 当作正式指标（只能作解释，且注明单人判读）。

### 5.3 建议

1. **论文主表不重跑**：M7 八轮与 B0 保留 54/55 前提，在表注与 5.6 局限中写明；本文作为 5.4「稳健性/敏感性」小节。
2. **门控阈值不沿用**：310 库上 0.75 不可用；若要上线，先按目标库重标定（本文扫描显示 0.82 才近似 0 错误但正例覆盖仅 8%），或直接走 DEC-06 的「间隔 + 根因一致性」。
3. **负例集需按 310 库重建**：13% 已失效，后续门控评测前必须先跑 `negcheck` 同款校验。
4. **若要正式报 310 库指标**：需先解决「同一知识点多版本条目」的 gold 对齐（同题条目应视为同一 gold 或合并），否则 Hit@1 会被版本竞争系统性压低。

## 七、局限

1. **gold ID 口径偏悲观**：310 库新增的同题条目即使语义正确也不计入命中；原始 −13.0pp 是上界，语义口径需人工判读、不可复算。
2. **失效负例**：13 条负例在 310 库已不成立；本文给了双口径，但两版都不是「按 310 库重新构造负例」的结果。
3. **单次运行、单模型**：embedding-3 + Milvus 单次采集，无重复测量；未测 BGE-M3。
4. **门控只测 B0**：未重跑「间隔 + 根因一致性」新方案，也未做 0.82 的上线验证。
5. **4 条 query 的 gold 缺失**：按存活 gold 计算，未评估「缺失条目是否影响 query 语义完整性」。
