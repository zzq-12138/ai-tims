# M7 检索消融评测报告

## 1. 评测目标与环境

| 项 | 内容 |
| --- | --- |
| 目标 | 验证知识检索链路各设计环节（关键词/向量/融合/设备加权/标签加权/RRF k/topK）的独立贡献，给出可直接写入论文的评测数据 |
| 被测系统 | AI-TIMS `ticket-knowledge`，接口 `GET/POST /api/kb/search`（VECTOR / KEYWORD / HYBRID，topK 可配） |
| 环境 | VM `dev@192.168.40.10`，服务端口 8103（网关 8080），MySQL FULLTEXT(ngram) + Milvus(HNSW, COSINE) + 智谱 embedding-3（1024 维） |
| 知识库快照 | 61 条 PUBLISHED（含 5 条测试残留干扰项），54 个有效知识点，评测期间无新增发布 |
| 评测集 | `docs/paper/评测/eval_set.csv`，100 条 query（54 formal + 46 口语/噪声/缺字段），构造与偏差见《评测集说明》 |
| 采集时间 | 2026-11-04 15:30 前后（Asia/Shanghai），`fallback=false` 100/100 |

### 指标口径

- **Hit@3（主指标）**：返回前 3 条与 `expectedIds` 有交集即命中 1，否则 0；全量平均 ×100%。
- **Recall@5**：前 5 条命中的标准答案数 / 标准答案总数。
- **MRR**：第一个正确答案排名倒数的平均值。
- **耗时**：单次 HTTP 端到端耗时（含 embedding 调用、检索、融合、序列化），P95 取 100 样本排序后第 95 百分位。
- 判定采用**标准答案匹配**，不使用 LLM 打分。

### 关于“离线复算”

现有接口只暴露 `query/mode/topK`，未暴露设备/标签权重与 RRF k。为在不修改后端代码的前提下完成 E3~E7，评测脚本用与 `SearchService.rrfFuse` **完全相同的公式**（两路各取 Top10，`1/(k+rank+1)` 累加，再乘设备/标签加权）在本地复算，候选池来自真实接口。

- 一致性校验：在生产配置（k=60、设备 1.5、标签 1.2）下，离线复算与真实 HYBRID 接口的**前 3 集合一致率 94%**（6/100 不一致）。
- 不一致原因：RRF 同分并列时，Java 侧 `HashMap` 迭代顺序与本地稳定插入顺序不同，差异均出现在第 3 名边界的并列项，不改变结论。
- E2/E5/E8/E8H 的指标直接取自真实接口；E3/E4/E6/E7 为同候选池离线复算，表格中标注数据来源。

| E8 | **最优组合复跑：VECTOR，topK=5** | 接口 | 98.0% | **100.0%** | 100.0% | 0.990 | 220.8 | **279.7** | +4.0pp（相对 E7） |
| E8H | 补充：生产 HYBRID 配置，topK=5 | 接口 | 89.0% | **96.0%** | 99.0% | 0.929 | 228.1 | 290.6 | 0.0pp（相对 E7） |

> E7 的 topK 只改变返回条数、不改变排序，因此 Hit@3 不随 topK 变化；三条分别看 Hit@1=90.0%、Hit@3=96.0%、Hit@5=99.0%。E7 的 Recall@5 取自同一排序前 5 位，不受展示 topK 影响。
> E5 与 E6-k60 为同一配置，MRR 有 0.929 与 0.938 的差异，来自上述并列排序口径，不是参数效果。

### 2.1 关键读数

1. **VECTOR 单独使用最强**：Hit@3 100%，Hit@1 98%，MRR 0.990；KEYWORD 只有 90% / 82% / 0.859。
2. **HYBRID 融合没有超过 VECTOR**：96% vs 100%（−4pp）。原因是关键词一路在语义歧义 query 上召回同设备近邻条目，RRF 等权累加后把向量排在第 1 的正确条目挤到第 3 名之外。
3. **设备类型加权与标签加权均无正增量**：E3→E4 为 0.0pp，E4→E5 为 0.0pp；离线口径下标签加权还使 Hit@1 从 91% 降到 90%（−1pp），MRR 从 0.943 降到 0.938。**如实记录为负向/中性，不做“显著提升”表述。**
4. **RRF k=30/60/100 无差异**：三档 Hit@3、Recall@5、MRR 完全相同，说明当前候选规模（两路各 10 条、库内 54 个知识点）下 k 不敏感。
5. **topK 只影响召回深度**：topK=1 时 Hit@1=90%；topK=3 时 Hit@3=96%；topK=5 时 Hit@5=99%。topK 3→5 的 +3pp 来自第 4~5 名的补充命中。
6. **延迟成本**：KEYWORD 平均 11.1ms；VECTOR/HYBRID 平均 218~229ms，约为前者的 20 倍，主要成本是 query embedding 的网络调用。

## 3. 达标判定

- 达标线：**Hit@3 ≥ 80%**。
- E8（最优配置 VECTOR topK=5）：**100.0%，达标**，余量 20pp。
- E8H（生产 HYBRID topK=5）：**96.0%，达标**，余量 16pp。
- 基线 E1（KEYWORD）：90.0%，也高于达标线——说明本评测集对当前知识库整体偏易，达标是**必要条件而非充分条件**，需结合失败样本与偏差说明解读。

## 4. 最优配置与权衡

| 方案 | Hit@3 | 平均/P95 耗时 | 适用判断 |
| --- | ---: | ---: | --- |
| **VECTOR topK=5（本评测最优）** | **100.0%** | 220.8 / 279.7 ms | 以命中率为第一目标时选用；单条 query 需一次 embedding 调用 |
| 生产 HYBRID（k=60+设备1.5+标签1.2，topK=5） | 96.0% | 228.1 / 290.6 ms | 当前已部署配置，比最优低 4pp，但保留关键词精确匹配能力（编号、型号、专有名词场景） |
| KEYWORD topK=5 | 90.0% | 11.1 / 16.4 ms | 延迟敏感或 embedding 不可用时的降级路径，命中率低 10pp |

结论：**在本评测集上，按 Hit@3 排序的最优配置是纯向量检索（topK=5）**；生产 HYBRID 配置达标但非最优，融合权重与 RRF k 的现有取值未带来可测量增益，设备/标签加权应视为“保留但未被本数据集验证”，后续需用真实工单语料复验。

### 归因归纳

- **A 表述不一致（4/10）**：口语现象词与知识库术语不同（断联/通讯中断、喷头/喷嘴、歪/偏斜、翘起来/立碑），关键词的 2-gram 无交集，向量虽能覆盖部分语义，但在同设备多条目竞争时排序下滑。
- **B 缺失设备字段（4/10）**：query 不含设备名，跨设备近邻条目抢占 top3；这是丢失字段的必然代价，也是真实工单的高频形态。
- **C 同设备内相近故障（2/10）**：位置偏/印刷偏移/立碑/抛料等故障在语义空间距离很近，需要更强的判别特征（如“锡膏”“元件”“板”等对象词）。
- **D 重复条目挤占（1/10）**：历史重复知识未清理，两个同名“回流焊炉温失控”同时进入前 3。

### 可优化方向（下一步）

1. 知识治理：清理 5 条测试残留与同名重复条目，预计可直接修复 D 类失败并减少排序噪声。
2. 查询理解：对缺设备字段的 query 做设备槽位推断（结合用户画像/工位/近期工单），再做设备过滤或加权，B 类失败有明确改善空间。
3. 术语映射：维护“口语词→知识术语”同义词表（喷头→喷嘴、断联→通讯中断、翘起来→立碑），在关键词路做查询扩展。
4. 融合策略：关键词一路降权（如 RRF 权重 0.3~0.5）或仅在专有名词命中时启用，避免当前等权融合拉低向量排序。
5. 评测扩充：引入真实已关单工单文本与未登录表述，降低“query 由知识反推”带来的乐观偏差。

## 6. 论文“实验与分析”段落草稿

> 为验证知识检索链路中各设计环节的贡献，本文构造了 100 条查询的评测集，覆盖 54 个已发布知识点、7 类设备与 52 个故障主题，其中 46% 为口语化、含噪声或缺失设备字段的困难表述。评测以 Hit@3 为主指标（返回前 3 条命中任一标准答案即视为命中），辅以 Recall@5、MRR 与端到端耗时，全部采用标准答案匹配，不使用模型打分。
>
> 消融结果如表 X 所示。仅使用关键词检索（MySQL FULLTEXT ngram）时 Hit@3 为 90.0%，改用向量检索（embedding-3 + Milvus HNSW/COSINE）提升至 100.0%（+10.0pp），平均耗时由 11.1ms 增至 218.3ms，说明语义向量对口语化、缺字段表述的泛化能力显著优于词面匹配，代价是约 20 倍的检索延迟。在向量与关键词之上引入 RRF 融合（k=60）后 Hit@3 回落至 96.0%（−4.0pp），说明在当前 54 条知识规模下，等权融合会让关键词一路的同设备近邻条目挤占向量排序的前列；进一步引入设备类型加权（×1.5）与标签加权（×1.2）后 Hit@3 保持 96.0%（0.0pp），MRR 由 0.943 降至 0.929，未观察到正收益；将 RRF k 在 30/60/100 间调整，三项指标完全一致，表明该参数在当前候选规模下不敏感。检索深度方面，topK=1/3/5 对应的 Hit 分别为 90.0%/96.0%/99.0%，说明前 3 条之外的补充结果仍有 3pp 的边际收益。
>
> 综合命中率与延迟，本评测集上的最优配置为纯向量检索（topK=5），Hit@3 达 100.0%，平均耗时 220.8ms、P95 279.7ms；当前生产使用的 HYBRID 配置（k=60、设备 1.5、标签 1.2）Hit@3 为 96.0%、P95 290.6ms，同样满足 80% 的达标线，但未超过纯向量方案。对 10 条未命中样本的归因显示，失败集中在口语术语与知识术语不一致（4/10）、缺失设备字段导致跨设备混淆（4/10）、同设备相近故障混淆（2/10），以及同名重复条目挤占（1/10）。据此，后续优化应优先做知识去重与术语同义扩展，并对缺失设备字段的查询引入槽位推断，而非继续调整融合权重。

## 9. 局限性

1. 知识库仅 54 个知识点，任务偏易，E1 已达 90%，存在天花板效应，各轮差异主要出现在困难表述与并列边界。
2. 评测 query 由知识正文反推，向量检索被系统性有利；结论需用真实工单语料复验。
3. E3/E4/E6/E7 为同一候选快照上的离线复算，虽与生产接口前 3 一致率 94%，仍不能完全等价于真实请求（并列排序差异）。
4. 单机单租户、单次快照、100 条样本，P95 的置信区间较宽；未做跨租户隔离与并发压力测试（并发性能见 M4 压测报告）。
