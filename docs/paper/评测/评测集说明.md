## 2. 构造方法

采用**规则模板拼接 + 人工撰写现象词表**，未调用 LLM（不产生生成成本，结果可复现）。

生成脚本：[scripts/eval/gen_eval_set.py](../../../scripts/eval/gen_eval_set.py)

| 步骤 | 做法 |
| --- | --- |
| 故障短语抽取 | 从知识标题剥离设备名前缀与“处理/故障/维修/SOP”等后缀，得到故障短语（如“贴片机吸嘴堵塞处理”→“吸嘴堵塞”） |
| 正式 query（54 条） | 模板：“{设备}{故障}怎么处理 / {设备}出现{故障}应该如何排查 / {设备}{故障}的解决方法”，每个知识点 1 条 |
| 困难 query（46 条） | 人工为 52 个故障短语撰写“车间现象描述”（如“吸嘴堵塞”→“吸嘴吸不住元件，像是堵了”），再套用口语/噪声/缺字段三种模板，**尽量不使用标题原词** |
| 分配策略 | 按设备类型轮转抽取 46 个知识点，风格按 colloquial / noisy / missing 轮转；故障描述有歧义时 automatic 降级为 noisy |

### 风格定义

| 风格 | 条数 | 模板示例 |
| --- | --- | --- |
| formal | 54 | 蚀刻机蚀刻不均怎么处理 |
| colloquial（口语化） | 16 | 车间那台涂布机，涂层表面冒泡，咋整啊 |
| noisy（含噪声/急单语气） | 15 | AOI检测机跟上位机断联了，数据传不过去！！！在线等，挺急的 |
| missing（缺失设备字段） | 15 | 最近板子边上一圈没涂上，咋解决 |

**困难表述占比 46%**，满足“至少 1/3 为口语化、含噪声或字段缺失”的要求。

## 4. 已知偏差（如实记录）

1. **query 偏理想化**：所有 query 均由知识正文/标题反推，词汇与知识表述重合度高，语义贴近原文；真实工单常包含知识库未覆盖的新表述、方言、错别字与跨设备多故障描述。因此向量检索在本评测集上被系统性有利，结论外推需谨慎。
2. **知识库规模小**：仅 54 个知识点，检索任务本身偏简单，各模式容易出现指标天花板（详见报告）。
3. **模板化口语**：口语/噪声 query 由模板生成，句式和噪声类型有限，不能完全代表真人口语分布。
4. **干扰项构成**：5 条测试残留与 2 组同名重复条目未被清理，会挤占 top3 名额，属真实系统状态而非人为加难。
5. **缺设备字段 query 的歧义**：15 条 missing query 仅使用现象描述，部分现象（如“位置偏”“温度不稳”）在多个设备上语义相近，失败可能来自跨设备混淆而非检索能力不足。
6. **未覆盖**：多故障混合描述、长工单上下文、图片/条码等非文本输入、跨租户数据隔离场景。
