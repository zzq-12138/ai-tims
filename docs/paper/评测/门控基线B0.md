## 二、门控实现（代码与配置）

### 2.1 配置（`ticket-knowledge/src/main/resources/application.yml`）

```yaml
tims:
  kb:
    gate:
      enabled: ${KB_GATE_ENABLED:true}          # 一键回滚：false 即恢复"无门控全返回"
      threshold: ${KB_GATE_THRESHOLD:0.75}      # 低于此值 → tier=C
      soft-band: ${KB_GATE_SOFT_BAND:0.07}      # [T, T+0.07) → tier=B
      fallback-tiers: ${KB_GATE_FALLBACK_TIERS:true}  # 向量降级/无向量分时保留结果，计 B
```

### 2.2 三档语义（`SearchService.search()`）

| tier | 判定 | 返回 | reason 示例 |
|---|---|---|---|
| A | `maxVectorScore ≥ T+soft-band`（≥0.82） | 方案正常返回 | `top1 余弦 0.8341 ≥ 软带上限 0.82` |
| B | `T ≤ maxVectorScore < T+soft-band` | 方案返回，标注"仅供参考" | `top1 余弦 0.7865 位于软带 [0.75, 0.82)，结果仅供参考` |
| C | `maxVectorScore < T` | **`items=[]`，`total=0`**，保留 `maxVectorScore` 供诊断 | `top1 余弦 0.7127 < 阈值 0.75，知识库无可用案例` |

补充规则：
- `KEYWORD` 模式不参与向量门控（`tier=A`，原行为不变）。
- `VECTOR/HYBRID` 向量降级或候选为空（`maxVectorScore=null`）时，`fallback-tiers=true` → `tier=B` 并保留结果（故障时不会把用户变成"零结果"）；设 `false` 则 `tier=C`。
- 门控判据是**返回条目中的最高余弦**（`maxVectorScore`）。VECTOR 模式下等于 top1 余弦；HYBRID 下是 RRF TopK 内条目的最高余弦（不是候选池全局 top1，见局限）。

### 2.3 返回体（只增不改）

```json
{"query":"...","mode":"HYBRID","fallback":false,
 "gateEnabled":true,"gateThreshold":0.75,"maxVectorScore":0.7865,
 "tier":"B","reason":"top1 余弦 0.7865 位于软带 [0.75, 0.82)，结果仅供参考",
 "total":5,
 "items":[{"id":"...","score":0.0332,"rrfScore":0.0332,"vectorScore":0.7865, "...":"..."}]}
```

- `vectorScore`：仅 VECTOR/HYBRID 有值；KEYWORD 为 `null`。
- `rrfScore`：仅 HYBRID 且未降级时有值（与 `score` 相同），其余 `null`；`score` 语义保持不变（VECTOR=余弦、HYBRID=RRF、KEYWORD=全文分）。

## 六、行为变化与风险（重点：现在会不会"该推的不推"）

1. **会。这是门控的设计后果，不是 bug。** 23 条正例（23%）在 0.75 被判 C 返回空列表，其中 **16 条原始 top1 本来正确**（占全部正例 16%）。这 16 条全部是口语化/低分同义改写（例："最近废液排不出去，一直报警，咋解决" 0.5886、"最近有不良品没检出来，咋解决" 0.5226）。
   - 影响面：前端若只渲染 `items`，这些查询从"有答案"变成"无结果"；但 `tier=C` 与 `reason` 已给出可解释文案，可引导用户补充设备型号/现象。
2. **空列表 + 可解释 reason 是新增契约**：`total=0` 与 `tier=C` 必须被前端识别；否则会把"知识库确实没有"与"接口异常"混为一谈。
3. **KEYWORD 模式不受门控**：仍返回低置信结果、`tier=A`。若某调用方切到 KEYWORD，门控形同虚设。
4. **降级不误伤**：Milvus/embedding 不可用时 `fallback=true`、`tier=B`，结果照常返回并标注仅供参考（`fallback-tiers=true`）。只有显式设 `false` 才会在故障时返回 C。
5. **回滚**：`KB_GATE_ENABLED=false` + 重启（或修改 yml）即回到"无门控全返回"，返回体仍带新字段（`tier=A`、`maxVectorScore` 照常透出），无需回滚数据。
6. **数据侧不可逆动作**：6 条知识为逻辑删除，可 `deleted=0` 恢复；Milvus 残留向量已物理删除，恢复记录后需等向量同步重建（`vector_synced_at` 置空即可）。

## 七、局限

1. **评测集规模 100+100+100**，正例以 formal/口语混合构造；C 档误挡集中在口语化改写，说明"余弦阈值 + 中文口语短句"本身有系统性上限（中位 0.783、p25 0.756）。
2. **`maxVectorScore` 是"返回条目中的最高余弦"**：HYBRID 下候选池 Top10 里若高余弦条目被 RRF 排出 Top5，门控会低估置信度（本轮 HYBRID/VECTOR 的 A/B/C 分布完全一致，未观察到实际影响，但结构性风险存在）。
3. **HYBRID 的 top1 是 RRF 序**，不是余弦序；0.75 下 2 条正例"错误"是因为 gold 被 RRF 排到第 2，门控无法修正排序。
4. **LG 采集在门控关闭下执行**（需拿到原始 top1），门控判定离线复算；已在 0.75 点验证与线上实测 0 条不一致，但 LG 的 `tier` 不是线上直接产出。
5. **B 档算作"推送"**：虽然 UI 语义是"仅供参考"，本文所有推送率/错误率都把 B 计入分母；若产品把 B 视作不推送，错误推送率会显著变化（需在论文口径中明确）。
6. **延迟是单机单实例、串行 200 次请求的口径**，未做并发压测；不含网关与鉴权开销。
