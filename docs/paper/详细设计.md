## 1. 设计目标与原则

1. **按业务域拆分六微服务**：gateway / system / order / push / knowledge / ai + common（K01）。
2. **共享库共享表 + tenant_id 隔离**：不按租户分库，降低单节点运维成本（K02）。
3. **状态机以常量迁移表为唯一事实来源**，禁止散落 if-else（K05）。
4. **先保证可降级**：MQ、推送、检索、AI 均有降级路径，失败不阻塞主流程（K19/K28/K32）。
5. **AI 异步、可审核、可回溯**：抽取不阻塞工单提交，结果先入 `ai_extracted`，人工审核后才进知识库。
6. **单节点 k3s 的容量自觉**：资源配额、镜像离线交付、监控瘦身（K09–K11/K43）。
- 素材：`关键技术点.md` 一、七；`决策台账.md` DEC-13 等；`开发计划与进度.md` §2。

## 5. 关键流程详细设计（每节建议 1 张时序图/活动图）

### 5.1 登录与租户上下文
登录 → Sa-Token 写 Redis → 网关校验 → 剥离外部租户头 → 回填可信租户 → 下游 `TenantContext`。
- 素材：K12/K13；`AuthController`；`ai-tims-common`。

### 5.2 工单状态机与并发控制
常量迁移表校验 → `version` 乐观锁更新 → 写 `wo_ticket_flow` → 四时间戳。
- 素材：K05/K18/K21；`TicketController`；`wo_ticket_flow`。

### 5.3 自动派发
4/2/1 加权打分（技能/负载/历史? 具体维度待确认）→ 选人 → 写派发记录 → 推送。
- 素材：K06；`wo_dispatch_rule`。
- **缺口：4/2/1 三个维度的准确定义与权重依据（G-05）**。

### 5.4 关闭事件与 MQ
关闭事务提交 → afterCommit 发送 → confirm → 消费端幂等 → 失败重试/DLX → 三级降级。
- 素材：K19/K20；`ticket-order` 事件发送、`ticket-knowledge` 消费。

### 5.5 实时推送
WS 鉴权 → 在线表 → 推送 → 落库；离线补推；空卡片兜底；冷启动预热。
- 素材：K30–K33；`ps_push_*`。

### 5.6 知识检索与门控
query 预处理（查询侧 instruction）→ 向量/关键词/混合 → RRF(k=60)+加权 1.5/1.2 → topK → 门控 A/B/C → C 档清空 items → 返回 `maxVectorScore/tier/reason`。
- 素材：K22–K28；`SearchController`；`检索与门控_章节正文.md` §5.3.1–5.3.5；`评测/Qwen3Embedding门控阈值实测结果.md`。
- 注意：`score` 是 RRF 融合分，不能当余弦阈值；门控看 `maxVectorScore`。

### 5.7 三步链式抽取
关闭事件 → 第 1 步现象 → 第 2 步根因/验证/排除 → 第 3 步措施/条件 → 逐步校验（JSON+schema/证据回溯/反向项）→ `ai_extracted`（含 `chain_trace`）。
- 素材：`创新点.md` §X.2；`问题二/链式抽取/链式抽取评测.md`；`ticket-ai` ExtractionController；`ai_extracted`。

### 5.8 去重、冲突判别与条件化入库
BGE-M3 余弦召回（仅特征）→ 结构化规则 → 条件互斥 → 灰区 LLM 复核 → duplicate/conflict/variant/unrelated → 审核 → `kb_knowledge` + Milvus 同步。
- 素材：`问题二/关系判别/关系判别评测.md`；`研究方向/标注手册_v1.md` §5；`kb_knowledge`/`kb_knowledge_history`；`ticket-knowledge` 同步任务。
- 口径：三关系为**设计/离线评测**，生产判别器未全量接入（M-028）。

### 5.9 审核与发布
`ai_extracted` 待审 → 人工审核 → 写知识库 → 向量同步 → 状态 PUBLISHED；驳回留痕。
- 素材：K23/K29；`KnowledgeController`；`ai_extracted`/`kb_knowledge_history`。
