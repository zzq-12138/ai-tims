## 一、8.5pp / 4pp 的完整拆解

### 1.1 指标与口径先写清楚

| 项 | 口径 |
|---|---|
| 指标 | **根因槽位一致率**（判等方式：字符 bigram Dice ≥ 0.55 或包含关系且长度比 ≥ 0.6） |
| 平均 Dice | 另一条指标（`root_dice_mean`），与上面的「一致率」不是同一个数，**不得混写** |
| 数据 | 200 条**跨模板留出集**（模板与训练集不重叠，仍未进入训练） |
| S1 | glm-4-flash 单轮零样本提示词（现网基线） |
| S2 | S1 + 规则与提示工程（推理链终点定位、槽位/单位/设备名规范化校验、排除假设黑名单） |
| S3 | S2 + Qwen-7B LoRA（r=16，1000 条 × 3 epoch） |

主结果：

| 方法 | 根因一致率 | 平均 Dice | 相对上一档 |
|---|---:|---:|---:|
| S1 | 86.5% | 0.873 | — |
| S2 | 95.0% | 0.953 | **+8.5pp** |
| S3 | 99.0% | 0.989 | **+4.0pp** |

> 注：86.5% / 95.0% / 99.0% 是**一致率**（`metrics.json` 的 `root_match`），不是平均 Dice；
> 平均 Dice 为 0.873 / 0.953 / 0.989。若论文写「Dice 99.0%」属指标名与数值错配。

**一句话口径**：在同一 200 条跨模板留出集上，根因一致率由 86.5%（S1）提升至 95.0%（S2）、99.0%（S3）；其中 **8.5pp 来自规则与提示工程，4.0pp 来自 LoRA 微调**。

### 1.2 8.5pp 来自哪里：规则 + 提示工程（S1→S2）

这 8.5pp 的本质是把「过程叙述」压成「结论句」，不涉及任何参数更新：

1. **推理链终点定位**：识别「最终确认」句，与「怀疑/待查/先怀疑 A」区分，避免把排查途中的猜测当成根因。
2. **槽位与单位校验**：对根因、措施做字段级规范化与空值兜底，减少格式漂移导致的整条判错。
3. **排除假设黑名单**：被明确排除的原因不得再写入根因槽位。
4. **提示工程**：把工单按段落角色组织后输入，减少整单截断造成的信息丢失。

> **可写**：8.5pp 是「规则 + 提示工程」的组合增益。
> **不可写**：把 8.5pp 拆分到某一条具体规则上——目前**没有单规则消融**，拆分会变成编造。

### 1.3 4pp 来自哪里：LoRA 微调（S2→S3）

**先纠正一处归因**：任务给的三个观察点里，**只有措施 F1 属于 S2→S3 的微调增益**；排除假设检出率在 **S2 就已到 100%**，`no_final` 留空在 **S2 也已到 100%**，这两项都属 S1→S2 的规则增益，微调增量为 0。依据 `S3评测/metrics.json`：`excl_detect` = 68.8（S1）→ 100.0（S2）→ 100.0（S3）；`meas_f1` = 0.944（S1）→ **0.944（S2）**→ 0.990（S3）。

| 观察点 | 起点 | S2 | S3 | 归属 |
|---|---|---:|---:|---|
| `no_final` 20 条（真值无最终根因） | S1 **20/20 编造根因** | **100% 判「无法确定」** | 100% 判「无法确定」 | **S1→S2（规则）**；微调增量 0（S2 代价：normal 切片 5 条误清空） |
| 排除假设检出率（`excl_detect`） | S1 68.8% | **100%** | **100%** | **S1→S2（规则）**；微调增量 0 |
| 措施 F1（`meas_f1`） | S1 0.944 | **0.944（与 S1 逐条相同 174/200）** | **0.990** | **S2→S3（微调独有，+0.046）** |

三点解释（已按上表更正）：

- **`no_final` 是最强行为证据，但不是微调的证据**：S1 在「不该抽根因」的样本上 20 条全错，S2 靠「空根因 ⇒ has_final=0」的显式规则即可全部留空；S3 的价值在于**同时保住 normal 切片**（S2 在 normal 上从 96.7% 掉到 94.2%，误清空 5 条），这才是 4pp 里能被归到微调的那部分。
- **排除假设召回不是微调解决的**：规则里「排除 X 一律进 `excluded_hypotheses`」是可执行指令，S2 已满分（条目 F1 1.000，误抽 0），S3 无额外增益。
- **措施 F1 0.944→0.990 是唯一纯微调增益**：S2 与 S1 的措施输出在 174/200 条上逐字相同，说明「不要拆条目」这类指令对基座无效；微调学到的是 **条目切分边界**（wechat 0.871→0.985），属格式对齐而非知识增量。

### 1.4 推荐给论文的叙述顺序

1. **先给主表**（S1/S2/S3 的根因一致率 + 平均 Dice），一句话给结论。
2. **再拆 8.5pp**：规则与提示工程解决的是「终点定位 + 格式稳定 + 负例排除」，不改变模型参数，因此可以单独作为 S2 线上兜底方案。
3. **再拆 4pp**：微调独有增益是「措施条目边界」与「保住 normal 切片不误清空」，用 1.3 的措施 F1 行与 S2 的 5 条误清空支撑；**排除假设召回与 no_final 留空是规则解决的，不要记到微调头上**。
4. **最后给边界**：99% 是合成跨模板留出集上的一致率；4pp 建立在 95% 高基线上，存在天花板效应，因此「微调贡献 4pp」不等于「微调只值 4pp」——在不该抽根因、措施切分上的行为收益大于分数收益。

## 二、三项方法落地状态（论文措辞版）

### 2.3 可直接引用的段落（按需取用）

**（1）系统实现现状段（放「系统实现」或「方法落地」小节）**

> 本文的系统实现覆盖三条链路：工单关闭事件的异步抽取、抽取结果的人工审核与知识入库、以及入库前的候选召回。抽取默认采用单轮提示词生成结构化字段，可由 `tims.ai.extract.chain-enabled` 切换为三步链式抽取（默认关闭）。审核环节强制人工确认，入库前的候选召回给出相似度与关系判别结论：结构化条件与根因齐全时按规则判 duplicate / variant / conflict / unrelated，字段不全或落灰区时退回余弦三分档；审核通过后按条件分支写入根因、验证与适用条件四列。需要说明的是，本文评测所用的五元组 Schema、四类关系判别集与条件五类标注仍属离线实验管线，**检索侧的条件过滤尚未实现**。

**（2）方法—实现边界段（放「实验设置」或「局限」）**

> 为避免将实验管线能力误读为系统能力，本文明确区分两层：离线实验管线负责五元组抽取评测、关系判别集构建与条件标注；现网服务负责字段抽取（单轮或开关控制的链式）、关系判别建议与人工审核入库。二者共享同一批工单文本与构造真值。边界在于：现网**没有**训练过的四类关系分类模型（落地的是规则判别 + 余弦兜底），也**没有**检索侧的条件过滤（向量检索仍只按租户过滤）。

**（3）局限段（放讨论）**

> 本文存在三点实现层面的局限：其一，链式抽取、关系判别与条件入库均已在服务端实现，但链式链路默认关闭，S1/S2/S3 的对比数字仍来自离线管线；其二，关系判别采用规则而非训练模型，条件或根因字段缺失时退回余弦，300 对构造集尚无生产 macro-F1；其三，适用条件已进入表结构与入库分支，但检索侧条件过滤未实现（Milvus 现有 collection 不支持在线加字段，方案 A/B 待编码）。上述三点不改变已报告的 S1/S2/S3 抽取数字，但限制了本文对「端到端知识治理」的主张范围。
