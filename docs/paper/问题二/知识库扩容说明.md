## 3. 字段定义

`content` 固定 7 段，段名固定、顺序固定，便于规则解析与评测对齐：

```
故障现象：<可观测表征，含量化阈值>
可能原因（根因）：<机理级根因，非“操作不当”式结论>
区分依据：<与同现象其他根因的区分方法/测量点>
处理步骤：1) ...；2) ...；3) ...；4) ...
预防措施：<周期/阈值/责任人可执行项>
验证结果：<复测指标 + 判定阈值 + 观察时长/样本量>
适用条件：适用机型：...；软件/固件：...；来料/工艺批次：...；工况：...
```

| 字段 | CSV 列 | 库内位置 | 约束 |
| --- | --- | --- | --- |
| 现象 | `symptom` | content 第 1 段 | 非空，含阈值 |
| 原因（根因） | `root_cause` | content 第 2 段 | 非空，机理描述 |
| 区分依据 | `discrimination` | content 第 3 段 | 非空（判 A/B/C 用） |
| 处置步骤 | `steps` | content 第 4 段 | 非空，3–5 步 |
| 预防 | `prevention` | content 第 5 段 | 非空，可执行 |
| 验证结果 | `verification` | content 第 6 段 | 非空，含指标与阈值 |
| 适用条件 | `conditions` | content 第 7 段 | 非空，四要素（机型/固件/批次/工况）齐全 |
| 来源标注 | `source_tier` / `source_ref` | `tags` + CSV 列 | 三选一，如实标 |
| 成组关系 | `cluster_key` / `cluster_type` | `tags` 的 `cluster:*` | 见第 4 节 |

`tags` 示例：`["贴片机","视觉光学","tier:SYNTHETIC","cluster:SIM-PM-01","theme:T11"]`。
`summary` ≤200 字，由标题 + 根因 + 验证指标生成，供列表展示与向量文本使用。

## 4. 成组设计（问题二三关系判别用）

- **同象异因**（`cluster_type = same_symptom_diff_cause`，`cluster_key = SIM-<设备码>-NN`）：
  一组共享同一 `symptom` 文本，成员的 `root_cause` 各不相同。典型：贴装偏移可来自锡膏印刷偏移、视觉标定漂移、轨道夹持松动、炉温翘曲。
- **同因异象**（`cluster_type = same_cause_diff_symptom`，`cluster_key = SIC-<设备码>-NN`）：
  一组共享同一 `root_cause` 文本，成员的 `symptom` 各不相同。典型：同一「供料器齿轮磨损」可表现为抛料、送料不到位、贴装偏移。
- 规模：每设备 5 组 SIM + 5 组 SIC，组大小分布 3/3/3/2/2，合计 13 条 SIM + 13 条 SIC = 26 条入组，另 5 条独立（用于负样本/干扰项）。
- 全局：**SIM 50 组 / SIC 50 组**，入组 260 条、独立 50 条，满足「各 ≥40 组」。
- 成组明细：`docs/paper/问题二/kb_310_clusters.json`（组键、类型、共享现象/原因、成员键与标题）。
- 注意：SIM 组成员的 `symptom` 被统一改写为组内共享表述，SIC 组成员的 `root_cause` 同理；原文语义保留在其余字段，便于构造"现象相同、根因不同"的对照样本。

## 7. 对 M7 评测集的影响（必须重跑）

- 现有 M7 评测集是 **100 条、基于旧 54 条唯一知识点**构建的：负样本与近邻干扰项都取自旧库。
- 扩容后候选池从 54 → 310（同设备内 10 → 31），top-k 的命中分布、近似重复干扰、指标分母都会变化。
- 结论：**扩容后 M7 的全部指标（检索 Recall@k / MRR、抽取字段 F1、A/B/C 判别准确率）必须整批重跑，旧结果不可与新库结果混用或直接对比。**
- 重跑前需确认：`kb_310.csv` 版本、Milvus 条数 310、评测脚本的知识 ID 映射已按新库刷新；评测集若继续沿用 100 条，需重新核对其中引用的知识点 ID 是否仍存在（SEED 保留原 ID，SYNTHETIC 为 `3100000000000000001` 起的新 ID）。
