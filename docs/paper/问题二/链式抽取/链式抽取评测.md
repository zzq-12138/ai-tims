## 口径说明

- 现象/根因/验证：dice≥0.55 或包含关系（短串占比≥0.6）记匹配。
- 措施：条目级贪心匹配，dice≥0.5 记命中，汇总为微平均 P/R/F1。
- 适用条件：同 type 下值做包含/近似匹配（dice≥0.6），避免「LAM-600」与「3 号线贴合机 / LAM-600」被判错。
- 排除假设三种口径不可混用：① 样本检出率分母是「原文确有排除假设」的 80 条，不是全部 200 条；② 条目 micro P/R/F1 的分子分母是条目数（TP/FP/FN）；③ 样本宏平均 F1 的分母是「任一侧非空」的样本，纯 FP 样本按 0 计入。
- 无最终根因的工单若抽出根因，计入「误填率」；验证方式与维修动作同源时按误归因清空并留痕。

|---|---|---|---:|---:|
| 样本检出率 | 检出样本数 80 | **原文确有排除假设的样本 80** | 40.0%（误用 200 作分母） | **100.0%** |

### 与规则档同口径对比

| 方案 | 样本检出率（80 条） | 条目精确率 | 条目召回 | 条目 F1 | 样本宏 F1 |
|---|---:|---:|---:|---:|---:|
| S2 规则（`S3评测/metrics.json`） | 100.0% | 1.000 | 1.000 | 1.000 | 1.000 |
| 链式三步（本表） | 100.0% | 0.826 | 1.000 | 0.905 | 0.816 |

> **口径同源说明：这张表是“口径一致性对比”，不是“能力对比”**
>
> 规则档三项全是 1.000，主要原因是它与构造真值同源，而不是它在真实噪声表述上也这么准。链式的 0.826 是**没有对齐 gold 标注边界**时的表现。两者不能直接换算成能力高低。
>
> 同源程度可量化，不是定性猜测（对照 `scripts/annotation/gen_heldout_cross_template.py` 与 `S3评测/eval_s2.py`）：
>
> | 同源维度 | 证据 | 同源程度 |
> |---|---|---|
> | gold 条目与触发句同源 | 生成器在写正文的同一循环里直接赋值 `excluded_hypotheses=[{hypothesis: s["alt"]}]`，`s["alt"]` 同时被插进正文模板 | **100/100 条** gold 的 hypothesis 在正文中逐字出现（子串命中） |
> | gold 条数由模板计划决定 | `make_plan` 每设备 12 条 excluded + 4 条 no_final → 60×1 + 20×2 | **100 条**，与 `metrics.json` 的 `excl_gold_items=100` 完全一致，不是从文本读出来的 |
> | 触发句式共享 | S2 提示词第 2 条写「排除 X」「按 X 方向排查/处置后无改善」；生成器模板为「按{alt}方向排查，…复测无改善，排除{alt}」（dispatch）、「按{alt}方向处置，…复测无改善，排除{alt}」（logbook） | 6/6 模板含字面「排除{alt}」；4/6 模板三信号（方向 + 无改善 + 排除）全中；wechat 2/6 用「还是那样/没用」，靠「排除」单词即可命中 |
> | 样本侧无错配 | 200 条中 **80 条**正文含字面「排除」，与 gold>0 的 80 条完全重合 | 无漏标、无多标 |
>
> 口径含义：S2 的 1.000 主要证明「规则提示词准确复述了构造模板的句式」，不证明「在真实工单的不规则表述上也能到 1.000」；链式 0.826 的 21 条 FP 里，13 条是 prompt 可修的边界过宽，8 条是构造 gold 的标注口径比模型更窄——后者恰好说明链式在未对齐标注边界时的自然表现。因此正确表述是「在构造口径下规则档更贴合真值」。

**结论：链式路线在排除假设上检出持平、条目精确率低于规则档**（0.826 vs 1.000，后者含构造口径同源成分），不能说“链式全面优于规则”。

### 21 条 FP 的逐条归类（用现有 predictions 统计，未新跑模型）

| 类型 | 条数 | 说明 |
|---|---:|---|
| 「初步方向：按 X 方向排查」 | 10 | 原文只写初步排查方向，没写“无改善”，模型仍当排除假设（过度触发） |
| 原文无排除语句、模型反推 | 8 | 如原文“胶层厚度实测均匀”，模型写“胶层厚度不均匀”作为被排除假设；语义成立但 gold 未按此口径标注 |
| 把“X 正常/合格”直接写进 hypothesis | 3 | 表述错误，应写被排除的 X 异常而非核查结论本身 |

- 不是“第 2 步被根因抢注意力”：80/80 样本都抽出了排除假设，检出没有损失。
- 错误集中在「什么算排除」的判定边界：13/21（10 过度触发 + 3 表述错误）属于 prompt 可修，8/21 属于构造 gold 的标注口径比模型更窄，需在论文里明说。

## 适用条件为什么只有 0.536（按类型拆解）

| 条件类型 | gold 条数 | 预测条数 | 命中 | 召回 |
|---|---:|---:|---:|---:|
| device_model | 200 | 200 | 200 | **1.000** |
| process_stage | 72 | 171 | 21 | 0.292 |
| param_range | 131 | 167 | 51 | 0.389 |
| material_or_batch | 11 | 12 | 0 | 0.000 |
| precondition | 27 | 7 | 0 | 0.000 |

失败原因（逐条核对预测与真值后归纳）：

1. **device_model 已解决**：留出集里微信风格正文不含型号，型号只存在于工单元数据。第 3 步输入补「工单元数据：设备型号 / 故障码」后，device_model 召回由 0 升到 1.000；该元数据只喂第 3 步，避免污染第 1/2 步的「以原文为准」判定。
2. **process_stage 过度抽取**：gold 72 条、预测 171 条，模型把「取料后/贴合后/调整后」这类时序词也写成工序，召回 0.292。已加「写工序/工步名称，不写时序词」的约束，仍未根治，需要工序词表约束或后处理白名单。
3. **param_range 的真值口径是「变化量/前后值」**：gold 形如 `温度 ±8℃`、`二段 105→88℃`、`误报 2%→9%`、`Ra 0.4→1.2μm`，而模型输出的是单点实测值（`烘箱二段温度显示 105℃，实测 88℃`）。两者语义相近但字面不同，按 dice≥0.6 严格匹配即判错；这部分是**真值 schema 与抽取 schema 不一致**，需要在 P2 统一为「参数名 + 前值 + 后值 + 单位」四元结构。
4. **precondition / material_or_batch 几乎不抽**：gold 分别 27 / 11 条，模型只输出 7 / 12 条且 0 命中，属于低资源类型，需在 prompt 里给正例或改为规则兜底。

> 口径演进留痕（均为同一 200 条留出集）：第 2 版 prompt 未区分「故障时条件」与「维修后目标值」，条件 F1 = 0.337；
> 第 3 版明确「只取故障发生时状态、禁止写入维修后目标值与占位值」后 0.431；
> 第 5 版把设备型号元数据只注入第 3 步后 0.536（device_model 1.000，其余类型仍低）。
> 三次改动没有动第 1/2 步输入，因此现象/根因/验证指标保持可比：根因 90.0%、验证 95.5%、措施 F1 0.953。

## 局限

1. 真值为构造真值，非人工标注；指标是与构造真值的一致性，不能表述为人工标注准确率。
2. 留出集为模板合成语料，长度与段落标签较规整，真实工单的口语化与信息缺失会进一步拉低指标。
3. 验证方式与适用条件在构造真值里本身较短，抽取粒度差异会放大字面指标误差。
4. 仅用 glm-4-flash 单模型、单次采样，未做多次采样方差估计。

## 复核阶段的两项指标：字段采纳率与必备字段完整率（理论定义，待真实数据）

> 状态：**已定义、待真实数据验证**。本节只给定义、公式、成立前提与测量方案，**不报任何示例数字**。原因见本节第 4 小节。

### 1. 为什么单列这两项
现有分步指标（现象/根因/验证/措施/条件）衡量的是「模型输出与构造真值的一致性」；这两项衡量的是「抽取结果交给人复核时，人要不要改、能不能直接入库」，属于人机协同的可用性指标。它们不能替代 P/R/F1，也不能由 P/R/F1 推导。

### 2. 字段采纳率（Field Adoption Rate, FAR）

**定义**：在复核环节，对抽取结果已输出的字段逐字段判断「原样采纳」还是「人工修改（含改写、删除）」，被采纳字段占已输出字段总数的比例。

**计数单元**：字段-记录对。同一字段被改多次按 1 个「被改字段」计；复核时新增的字段不计入分母，另记「补录率」。

**公式**：
- 字段修改率 `r_mod = M / F`
- 字段采纳率 `r_adopt = 1 − r_mod = (F − M) / F`

其中 `F = Σ_e F_e` 为复核记录中抽取已输出字段总数，`M = Σ_e M_e` 为其中被人工修改或删除的字段数。**若论文只报修改比例，必须叫「字段修改率」，不能叫「采纳率」；两者互为补数，只报一个。**

**报法**：micro（先汇总 F、M 再算，主口径）+ macro（每条记录先算再平均，辅助）。

**为什么能反映抽取质量**：人工修改是语义正确性的直接代理——字面不同但语义正确的字段不会被改；它把「能不能直接用」变成可计数行为，并且对长尾字段敏感，能暴露 P/R/F1 掩盖的可用性问题。

**成立前提**：
1. 复核表单字段集合与抽取 schema 一一对应，测量期内口径不变；
2. 复核人按同一份《字段填写规范》操作，事前培训；抽 20% 双人复核并报告 Cohen's κ；
3. 复核是真实动作而非「全选通过」，必须记录逐字段 diff，不能只存最终文本；
4. 分母只含「抽取实际输出的字段」；对「本应为空」的字段（如无最终根因）不纳入，否则正确留空会被误判为缺失；
5. 「整条驳回」不折算成字段修改，单独记「整条驳回率」。

**会失真的情形**：合成样本 + 自动生成真值（抽取与真值同模板，修改数趋近 0）；复核被暂停或走过场；字段集合中途增删；不同复核人对「修改」的粒度判定不同。

### 3. 必备字段完整率（Required Field Completeness, RFC）

**定义**：一条抽取结果中，业务规定的必备字段「非空且通过基本有效性校验」的数量，占必备字段总数的比例。

**必备字段集合（Q-11 定稿，2026-11-25）**：

| 层级 | 字段 | 依据 | 是否必备 |
|---|---|---|---|
| 知识卡 | `title` | `kb_knowledge.title NOT NULL` | 是 |
| 知识卡 | `content` | `kb_knowledge.content NOT NULL` | 是 |
| 知识卡 | `category_id` | 业务要求；DB 允许 NULL | 是（Q-11 定为必备） |
| 抽取 | `fault_phenomenon` | 五元组入口，缺则无法检索 | 是 |
| 抽取 | `root_cause` | 仅 `has_final_root_cause=1` 时必备 | 条件必备 |
| 抽取 | `solution_steps` | 可执行性核心 | 是 |
| 抽取 | `verification` | 支撑根因可信 | 是（Q-11 定为必备） |
| 抽取 | `apply_conditions` | 条件化知识核心，但允许为空 | 否（另记条件覆盖率） |

**有效性判定**：`trim` 后非空；不是「未知 / 无 / 待补充 / 暂无」等占位；枚举字段在字典内；`category_id` 能在 `kb_category` 命中；标题**不设字数硬阈值**，只判非空、非占位、能区分设备对象与故障。

**公式**：
- micro：`RFC_micro = Σ_i c_i / (N × K)`
- macro：`RFC_macro = (1/N) Σ_i (c_i / K)`

其中 `c_i` 为第 i 条命中的必备字段数，`K` 为必备字段总数（条件必备按 `has_final_root_cause` 展开），`N` 为记录数。

**为什么能反映抽取质量**：必备字段缺失会直接阻断入库、检索与引用；它是「结构可用性」的下限指标，与语义正确性正交，可与字段采纳率互补。

**成立前提**：
1. `K` 在测量前冻结，条件必备字段按 `has_final_root_cause` 展开；
2. 在「抽取输出」上算，不在「人工复核后」算——复核会补齐字段，算在复核后必然接近 100%；
3. 空值语义明确：允许为空的字段不计入 `K`；
4. 占位词表固定；
5. 同一记录多版本取首版（衡量模型），不取人工修订后的版本。

**会失真的情形**：漏掉 `category_id` 这种「DB 可空但业务必备」的字段；用复核后的数据算；把「未知」当非空；合成数据生成器把必备字段全填满。

### 4. 本轮为什么没有实证数字

1. 本轮数据是**自造测试样本**，抽取与真值同源/同模板，字段采纳率会天然接近 100%，不能证明真实准确率；
2. **复核环节已主动暂停**：造数上复核必然全通过，测出来的是「流程能跑」，不是「抽取可用」；
3. 无企业真实工单（2026-11-10 已确认不提供），也没有人工逐字段修改记录；
4. 因此两项只写定义、公式、前提与测量方案，论文中标注「已定义、待真实数据验证」，**不得填任何示例数字**。
