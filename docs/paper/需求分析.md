## 1. 引言

### 1.1 编写目的
说明系统为谁解决什么问题、边界在哪、怎样算验收通过；为详细设计提供可追踪的需求编号（FR/NFR）。

### 1.2 项目背景与问题定义
- 业务背景：中小制造/运维场景的工单靠微信群、Excel、口头交接，处理过程不可追踪，维修经验留在个人手里。
- 三个具体问题（与开题报告一致，直接复用，不另造）：
  1. 工单流转与派发不可追踪；
  2. 维修知识非结构化，检索靠关键词，答非所问；
  3. 知识抽取与入库缺可信校验，容易把「排除项/维修动作」当根因，且知识带条件、会过期。
- 现有素材：`docs/paper/开题报告.md` §1–§3；`docs/paper/创新点.md`；`docs/paper/论文素材总台账.md` M-001/M-002/M-005/M-006。

- 口径来源：`docs/paper/研究方向/标注手册_v1.md` §5；`docs/paper/检索与门控_章节正文.md` §5.3.2；`docs/paper/论文素材总台账.md` M-024。

## 2. 总体描述

### 2.1 产品定位与范围
- 定位：面向中小型运维/售后团队的**工单 + 知识库 + AI 辅助**一体化系统；单租户部署、多租户代码隔离。
- 范围内：认证与租户、工单全生命周期、自动派发、实时推送、知识库与混合检索、知识抽取与审核、AI 对话/回填、观测与用量。
- 范围外（本期不做）：计费、开放平台、移动端原生 App、跨集群容灾。
- 素材：`关键技术点.md` K01/K02；`开发计划与进度.md` §2.2；`ai-tims-front/src/views/` 11 个页面。

### 2.2 用户角色与权限（【待确认】权限矩阵）
| 角色 | 目标 | 主要用例 | 现状 |
|---|---|---|---|
| 报修人 | 快速提单、看进度 | 创建工单、上传附件、查看详情、接收推送 | 已实现 |
| 维修工程师 | 接单、处理、关闭 | 工单列表/详情、评论、状态流转、知识检索 | 已实现 |
| 知识管理员 | 审核抽取结果、维护知识 | 抽取审核、知识增删改、分类管理 | 已实现 |
| 租户管理员 | 管人、管角色、管配额 | 用户/角色/部门、API Key、用量 | 已实现 |
| 系统运维 | 部署、观测、降级 | 监控、日志、降级开关 | 已实现（观测页/运维脚本） |

- 权限模型：Sa-Token + 角色/部门（`sys_user/sys_role/sys_dept`），网关统一 401（K04/K12）。
- 缺口：角色-菜单-按钮的**完整授权矩阵**需从代码/页面反推后由用户确认（见 §8 G-03）。

### 2.3 运行环境
浏览器（Chrome/Edge）；后端六微服务（gateway/system/order/push/knowledge/ai + common）；MySQL、Redis、RabbitMQ、Milvus、对象/本地附件存储、内网 vLLM/智谱 API；k3s 单节点多 Pod。
- 素材：`deploy/`（k8s/kustomize）、`docs/handover/环境与版本对照.md`、`关键技术点.md` K09/K10/K44。

### 2.4 约束与假设
1. 无企业真实工单，评测数据为模拟器/公开手册/受控合成（M-002）。
2. 公司侧模型为内网 Qwen3-Embedding-8B，开发机为 embedding-3，两者余弦不可比（`检索与门控_章节正文.md` §5.3.4）。
3. 抽取异步执行，不阻塞工单提交；单条推理 6–12 s 可接受（M-020）。
4. 公司数据不得外发；论文中不得出现内网地址、账号、密钥（§8 G-07）。
5. 中期前不新增功能，只做文档与演示收口（`开发计划与进度.md` §2.1）。

**数据合规边界（2026-11-25 补，P0）**

可确定（有依据）：

1. **数据来源**：不使用企业真实工单；企业已确认不提供、无脱敏版本、无导出授权（`决策台账.md` DEC-29、`论文素材总台账.md` M-002）。论文须显式声明：构造语料 + 公开集外部验证。
2. **模型与传输**：对话与向量均走公司内网 vLLM，数据不出内网（`决策台账.md` DEC-39）；论文不写内网地址、端口、账号、密钥。

4. **论文脱敏**：企业实名、内网 IP/端口、账号、token、密钥一律不出现；统一写「公司环境」「网关入口」「集群内服务」。
5. **PII**：护栏含手机号、座机、身份证、邮箱、姓名、地址六类脱敏（`创新点.md` 护栏评测）；但只覆盖对话输出，**不覆盖工单附件与历史日志**。

### 5.3 写作边界

- 只能写「实测值 + 测试条件」，不能写「达标 / 满足要求」；目标值未定前，结论一律用「在 X 条件下实测为 Y」。
- 单节点部署不能表述为「高可用」；只能写「具备降级路径，未做 HA 验证」。
- P95 必须注明并发数、样本量与统计区间；507/943 ms 是特定压测结果，不是生产 SLA。
- 所有目标值待 Q-01～Q-11 确认后回填；未确认的格子保留「待确认」，不得用行业惯例代替。
