### 2.3 阻塞、待确认与无留存说明

- **检索分数定案（2026-11-23）**：0.7696 是 11-19 旧 embedding 模型下的评测读数，与当前模型不可比；**0.6589 不可复现、已作废**（属噪声版蚀刻 query）；同 query 现测 VECTOR/HYBRID 均 **0.7737、A 档**；**系统性偏移不成立，唯一异常项是回流焊 −0.0173**。0.7691（11-20 控制台实时返回）与 0.76701（11-19 单点验证）同为旧模型口径读数，不再单独追查。
- **gateway NodePort 30204** 只存在于现场，公司 overlay 未回写该 patch（见 `docs/ops/公司环境资产清单.md` 第六节）。

### 2.4 已实现但未排期上线的条目

| 条目 | 现状 | 状态 |
|---|---|---|
| **建议→回填→入库（C 档兜底建议回流知识库）** | **已实现（默认关闭）**：主动推荐（`ticket.created` 时 HYBRID Top5 检索，向在线坐席推送知识卡、离线坐席落站内信）；C 档建议与工单实际处置的配对留档在 `ai_fallback_pair`。**回填入口已开发**（`bb44127`）：人工回填处置后按灰度投递 `ai_extracted` 待审，复用既有去重/关系判别与审核流程，不直写 `kb_knowledge`/Milvus；默认 `AI_FALLBACK_INTAKE_ENABLED=false`、灰度 0。注：主链路「工单关闭→抽取→审核→入库」已完成，本条仅指「建议→回填」支线，二者不可混为一条。 | **已实现 · 默认关闭 · 未排期上线** |

**设计约束（实施时不得放宽）**

1. **必须走同一审核闸门**：回填条目落 `ai_extracted` 待审，经人工审核通过后才写 `kb_knowledge`；**禁止直写知识库**，也不得绕过审核直接进 Milvus。
2. **来源可回溯**：每条回填知识须带来源标记（来源工单、问答会话、模型版本、置信分），供审核与后续追责。
3. **双重上限**：设置信阈值（低于阈值不进入审核队列）与每日新增量上限，防止批量污染。
4. **复用既有判别**：入库前复用现有去重与冲突/关系判别（`ai_extracted` 的 `dedup_action` / `dedup_score` / `relation_type`），不另写一套。
5. **审核界面可区分来源**：审核页需能区分「建议来源」与「抽取来源」，便于按来源统计与限流。
6. **先灰度再放开**：按小流量灰度上线，以「回填知识被检索命中率」和「审核否决率」作为是否扩大放开的判据，不设事先承诺的时间点。

- **最紧节点：开题 2027-01 上旬**。开题只写到 M3，M0~M3 必须在 2026-12-31 前可演示——目前 M0~M3 已完成，**该节点风险已基本解除**，剩余工作是把演示脚本与截图补齐。
- **关键路径**：M7 评测口径 → 论文实验章节。评测产物已齐，但 **0.7696 是 11-19 旧 embedding 模型下的评测读数，与当前模型不可比**；现行门控 0.70 / 0.07；11-23 蚀刻 query 双模式实测 **0.7737 / A 档**，**0.6589 不可复现、已作废**；系统性偏移不成立，唯一异常项为回流焊 −0.0173。待审条数已实查为 0，不再是阻塞。
