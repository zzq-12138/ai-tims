## 2. 一句话架构

Vue3 前端 → Spring Cloud Gateway → 6 个 Java 微服务；业务库 MySQL，缓存 Redis，消息 RabbitMQ，向量库 Milvus；大模型与 Embedding 走公司内网 vLLM；所有组件部署在公司 K8s 的 `ai-tims` namespace（单副本）。

## 7. 名词解释（大白话）

| 名词 | 含义 |
|---|---|
| **工单状态机** | 工单只能按规定路线走：提交 → 受理 → 处理中 → 已解决 → 关闭；可挂起/恢复；非法跳转返回 `20401` 并写流转日志 |
| **五元组** | 从工单里抽出的五个条件：设备型号、工艺段、材料或批次、参数区间、前置状态。作用是让知识“在什么条件下适用”说得清 |
| **链式抽取** | 把一次抽取拆成三步：先抽现象 → 再抽根因和验证 → 最后抽措施和适用条件。每单 3 次模型调用，结果写进 `chain_trace` |
| **门控** | 检索回来的知识先过一个“可信度闸门”：A 档正常推送，B 档带“仅供参考”，C 档不返回。防止答非所问 |
| **软带** | 阈值上方的一小段缓冲区。公司配置阈值 0.70、软带 0.07，所以 `[0.70, 0.77)` 是 B 档，`≥0.77` 才是 A 档 |
| **`ref_count`** | 这次 AI 回答引用了几条知识。之前 Agent 路径恒为 0，已修代码但还没上线 |
| **向量同步** | 知识发布后，定时任务每 10 秒扫一次，把 `title + summary + content` 送 embedding，写进 Milvus；改标题也会触发重算 |
| **C 档兜底** | 检索没把握时给出的建议，必须明确标注「无知识库依据，仅供参考」，不能混进有依据的统计 |

## 8. 两个研究问题与创新点

| 问题 | 内容 |
|---|---|
| 问题一 | 知识库检索与门控：阈值、错误推送率、310 库敏感性 |
| 问题二 | 维修知识自动抽取、语义去重与冲突消解：五元组、链式抽取、四类关系判别、条件化入库 |

创新点固定为「3 条核心 + 1 条边界研究 + 1 条应用」。边界研究写「验证了它在什么条件下才成立」，不得写「我们提出」。

论文口径红线（详细见 `docs/paper/论文素材总台账.md`、`docs/paper/决策台账.md`）：

- 禁止「人工标注 / 专家标注 / 双人标注」，统一写 construction-based gold（弱监督）。
- 构造集是上界，反构造集是主结果；两者必须并列，不得只报高值。
- 一次报告一套数，跨运行不拼表（DEC-31）。
- 盲评 κ=1.000 必须保留限定：「系合成句式规律所致、不代表真实工单能力」。
