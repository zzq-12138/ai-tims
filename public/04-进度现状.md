## 2. 工单与抽取细节

- 表名：工单主表是 **`wo_ticket`**、流转表 **`wo_ticket_flow`**，不是 `ticket`。
- **历史**：10.33 时 102 条剩余工单走真实业务接口：`accept → start → resolve → confirm → CLOSED`；关单事件按生产路径经 `tims.ticket.event` + `ticket.closed` 进入 `q.kb.extract`，没有直投、没有手工改状态。
- **历史**：当时唯一未抽取的是 `WO20261118-0105`（`MANUAL_REQUIRED`）；2026-11-23 实查 `ai_extracted` 78、`PENDING_REVIEW` 0，旧「105 / 104+1」与「唯一 0105」不再作为当前口径；未抽取/失败单的具体数量本次未查。
- 链式抽取的既定取舍：`troubleshootSteps` 置空、`tags` 只保留设备类型、`title` 按「设备类型：现象」截 30 字、每条工单 3 次模型调用。
- **11-20 后无新抽取已结案**：`wo_ticket` 只有 2026-11-18 有 105 条，之后零新单；`ai_call_log` 11-18/19/20 = 154/23/238，11-21 起为 0。结论是**无新业务输入导致静默，不是链路故障**。时间列是 `create_time`（不是 `created_time`）；`wo_ticket` 另有 `abnormal_time`（报障时间）。
- 标题缺陷：10.34 只做了 SQL 数据订正，代码当时没修；**2026-11-23 已补最小修复（`ChainExtractionService` 新增 `buildTitle()`，已提交、未部署）**，结论与依据见 06 P3；同批提交 `860d74e` 另修 `WsSessionRegistry` 空指针，见 06 P3。

## 4. 三问检索验证（已收口）

> 0.7696 是 11-19 旧 embedding 模型下的评测读数，与当前模型不可比；**0.6589 属噪声版 query、已作废**；同 query 现测 VECTOR/HYBRID 均 **0.7737、A 档**；系统性偏移不成立，唯一异常项为回流焊 −0.0173（已归因收尾）。

历史观察（旧模型口径）：

| 查询 | 结果 |
|---|---|
| 贴片机相关 | 命中新入库条目，分数在 A/B 档 |
| AOI 相关 | 命中新入库条目，分数在 A/B 档 |
| 蚀刻相关 | **0.7691**（11-20 控制台实时返回，未落库、无日志，不可事后复核）；同 query 另落档 **0.7696**（11-19 kb310 回放） |

**库内字段**：只有 `ai_extracted.dedup_score`、`ai_fallback_pair.consistency_score`、`ai_fallback_pair.coverage_score`，**没有检索相似度字段**，因此无法用 MySQL 复核 0.7691。

**0.7696 落档证据**（11-19 kb310 回放，蚀刻 query）：

- `docs/paper/评测/gate_baseline.csv:81`（P-080）
- `docs/paper/评测/threshold_eval.csv:81`

- `docs/paper/评测/_scores_positive.json:2610`
- top1：`2117517479423836162`《蚀刻机过蚀刻处理》

query：`蚀刻机 刻过头了，线路都刻细了，有没有人遇到过，求个解决方案`。

**0.76701**（11-19 回流焊 query 单点验证，310 条 PUBLISHED，B 档）：query `回流焊8温区温度偏低，焊点虚焊`（**全角逗号版**；空格版同条件约低 0.015——0.7497），`maxVectorScore=0.76701`，top1《回流焊预热不足导致冷焊》；出处 `docs/paper/检索与门控.md`、`docs/paper/决策台账.md` DEC-43。

**2026-11-23 重放（master1，当前线上配置）**：

- 干净 query `蚀刻机过蚀刻怎么处理`：`maxVectorScore=0.7737`、`tier=A`（VECTOR/HYBRID 双模式一致），top1 `2117517479423836162`；0.6589 属噪声版 query、已作废，不能用于「误杀」表述。
- `kb_knowledge` 表结构截图：**没有** `embed_model` / `vector_status` / `embedding_time`，只有 `vector_synced_at`（datetime，可空）。
- `vector_synced_at` 实查（2026-11-23）：`MIN=2026-11-18 14:31:19`、`MAX=2026-11-20 14:41:39`、`COUNT(*)=328`、`SUM(IS NULL)=0`。按日 `GROUP BY DATE(vector_synced_at)` 结果未显示，**无法判断是否跨模型分批灌入**；不要据此新增「混有两代向量」的结论。
- 当前 env：`TIMS_KB_EMBEDDING_MODEL=Qwen/Qwen3-Embedding-8B`、`TIMS_KB_EMBEDDING_DIMENSIONS=1024`、`TIMS_KB_MILVUS_COLLECTION=kb_knowledge_vec`、`KB_EMBED_QUERY_INSTRUCTION=Given a web search query, retrieve relevant passages that answer the query`。

**复核方式**：

- `POST /api/kb/search`。
- 集群内：`http://ticket-knowledge:8103/api/kb/search`（exec 进 pod 后 `curl`）；对外经网关：`http://172.27.19.64:30204/api/kb/search`。
- 参数：`mode=HYBRID`、`topK=5`、`gateEnabled=true`、`gateThreshold=0.70`，软带 0.07；header `X-Tenant-Id: 1`。
- 看 **`data.maxVectorScore`**（topK 中 `items[].vectorScore` 的最大值）；`score` 是 RRF 融合分（量级约 0.05），**不能用它核对余弦阈值**；响应无 `similarity` / `distance` 字段。
- collection `kb_knowledge_vec`、tenant 1、1024 维、余弦、HNSW。
- **引用前建议重放同一请求并留存原始 JSON**；仓库目前没有三问请求的记录；本次复核时公司集群/DB 均不可达（见 10 §4）。
