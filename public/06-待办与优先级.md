**执行步骤（本次实践，命令仍可复用）**

1. 确认台式镜像包位置（`D:\tims-images` vs `D:\ai-tims-images`，见 10）；公司侧 `/data/sdv1/tims/images/` 已确认存在（2.9G / 20 项），三个新包另行拷入后完成推送。
2. `md5sum -c MANIFEST.md5` 校验三个包。
3. 把三个包拷进公司内网 `/data/sdv1/tims/images/`（已完成）；注意 `ai-tims-front-1.0.2.tar` 是裸 tar，其余是 `.tar.gz`。
4. 在能连 Harbor 的内网机器 `docker load` 三个包 → `docker login` → `docker push` 三个 tag。
5. 在 master1 `/data/sdv1/tims` 逐服务执行：
   ```bash
   EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh ai 1.0.2 --yes
   EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh knowledge 1.0.2 --yes
   EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh front 1.0.3 --yes
   ```
6. 回读三个 Deployment 的 image 必须是新 tag，Pod `1/1 Running`、重启次数 0。
7. 功能验证：
   - 审核列表翻到第 2 页，数据要变化；
   - 加筛选后页码回到 1，结果数量变化；
   - Agent 问答后查 `ai_call_log.ref_count`，不再恒为 0。
8. 每步追加台账。

**完成标准**：三个 Deployment 回读新 tag；功能验证通过；台账有记录。

**失败/回滚**：

```bash
./deploy/sdv1/deploy.sh ai 1.0.1 --no-image --yes --allow-downgrade
./deploy/sdv1/deploy.sh knowledge 1.0.1 --no-image --yes --allow-downgrade
./deploy/sdv1/deploy.sh front 1.0.2 --no-image --yes --allow-downgrade
```

前端也可以手工把 `base/apps/front.yaml` 的 tag 改回 `1.0.2` 再 `apply -k`；**不要用 `set image` 救急后不修清单**。

**注意**：

- `deploy.sh` 的 `all` 会把 6 个后端一次性改成同一个 tag，**禁止用 `all`**，逐服务发。
- 新 tag 不能复用已推过的 tag 覆盖推送。
- 发布前先看 `deploy.sh` 预检打印的 image 行，确认与预期一致。
