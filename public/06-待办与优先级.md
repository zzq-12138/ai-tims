   ```bash
   EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh ai 1.0.2 --yes
   EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh knowledge 1.0.2 --yes

   ```
6. 回读三个 Deployment 的 image 必须是新 tag，Pod `1/1 Running`、重启次数 0。
7. 功能验证：
   - 审核列表翻到第 2 页，数据要变化；

**失败/回滚**：

```bash
./deploy/sdv1/deploy.sh ai 1.0.1 --no-image --yes --allow-downgrade
./deploy/sdv1/deploy.sh knowledge 1.0.1 --no-image --yes --allow-downgrade
```

**注意**：

- `deploy.sh` 的 `all` 会把 6 个后端一次性改成同一个 tag，**禁止用 `all`**，逐服务发。
- 新 tag 不能复用已推过的 tag 覆盖推送。
- 发布前先看 `deploy.sh` 预检打印的 image 行，确认与预期一致。

低优先级待确认（2026-11-23 两条均已查清，结论如下；修复**已提交，公司线上未部署**；dev overlay 已按 2026-11-24 实测回写为 `ticket-ai:1.0.3` / `ticket-push:1.0.1`，`ticket-knowledge:1.0.1`、`ai-tims-front:1.0.2` 也与实测一致）：

- **`WsSessionRegistry` 的 NPE：真实缺陷，已最小修复。**
  - 依据：`heartbeat()` 把 `sessions.get(userId)` 原样交给 `online()`，后者无条件 `sessions.put(userId, session)`；会话不在本机 map 里时传入 null，`ConcurrentHashMap.put` 必抛 NPE。可触发路径是前端 WS 重连抖动：旧连接的关闭回调先执行，按 `userId` 把重连后的新会话摘掉，随后新会话心跳取到 null。同一处 `offline()` 也无归属校验，原注释写的「仅当在线表归属仍是自己」在代码里并未实现，会误删新会话和 Redis 在线键。
  - 修复：`online()` 仅在 `session != null` 时写 map，空值只续期在线表（心跳不中断）；`offline(userId, session)` 改为 `sessions.remove(userId, session)`，只有确实摘到自己的会话才删在线键；`PushWebSocketHandler` 的关闭回调传入 `session`。
  - 线上取证（2026-11-23）：在 master1 用 `kubectl -n ai-tims logs deploy/ticket-push` 查 `NullPointerException`，近 **24 小时**与近 **168 小时**均 **0 条**。结论：缺陷按代码路径成立，但线上未观测到实例，本次按**预防性修复**对待——既不写成「疑似问题」，也不写成「线上确实报过」。
- **链式标题生成逻辑：代码当时未修，现已最小修复。**
  - 依据：`ChainExtractionService` 的标题一直是 `truncate(deviceType + "：" + symptom, 30)`；该文件 git 历史只有首次提交，10.34 仅用 SQL 订正了 104 条数据，没有改代码。
  - 缺陷点：① `symptom` 自带设备名时生成「设备名：设备名…」；② 硬截 30 字可能停在标点或连词（`、和与及或的`）；③ `symptom` 为空时生成「设备类型：」带尾巴。
  - 修复：新增 `buildTitle()`——先剥掉与设备类型重复的前缀（连同紧随的分隔符），空现象只留设备类型，截 30 字后再清掉结尾标点与连词；「设备类型：现象、截 30 字」的既定口径不变。已用独立样例验证：`焊接机器人` + `焊接机器人报警，焊丝送进不畅` → `焊接机器人：报警，焊丝送进不畅`；空现象 → `焊接机器人`；截断后结尾 `并且`、`与` 均被清掉。
  - 验证：VM（`zzqserver`，Maven 3.6.3 + JDK 21.0.13.1）`mvn -o -DskipTests -pl ticket-ai,ticket-push -am clean compile` → **BUILD SUCCESS**（离线模式；`ai-tims-common` 6、`ticket-ai` 74、`ticket-push` 22 个源文件，release 17），仅既有 `OrderClient` deprecation 与 `WsSessionRegistry` unchecked 提示。公司线上未部署。

已确认：`tims-redis:7-alpine` **已在 Harbor**（2026-11-23 实测），原「未推送」注释作废，无需再补推；`NACOS_PASSWORD`、`SMTP_AUTH` 为空属预期（Nacos 用公司既有环境、无需在本次 Secret 配置；内网部署未启用邮件），不是遗漏。
