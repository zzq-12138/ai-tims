### 2.4 模型链路（2026-11-23 实测）

- 本项目**不使用**集群内 `alg-llm-service`。
- `LLM_BASE_URL`、`ZHIPU_EMBEDDING_URL` 指向 `172.27.26.253`；这是**集群外独立网关**，不在任何 Service 内。
- chat / 抽取 / 复杂路由模型均为 `Qwen/Qwen3.8-27B-dev`；embedding 为 `Qwen/Qwen3-Embedding-8B`，1024 维，集合 `kb_knowledge_vec`。
- **embedding 换模（已定案）**：0.7696 是 11-19 旧 embedding 模型下的评测读数，与当前模型不可比；0.7691 同为旧模型历史观察；**0.6589 属噪声版 query、已作废**；同 query 现测 VECTOR/HYBRID 均 **0.7737、A 档**；系统性偏移不成立，唯一异常项为回流焊 −0.0173。
- **`kb_knowledge` 字段（截图）**：**没有** `embed_model` / `vector_status` / `embedding_time`；只有 `vector_synced_at`（datetime，可空）。2026-11-23 实查：`MIN=2026-11-18 14:31:19`、`MAX=2026-11-20 14:41:39`、`COUNT(*)=328`、`SUM(IS NULL)=0`。按日 `GROUP BY DATE(vector_synced_at)` 结果未显示，**无法判断是否跨模型分批灌入**；不要据此推断「混有两代向量」。
- 门控 0.70 / 软带 0.07；向量同步每 10 秒一轮、每批 16 条。
- `alg-llm-service`（`mqis-tm16-test`）仅作**相邻服务记录**：NodePort 18992→31133，容器端口 18992，无 hostPort，镜像 `algcenter/llm:2.1.0.5`，`/v1/models` 返回 uvicorn 404；Pod IP 随重建变化。**不要把它当成本项目依赖。**

## 3. 门控 A/B/C

代码位置：`SearchService.java`。判定顺序：

1. 关键词模式 / 门控关闭 → `A`，不做向量门控。
2. 无向量分数（降级或候选为空）→ `fallback-tiers=true` 时 `B`，否则 `C`。
3. `maxVectorScore < threshold` → **C**，清空 `items`。
4. `threshold ≤ score < threshold + softBand` → **B**，返回但标注「仅供参考」。
5. `score ≥ threshold + softBand` → **A**。

公司当前 `threshold=0.70`、`softBand=0.07`：

| 分数区间 | 档位 | 行为 |
|---|---|---|
| `< 0.70` | C | 不返回知识，给兜底建议（必须标注「无知识库依据，仅供参考」） |
| `[0.70, 0.77)` | B | 返回，标注仅供参考 |
| `≥ 0.77` | A | 正常推送 |

例：`0.76701`（2026-11-19 线上实测，回流焊 query）→ B（落在 `[0.70, 0.77)` 软带内）。

> 0.7696 是 11-19 旧 embedding 模型下的评测读数，与当前模型不可比；**0.6589 属噪声版 query、已作废**；同 query 现测 VECTOR/HYBRID 均 **0.7737、A 档**；系统性偏移不成立，唯一异常项为回流焊 −0.0173（已归因收尾）。
>
> 0.7691 是 11-20 下午控制台实时观察值，未落库/无日志留存，不可事后复核；0.76701 是 11-19 回流焊 query 单点验证（310 条 PUBLISHED，B 档）。两者均按历史读数保留。

> 门控阈值历史：0.75 来自 2026-11-05 的基线；换 Qwen3-Embedding-8B 后重标定为 0.70，现行值以 0.70/0.07 为准。
>
> 口径提醒（与 [11-论文与素材.md](11-论文与素材.md) §五「门控口径三条」同源）：现网只认 0.70/0.07，不要再写「现网阈值 0.75」；2.4% 是正例池内的正例错误率，不能外推为整体错误推送率，也不能写「已降到 3% 以下」「已达标」。

## 4. 向量化规则

- 向量文本 = `title + "\n" + summary + "\n" + content`，截断 4000 字符。
- **标题参与向量化**：改标题后必须让 `update_time` 抬升，定时任务才会重算。
- 定时任务：每 10 秒一轮，每批 16 条，条件 `status='PUBLISHED' AND update_time > vector_synced_at`。
- 改完标题立刻查 `vector_synced_at` 仍是旧值属正常，等一轮再看。
- Milvus 集合 `kb_knowledge_vec` 维度 **1024** 建时写死，事后不能改；换维度必须删集合重灌。
- 集合只在第一次 upsert 时创建；没有知识入库就永远 `collection not found`。

## 5. 字符集与 collation（1267 坑）

| 表/列 | 实际 collation |
|---|---|
| `kb_knowledge.title` | `utf8mb4_bin` |
| `ai_extracted.*`（如 `fault_phenomenon`） | `utf8mb4_0900_ai_ci` |

跨表把这两列放进同一个 `REGEXP_REPLACE` 会报：

```text
1267 Illegal mix of collations (utf8mb4_bin, NONE) and (utf8mb4_0900_ai_ci)
```

正确做法：

- **优先**：只在 `ai_extracted` 单表算完，再按数字键 `source_ticket_id`（bigint）关联写 `kb_knowledge`。
- 确需跨表比字符串：`CONVERT(... USING utf8mb4) COLLATE utf8mb4_0900_ai_ci` 显式统一。

> 数据规模一律用 `COUNT(*)`；`TABLE_ROWS` 是 InnoDB 估算（`kb_knowledge` 显示 292、实际 328），不能引用。工单表是 `wo_ticket`、流转表 `wo_ticket_flow`，不是 `ticket`。

## 7. 改配置的正确姿势

1. 改 `deploy/k8s/overlays/company/patches/*.yaml`（不要 `kubectl set env` / `patch` 手改集群）。
2. 渲染预检：
   ```bash
   kubectl kustomize deploy/k8s/overlays/company > /tmp/ai-tims-company.yaml
   ```
3. `kubectl apply -k deploy/k8s/overlays/company`。
4. **ConfigMap 变更不会自动重建 Pod**，必须：
   ```bash
   kubectl -n ai-tims rollout restart deploy/<服务>
   kubectl -n ai-tims rollout status deploy/<服务> --timeout=180s
   ```
5. 回读：
   ```bash
   kubectl -n ai-tims exec deploy/<服务> -- printenv | grep -E '<KEY>'
   ```
6. 写台账（命令、输出、判读、回滚）。

> 手工 `kubectl patch` 改的配置不在清单里，下一次 `apply -k` 必丢。前端 nginx 就这样丢过 `/ws/`。
