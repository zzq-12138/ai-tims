# 09 发布部署速查

> 权威原文：`docs/ops/发布流程.md`（348 行，2026-11-20 在台式、VM、公司内网实机验证过）。

## 1. 四角色分工

| 角色 | 机器 | 做什么 | 不做什么 |
|---|---|---|---|
| 编辑 / 传输 | 台式 `g:\JAVA\Code\ai-tims` | 改代码、`scp` 单文件、整理包 | 不编译、不构建、不连集群 |
| 编译 / 构建 / 导出 | VM `dev@192.168.40.10`，`/home/dev/ai-tims` | `mvn package`、`docker build`、`docker save \| gzip` | 不 push Harbor、不碰集群 |
| 装载 / 推送 | 公司内网有 Docker 的机器 | `md5sum -c`、`docker load`、`docker login`、`docker push` | 不改清单 |
| 发布 | master1 `/data/sdv1/tims` | `deploy.sh`：镜像准备 → 改 tag → `apply -k` → `rollout` → 回读 | 不 build |

## 3. 代码同步（台式 → VM）

```bash
# 1) VM 上备份旧文件
cp <文件> /home/dev/verify-backup-$(date +%Y%m%d)/

# 2) 台式传单文件（不要整目录）
scp <文件> dev@192.168.40.10:/home/dev/ai-tims/<相对路径>

# 3) VM 上统一换行符
cd /home/dev/ai-tims
sed -i 's/\r$//' <本次改到的文件...>

# 4) 只 add 本次文件
git add <本次文件...>
git commit -F /tmp/commit-msg.txt
git push origin main
```

禁止 `git add .`、禁止整目录覆盖、禁止 force push。

## 4. 编译（VM）

```bash
cd /home/dev/ai-tims/ai-tims-parent
mvn -B -pl ticket-ai,ticket-knowledge -am -DskipTests package
```

产物：`ticket-*/target/<模块>-1.0.0-SNAPSHOT.jar`，确认时间戳是本次。

---

## 5. 构建镜像（VM）

```bash
cd /home/dev/ai-tims

# 后端
docker build \
  --build-arg JAR_FILE=ai-tims-parent/ticket-ai/target/ticket-ai-1.0.0-SNAPSHOT.jar \
  -f deploy/docker/Dockerfile \
  -t harbor.xnunion.com/library/ticket-ai:<tag> .

# 知识库
docker build \
  --build-arg JAR_FILE=ai-tims-parent/ticket-knowledge/target/ticket-knowledge-1.0.0-SNAPSHOT.jar \
  -f deploy/docker/Dockerfile \
  -t harbor.xnunion.com/library/ticket-knowledge:<tag> .

# 前端
docker build -f ai-tims-front/Dockerfile \
  -t harbor.xnunion.com/library/ai-tims-front:<tag> ai-tims-front
```

`deploy/scripts/images.env` 是占位值（`registry.company.internal/ai-tims` + `1.0.0`），**不要吃默认值**，必须显式传仓库与 tag。

> 口径修正（2026-11-23）：外部 `AI-TIMS-环境速查.md` 第 271 行已按实际 Dockerfile 修正为「多阶段构建，容器内 `npm install` + `npm run build`」；「`deploy.sh` 不碰 docker」也已修正。两处口径都以本节为准：前端是 `ai-tims-front/Dockerfile` 多阶段构建（容器内 `npm install` + `npm run build`）；新版 `deploy.sh` 内置镜像 load/push，只有加 `--no-image` 或脚本不可用时才手工做。

## 6. 导出（VM）

```bash
mkdir -p /home/dev/tims-images-<日期>
cd /home/dev/ai-tims
docker save harbor.xnunion.com/library/ticket-ai:<tag> | gzip > /home/dev/tims-images-<日期>/ticket-ai-<tag>.tar.gz
docker save harbor.xnunion.com/library/ticket-knowledge:<tag> | gzip > /home/dev/tims-images-<日期>/ticket-knowledge-<tag>.tar.gz
docker save harbor.xnunion.com/library/ai-tims-front:<tag> | gzip > /home/dev/tims-images-<日期>/ai-tims-front-<tag>.tar.gz

cd /home/dev/tims-images-<日期>
gzip -t *.tar.gz
tar -xzOf ticket-ai-<tag>.tar.gz manifest.json     # 确认 RepoTags
md5sum *.tar.gz > MANIFEST.md5
```

生成 `MANIFEST.txt`（文件/镜像/大小/md5/总量）与 `MANIFEST.md5`，最后 `md5sum -c MANIFEST.md5`。

## 7. 搬运到公司内网

1. `scp` 从 VM 拉到台式 **`D:\tims-images\`**（约定位置；当前实际在 `D:\ai-tims-images`，先找用户确认）。
2. Windows 侧用 `Get-FileHash -Algorithm MD5` 逐个比对。
3. U 盘/摆渡机拷进 `/data/sdv1/tims/images/`。
4. **必须**先 `md5sum -c MANIFEST.md5`，FAILED 就重拷该文件。

VM 连不上 Harbor（DNS 失败、无 docker 凭据），不要在 VM 上 push。

## 8. 装载与推送（公司内网）

新版 `deploy.sh` 默认会自动做（`ensure_image`）：按 `IMAGES_DIR` 找包 → 本机没有就 `docker load` → Harbor 没有就 `docker push`。

前置条件：

- master1 有 Docker；
- 已 `docker login harbor.xnunion.com`；
- 包在 `/data/sdv1/tims/images/`。

手工等价（`--no-image` 时）：

```bash
cd /data/sdv1/tims/images
md5sum -c MANIFEST.md5

docker load -i ticket-ai-1.0.2.tar.gz
docker load -i ticket-knowledge-1.0.2.tar.gz
docker load -i ai-tims-front-1.0.3.tar.gz

docker login harbor.xnunion.com
docker push harbor.xnunion.com/library/ticket-ai:1.0.2
docker push harbor.xnunion.com/library/ticket-knowledge:1.0.2
docker push harbor.xnunion.com/library/ai-tims-front:1.0.3
```

`deploy/scripts/load-and-push.sh` 不适用本流程（按占位仓库名找镜像）。

## 9. 部署（master1）

### 9.1 后端

```bash
cd /data/sdv1/tims
EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh ai 1.0.2 --yes
EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh knowledge 1.0.2 --yes
```

脚本动作：

1. 校验参数，打印 context / namespace / 现有 Pod；
2. 镜像准备（找包 → load → push；`--no-image` 可跳过）；
3. 备份 `.bak`，改 overlay `newTag`，同步 base `image:`；
4. `kubectl kustomize` 预检，打印 image 行并与集群对比；
5. 版本回退默认终止，需 `DOWNGRADE` 或 `--allow-downgrade`；
6. `apply -k` → `rollout status --timeout=180s` → `jsonpath` 回读；
7. 失败自动还原 `.bak` 并重新 apply。

**禁止 `all`**：`all` = 6 个后端一次性同 tag，且会逐个 load/push，缺包直接中止。

### 9.2 前端

```bash
cd /data/sdv1/tims
EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh front 1.0.3 --yes
```

手工等价：

```bash
cd /data/sdv1/tims
sed -i 's|image: harbor.xnunion.com/library/ai-tims-front:.*|image: harbor.xnunion.com/library/ai-tims-front:1.0.3|' deploy/k8s/base/apps/front.yaml
kubectl apply -k deploy/k8s/overlays/company
kubectl -n ai-tims rollout status deploy/ai-tims-front --timeout=180s
```

**禁止 `kubectl set image`。**

## 10. 验证

```bash
kubectl -n ai-tims get deploy ticket-ai ticket-knowledge ai-tims-front \
  -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.template.spec.containers[0].image}{"\n"}{end}'

kubectl -n ai-tims get pods -o wide
kubectl -n ai-tims get svc
kubectl -n ai-tims get endpoints
```

- 三个 image 必须是新 tag；
- Pod `1/1 Running`，重启次数 0；
- 功能验证：
  - 审核列表第 2 页数据变化；
  - 筛选后页码回 1；
  - Agent 问答后 `ai_call_log.ref_count` 不再为 0。
- 对外验收只走 NodePort：front `http://172.27.19.64:31579/`、gateway `http://172.27.19.64:30204/`；`ai-tims/ai-tims` Ingress 虽存在但无 IngressClass/controller，ADDRESS 空，不要用 `tims.company.local`。域名访问需为 ai-tims 单独部署 router + IngressClass，改注解无效。

## 11. 回滚

```bash
cd /data/sdv1/tims
EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh ai 1.0.1 --no-image --yes --allow-downgrade
EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh knowledge 1.0.1 --no-image --yes --allow-downgrade
EXPECTED_CONTEXT=kubernetes-admin@kubernetes ./deploy/sdv1/deploy.sh front 1.0.2 --no-image --yes --allow-downgrade
```

前端也可手工改回 `front.yaml` 的 tag 再 `apply -k`。回滚后同样要跑第 10 步回读。
